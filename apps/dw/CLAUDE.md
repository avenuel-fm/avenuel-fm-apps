## 1. 작업 규칙 (사용자와 정한 것 — 반드시 지킴)

1. **"진행시켜" 전에는 코딩하지 않습니다.** 설계 변경·기능 추가·버그 수정 모두 먼저 확인을 받습니다. 원인 조사·시안 만들기·문서 정리는 해도 됩니다.
2. (뺌 — 개선안 두 개 이상 규칙은 결정 37로 없앰)
3. 화면이 바뀌는 일은 **시안(이미지)을 먼저** 보여 줍니다. 시안은 실제 `Styles.html`을 쓴 미리보기(`test/build_preview.py`)에 덧입혀 찍습니다.
4. 수정 요청은 바로 고치지 않고 `docs/수정요청_대기목록.md`의 **DW 구역**(DW-n)에 모읍니다. 사용자가 "코딩은 나중에 한 번에"라고 하면 모았다가 한 판으로 묶습니다.
5. 답은 **한국어**, 쉬운 말로. 사용자는 시설팀 소장(비개발자)입니다.
6. 설계 문서는 **`docs/설계/00_목차_읽는법.md`부터** 읽고, 작업하는 기능 문서(`DW_도면협의.md`)와 그 문서가 가리키는 공통 장만 엽니다.
7. 문서를 고치다 **새 충돌**을 찾으면 임의로 정하지 않고 사용자에게 묻습니다.
8. 코드를 바꾸면 설계 문서도 같이 맞춥니다(먼저일 필요는 없음, 결정 37). 고친 문서만 판을 올리고 `90_결정과이력.md` 부록 B에 한 줄 적습니다. 공통 문서(01~07) 규칙이 바뀌면 `00` 목차의 공통 규격 버전도 올립니다.
9. **다른 대화방(업무지원 WS)과 맞추기**: 바뀐 문서만 주고받고, 받은 쪽은 문서 맨 위 판을 비교합니다. 더 새 판이면 바꾸고, **같은 판인데 내용이 다르면 사용자에게 확인**합니다. (11-04에 두 방이 같은 결정 번호·같은 공통 규격 번호를 따로 써서 두 번 겹쳤습니다 → 결정 26~31, 33~34로 다시 매김.)
10. **결정 번호는 홀수** (결정 38, 00 3장 10번): 도면협의 쪽 결정은 홀수(35, 37, 39 …), 업무지원 쪽은 짝수. 결정 39(PIN 전체 잠금)까지 썼으니 다음은 **41**입니다. 90 결정표에서 마지막 번호를 확인하고 씁니다.
11. **아이패드(WebKit) 시험은 하지 않습니다** (결정 31). 화면 검사는 13가지 크기 × 보통·큰 글꼴만.
12. 사진 파일 이름은 `YYYY-MM-DD_작업명_###.jpg` (이름·날짜로 찾기). DW 협의서는 `YYYY-MM-DD_방재실협의서-{테넌트}_001.jpg`.
13. 배포는 항상 **배포 관리 → ✏ → 새 버전** (새 배포 금지 → `/exec` 주소 유지).

## 3. 로그인 — 소장·부소장 PIN 2개 방식 (지금 운영)

- 역할은 `APP.ROLES = ['소장', '부소장']` 두 개뿐입니다. 직원·파트장은 DW를 쓰지 않습니다 (결정 2·12·32: **소장·부소장 전용 단독 앱**).
- PIN은 시트 메뉴 **② PIN 설정 – 소장 / 부소장**에서 넣고, 스크립트 속성 `PIN_소장`, `PIN_부소장`에 **SHA-256 해시**로 저장합니다. 두 사람이 같은 PIN을 쓸 수 없습니다(저장 때 막음).
- 로그인 화면은 **PIN만** 받습니다. 서버가 두 해시와 비교해 역할을 찾습니다 (v1.7~).
- 기기 기억: 서버가 준 표 `hash('token:' + 역할 + ':' + 저장된PIN해시)`를 localStorage `dr_auth`에 둡니다. **PIN을 바꾸면 모든 기기의 기억이 무효**가 됩니다.
- 「시설 소장 확인」은 소장 PIN으로 들어왔을 때만 됩니다.
- 첫 화면 기억 `dr_start_cache`: 지난 매장 목록·설정으로 먼저 그리고 1~3초 뒤 서버 값으로 바꿉니다.
- **앞으로도 이 방식 그대로** (결정 36, 결정 3을 바꿈): 공통 직원 PIN·입장표(`?t=`)로 바꾸지 않습니다. HUB의 DW 카드는 DW 짧은 주소로 열고, DW가 자기 PIN을 확인합니다(기기에 기억돼 있으면 바로 열림). WS의 「근무일 첫 로그인 서명」(결정 56·60)도 DW에는 없습니다.

## 4. 디자인 기준

- **이 앱의 `Styles.html`이 모든 앱의 디자인 기준**입니다 (06 문서 12장). 색 변수 이름도 DW 이름(`--ground`, `--card`, `--line`/`--line2`/`--line3`, `--ink`/`--sub`/`--muted`, `--blue`, `--green`, `--orange`, `--red` …).
- 입력칸 글자 16px 이상, 버튼·입력 높이 44px, 휴대폰 주 버튼 52px, 모서리 8/12/999px, 글꼴 Noto Sans KR.
- 사진 칸은 가로 4:3, 자르지 않고 줄여 넣기, 남는 곳 `--line3` #EDF0F3 (결정 20). 문서 사진은 2400px·JPEG 85% (결정 27).
- 화면 검사: `test/ui_audit.py` (13가지 크기, `--stress` 큰 글꼴). 넘침 0건이 기준.
- 휴대폰(좁은 화면)에서는 대시보드 표가 카드로 바뀝니다 (`Styles.html` `@media` 603줄 부근).
