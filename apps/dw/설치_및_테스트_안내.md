## 1. 구글시트 만들기

1. 구글 드라이브에서 새 구글시트를 만듭니다. 이름 예: `잠실점 에비뉴엘 도면협의`
2. 메뉴 **확장 프로그램 → Apps Script** 를 엽니다.

## 2. 코드 붙여넣기

Apps Script 편집기에서 아래 4개 파일을 만듭니다. **파일 이름이 정확히 같아야** 합니다.

| 편집기에서 만들 파일 | 종류 | 붙여넣을 내용 |
|---|---|---|
| `Code` | 스크립트 (기본으로 있는 `Code.gs`) | `src/Code.gs` 전체 |
| `Index` | **＋ → HTML** | `src/Index.html` 전체 |
| `Styles` | **＋ → HTML** | `src/Styles.html` 전체 |
| `App` | **＋ → HTML** | `src/App.html` 전체 |

그다음 시간대를 맞춥니다.
- 왼쪽 **⚙ 프로젝트 설정** → **"appsscript.json" 매니페스트 파일을 편집기에 표시** 체크
- 편집기에 생긴 `appsscript.json` 내용을 `src/appsscript.json` 으로 바꿉니다.

**💾 저장**(Ctrl+S)합니다.

## 3. 초기 설정과 PIN

1. 구글시트 탭으로 돌아가 **새로고침**합니다. 상단에 **도면협의** 메뉴가 생깁니다.
2. **도면협의 → ① 초기 설정 (시트 만들기)** 를 누릅니다.
   - 처음 한 번 권한 승인 창이 뜹니다. 본인 계정 선택 → "고급" → "(프로젝트명)(으)로 이동" → 허용.
   - 승인 후 메뉴를 한 번 더 누르면 시트 5개가 만들어집니다: `매장`, `검토서`, `준수사항`, `자주쓰는문구`, `변경기록`
3. **도면협의 → ② PIN 설정 – 소장**, **② PIN 설정 – 부소장** 에서 각각 숫자 4~8자리 PIN을 정합니다.
   - PIN은 시트가 아니라 스크립트 속성에 암호화(해시)되어 저장되므로 시트에는 보이지 않습니다.
   - PIN을 바꾸려면 같은 메뉴를 다시 실행하면 됩니다.
   - 1.7부터 첫 화면은 PIN 칸 하나뿐이고, **PIN으로 소장/부소장을 구분**합니다. 그래서 두 사람 PIN은 서로 달라야 하며, 같은 PIN으로 정하려 하면 거부됩니다.
   - 기기마다 처음 한 번만 PIN을 넣으면 그다음부터는 바로 대시보드가 열립니다. 로그아웃하거나 브라우저 기록을 지우면 다시 묻고, PIN을 바꾸면 기억된 기기도 새 PIN을 한 번 넣어야 합니다. 기기에는 PIN이 아니라 확인용 표만 남습니다.
   - 다른 사람으로 바꾸려면 대시보드 **로그아웃** 후 그 사람 PIN을 넣습니다.

## 4. 웹앱으로 배포

1. Apps Script 편집기 오른쪽 위 **배포 → 새 배포**
2. ⚙ 유형 선택 → **웹 앱**
3. 설정
   - 설명: `도면협의 v1`
   - 다음 사용자 인증정보로 실행: **나**
   - 액세스 권한이 있는 사용자: **모든 사용자**
4. **배포** → 나오는 **웹 앱 URL** 을 복사합니다. 이 주소로 접속하면 로그인 후 **대시보드가 첫 화면**으로 열립니다.

> 접근은 PIN으로 막습니다. URL은 소장·부소장 두 분만 공유하세요.
> 구글 로그인까지 요구하려면 3번에서 "Google 계정이 있는 모든 사용자"를 고르면 됩니다.

## 4-2. 지침 준비 (지침 검색·쪽 미리보기)

지침 PDF를 드라이브 폴더에 넣고, 웹앱에서 버튼 한 번으로 검색 색인을 만듭니다. 파이썬 같은 별도 프로그램은 필요 없습니다.

1. 웹앱 대시보드 오른쪽 위 **지침 관리** 를 누릅니다.
   - 처음 열면 내 드라이브에 `도면협의_지침` 폴더가 자동으로 생깁니다. (시트 메뉴 **도면협의 → ④ 지침 폴더 열기** 로도 열 수 있습니다.)
2. **드라이브에서 폴더 열기** 를 눌러 지침 PDF를 올립니다.
   - 예: `시설공사지침_2024.07.09.pdf`, `통합안전관리지침_26.pdf`
   - 글자를 선택할 수 있는 PDF만 검색됩니다. 종이를 스캔한 사진 PDF는 검색되지 않습니다.
3. 지침 관리 화면에서 **폴더 다시 확인** → PDF 옆 **색인 만들기** 를 누릅니다.
4. 입력 창에 다음을 넣고 **만들기 시작**:
   - **지침 이름**: 예) 타워&몰 통합안전관리지침 (26년 개정판)
   - **줄임말**: 특이사항 삽입 문구에 들어갑니다. 예) `통합안전관리지침` → `(통합안전관리지침 방화및방염관련, p.91)`
   - **쪽 아래에 지침 안 쪽 번호(예: 6/10)가 있음**: 시설공사 지침처럼 쪽 아래에 "6/10"이 있으면 체크합니다. → `(설비공사 지침 6/10, p.30)`
5. 진행 막대가 끝나면 바로 검색에 나옵니다. PC 기준 지침 하나에 1~3분 걸립니다.
   - 작업 중에는 화면을 닫지 마세요. 끊겨도 저장된 쪽은 남아 있어서 **이어서 만들기** 로 나머지만 만듭니다.
   - 색인과 쪽 이미지는 `도면협의_지침/_검색색인 (자동 생성 · 지우지 마세요)` 폴더에 저장됩니다.
   - 웹앱이 대신 읽어 오므로 드라이브 공유 설정을 바꿀 필요가 없습니다.

## 4-3. 시방서 발송 준비 (1.6)

1. **보내는 주소**: 웹앱을 배포한 구글 계정 Gmail → ⚙ 모든 설정 보기 → **계정 및 가져오기 → 다른 주소에서 메일 보내기** 에 `max2122@nate.com` 이 등록돼 있어야 합니다 (등록·테스트 완료).
   - 등록이 빠져 있으면 구글 계정 주소로 보내고 답장은 nate로 받도록 보냅니다. 발송 창에 주황색 안내가 뜹니다.
   - 주소를 바꾸려면 `Code` 파일 맨 위 `SPEC_FROM`, `SPEC_FROM_NAME` 을 고칩니다.
2. **시방서 파일**: 드라이브 `도면협의_지침` 폴더에 ZIP 2개
   - 이름에 `Tenant` 가 들어간 .zip → **Tenant 시방서** (지금: `01_Tenant 시방서.zip`)
   - 이름에 `Crown` 이 들어간 .zip → **The Crown 시방서** (지금: `02_B1F The Crown 시방서.zip`)
   - 새 판은 드라이브에서 파일 ⋮ → **파일 정보 → 버전 관리 → 새 버전 업로드** 로 바꾸면 이미 보낸 링크도 새 파일을 가리킵니다. 새 이름으로 올려도 이름에 Tenant/Crown만 있으면 됩니다 (같은 종류가 둘이면 최근 파일).
   - 처음 보낼 때 앱이 ZIP 공유를 **링크가 있는 모든 사용자 · 보기** 로 바꿉니다. 지침 관리는 PDF만 다루므로 ZIP과 섞이지 않습니다.
3. 구글시트 메뉴 **도면협의 → ⑤ 시방서 발송 준비 확인** 을 누릅니다. 처음에는 권한 승인 창이 뜹니다 (계정 선택 → 고급 → 이동 → 허용). 보내는 주소 ✓, 시방서 2개 ✓ 가 나오면 준비 끝입니다.
4. 개인 Gmail은 하루에 보낼 수 있는 메일 수에 한도가 있습니다(받는 사람 기준 약 100명). 넘으면 "내일 다시 보내 주세요" 안내가 뜹니다.

## 4-4. 바로가기 주소 (짧은 주소 · 여러 구글 계정 오류 대책, 1.8.4)

브라우저에 구글 계정이 2개 이상 로그인돼 있으면 웹앱 `/exec` 주소가 「현재 파일을 열 수 없습니다」로 열리지 않을 수 있습니다. 그래서 웹앱을 **바로가기 페이지(껍데기, GitHub Pages)** 안에서 엽니다. 바로가기 주소를 넣으면 **검토서 1쪽 아래 QR**과 **원격 서명 메일의 [서명하기] 링크**가 그 주소로 만들어집니다. (서류 요청·시방서 메일에는 앱 링크가 없어 바뀌지 않습니다.)

1. 시트 메뉴 **도면협의 → ⑧ 웹앱 주소 · 바로가기 주소** → 맨 위 **웹앱 주소(/exec)** 를 복사합니다.
2. GitHub 껍데기 `fm/apps.js`의 도면협의(`dw`) 줄에 그 `/exec` 주소를 넣고, `https://계정이름.github.io/fm/dw/`가 로그인 화면을 띄우는지 확인합니다.
3. 다시 **⑧**을 눌러 아래 칸에 `https://계정이름.github.io/fm/dw/`를 넣고 [확인]. 「시험해 보기」 주소(`…/fm/dw/?store=시험`)를 새 창에서 열어 로그인 화면이 뜨는지 봅니다.
4. 검토서를 열어 **A4 인쇄(미리보기)** → 1쪽 아래 QR을 휴대폰으로 찍어 봅니다 → 바로가기 주소로 열리고, 로그인하면 그 매장 검토서가 열립니다.
5. TinyURL `tinyurl.com/avenuel-dr`의 원래 주소(Long URL)에도 같은 바로가기 주소를 넣습니다. **QR에는 TinyURL이 아니라 바로가기 주소가 들어갑니다** (뒤에 붙는 `?store=`가 빠지지 않게).

- 형식: `https://`로 시작하고 공백·`?`·`#`가 없어야 합니다. 형식이 틀리면 저장하지 않고, 시트에서 직접 틀리게 고쳐도 쓰지 않고 `/exec`를 씁니다.
- **비우고 [확인]** 하면 바로가기 주소를 지우고 예전처럼 `/exec`를 씁니다.
- 이미 출력한 QR·보낸 메일의 링크는 바뀌지 않습니다. 이제부터 만드는 것부터 새 주소입니다.
- 계정을 옮겨 `/exec`가 바뀌어도 바로가기 주소·TinyURL·QR은 그대로 두고, 껍데기 `apps.js` 한 줄만 고칩니다.
- 앱끼리 서버로 부르는 주소(⑥ 블럭 연결 키의 웹앱 주소)는 계속 `/exec`입니다. 업무지원 앱 설정의 도면협의 주소는 `/exec`로 둡니다.

## 6. 계정 옮기기 (기존 계정 → 새 계정, 1.8.3)

도면협의 시트와 드라이브 자료를 다른 구글 계정(예: 업무지원 앱 계정)으로 옮길 때 씁니다. **복사가 아니라 소유권을 넘기므로** 파일 ID가 그대로입니다. 그래서 예전 사진·협의서·PDF가 앱에서 그대로 보이고, 이미 메일로 보낸 검토서 링크도 열리며, PIN도 그대로입니다. 두 계정 모두 **개인 Gmail**이어야 합니다.

넘기는 것: **이 시트(Apps Script 포함) + 폴더 4개(`도면협의_사진`, `도면협의_출력`, `도면협의_지침`, `도면협의_백업`)와 그 안 모든 폴더·파일**. 휴지통에 있는 것과 다른 계정 소유 파일은 넘기지 않습니다(「건너뜀」).

### 0. 준비 — 기존 계정
1. 앱을 쓰지 않는 시간(퇴근 뒤)에 합니다.
2. 보험으로 [구글 테이크아웃](https://takeout.google.com)에서 드라이브를 내려받아 둡니다.
3. 시트 메뉴 **③ 자동 백업 끄기**. (기존 계정 이름으로 백업이 계속 생기는 것을 막습니다.)
4. 두 계정을 Google One 가족 그룹에 넣었다면 새 계정에 용량이 충분한지 확인합니다.

### 1. 넘기기 요청 — 기존 계정
1. 기존 계정으로 시트를 열고 **도면협의 → ⑦ 계정 옮기기 → 1. [기존 계정] 소유권 넘기기 요청**.
2. 새 계정 이메일을 넣습니다.
3. 시트에 **`_계정이전`** 탭이 생기고, 폴더 안 파일까지 하나씩 「요청함」으로 바뀝니다. 시트는 맨 마지막에 넘깁니다.
   - 4분 30초 넘게 걸리면 「1분 뒤 자동으로 이어서」 합니다. 시트를 닫아도 됩니다. 다시 메뉴를 누르면 **[예] = 이어서**.
   - 「오류」가 있으면 메뉴를 다시 눌러 [예]를 고르면 그 항목만 다시 시도합니다.
4. 새 계정에 「소유권 이전」 알림 메일이 여러 통 갈 수 있습니다. **메일은 무시하고** 다음 단계의 메뉴로 받으면 됩니다.

### 2. 받기 — 새 계정
1. `_계정이전` 탭에 「대기」가 없어지면, **새 계정으로** 같은 시트를 엽니다. (새 계정에 편집자로 공유돼 있어서 「공유 문서함」에 보입니다.)
2. **⑦ 계정 옮기기 → 2. [새 계정] 소유권 받기** → 권한 승인 → 모두 「받음」이 될 때까지 기다립니다 (남으면 1분 뒤 자동으로 이어서).
3. **⑦ 계정 옮기기 → 3. 이전 점검** → `_이전점검` 탭에서 확인합니다.
   - 「다른 계정 소유」가 `삭제보관` 줄에만 있으면 괜찮습니다 (지운 매장의 예전 사진).
   - `매장`·`검토서` 줄에 「다른 계정 소유」·「찾을 수 없음」이 있으면 그 줄을 알려 주세요.
4. (선택) 새 계정 드라이브에 `시설팀 통합업무/10_도면협의/`를 만들고 폴더 4개를 그 안으로, 시트는 `시설팀 통합업무/00_시스템/`으로 옮깁니다. **폴더 이름은 그대로** 둡니다.

### 3. 앱 다시 켜기 — 새 계정
1. 시트 → **확장 프로그램 → Apps Script** → **배포 → 새 배포 → 웹앱**. 실행: **나(새 계정)**, 액세스: **모든 사용자** → 권한 승인. **새 `/exec` 주소**가 나옵니다.
2. 시트 메뉴 **③ 자동 백업 켜기** (새 계정 이름으로 예약이 다시 생김).
3. 시방서 보내는 주소: 새 계정 Gmail **설정 → 계정 → 다른 주소에서 메일 보내기**에 `max2122@nate.com` 등록 후 **⑤ 시방서 발송 준비 확인**. (등록하지 않아도 발송은 되지만 새 계정 Gmail 주소로 나가고 답장만 nate로 옵니다.)
4. 바로가기 껍데기 페이지(GitHub Pages)가 가리키는 `/exec` 주소를 새 주소로 바꿉니다. TinyURL·QR은 그대로 씁니다.
5. 새 주소로 점검: 로그인(PIN 그대로) → 예전 매장 사진 보기 → 방재실 협의서 확인하기 → PDF 저장 → 지침 검색 → 시방서 1건.
6. **⑦ 계정 옮기기 → 3. 이전 점검**을 한 번 더 → 「자동 백업 예약 ✓ 있음」 확인.
7. ⑥ 블럭 연결 키는 그대로입니다. 업무지원 앱 설정의 도면협의 주소만 새 `/exec`로 바꿉니다.

### 4. 정리 — 기존 계정 (점검이 끝난 뒤)
1. 기존 계정으로 Apps Script → **배포 → 배포 관리**에서 예전 배포를 **보관처리**합니다. (예전 `/exec` 주소가 멈춥니다.)
2. Apps Script **트리거(⏰)** 에 기존 계정 이름의 예약이 남아 있으면 지웁니다.
3. 기존 계정은 시트·폴더에 **편집자**로 남아 있습니다. 필요 없으면 새 계정에서 공유를 뺍니다.
4. 이제 도면협의와 업무지원이 같은 계정으로 메일을 보내므로 **하루 메일 한도(약 100명)를 두 앱이 함께** 씁니다.

## 사용 요약

- **대시보드**: 매장 목록, 차수 진행(1차·2차·3차), 컨펌완료 버튼(확인 팝업 1회), 검색·월별·정렬, 협의중/컨펌완료 탭
- **새 도면협의**: 첫 저장 때 문서번호가 자동으로 부여됩니다.
  - 형식: `에비뉴엘컨펌_001_YYMMDD`
  - 세 자리 번호는 매장마다 하나이고, 새 매장이 생길 때 1씩 늘어납니다.
  - 뒤 6자리는 최초 등록일(1차 검토일)입니다.
- **다음 차수**: 직전 차수 내용이 복사됩니다. 특이사항, 서명, 준수사항 확인은 비워진 상태로 시작합니다.
- **컨펌완료**: 처리한 사람(소장/부소장)과 시각이 기록되고, 그 매장 검토서는 수정이 잠깁니다. 다시 누르면 취소됩니다.
- **특이사항 지침 검색**: **지침 검색** 버튼, **Ctrl+K**, 또는 문장 중에 `#방화구획` 입력 후 Enter
  - 검토서 문장에 `(설비공사 지침 6/10, p.30)` 형식으로 쪽 번호가 들어갑니다.
- **메인차단기 판정**: 전기용량, 전원 방식(단상 220V / 삼상 380V), 메인차단기 용량을 넣으면 시설공사 지침 기준으로 바로 확인합니다.
  - 기준: 부하전류가 차단기 용량의 60% 이하일 때만 사용 가능합니다(전기공사 지침 3/11, p.16 · KEC 212.4.1). 역률은 0.9로 계산합니다.
  - 기준을 넘으면 "사용이 불가능한 차단기 입니다" 팝업에 계산 과정과 지침에 맞는 차단기 용량(권장값 포함 3개)이 나오고, 버튼 한 번으로 고칠 수 있습니다.
  - 사용 불가 상태에서는 임시저장만 되고, 검토 완료 저장·출력·PDF는 막힙니다.
  - 역률·표준 차단기 목록은 `App.html` 의 `BRK` 설정에서 바꿀 수 있습니다.
- **자동 저장**: 이미 저장된 검토서는 수정 후 30초가 지나면 자동 저장됩니다. **Ctrl+S** 로 바로 저장할 수도 있습니다.

  - 사진은 **마지막으로 쓴 문장 끝**에 붙습니다. 오른쪽에 자리가 없으면 다음 줄 처음에 붙습니다.
  - 사진을 누르면 파란 테두리가 생기고: 끌어서 옮기기, 오른쪽 아래 동그라미로 크기 조절(비율 유지), 아래 가운데 **↺ ↻** 로 90도씩 돌리기, 오른쪽 위 **✕** 로 빼기.
  - 사진은 글 위(맨 위층)에 놓입니다. 사진이 붙은 문장 앞에 글을 넣거나 지우면 사진도 그 문장을 따라 움직입니다.
  - 출력할 때 사진이 1쪽 칸에 다 안 들어가면 붙은 문장과 함께 **별지로 넘어갑니다**. 편집칸에 주황 점선 "여기부터 별지 2쪽"이 보입니다.
  - 한 차수에 **10장까지**. 사진은 긴 변 1600px로 줄여 드라이브 `도면협의_사진/문서번호` 폴더에 저장되고, 시트에는 위치·크기·회전만 저장됩니다.
  - 다음 차수는 사진 없이 시작하고, **이전 차수 특이사항 불러오기**를 누르면 사진도 같은 문장에 붙어서 같이 옵니다.
  - 새 검토서에서 사진을 붙이면 먼저 자동 저장해 문서번호를 받습니다 (테넌트명 필요).
  - 인터넷이 끊긴 상태에서는 사진을 올릴 수 없다고 안내합니다. 연결된 뒤 다시 붙여 주세요.
  - 아이폰 사진이 HEIC 형식이라 안 붙으면, 아이폰 **설정 → 카메라 → 포맷 → 높은 호환성**으로 바꾸면 됩니다.

## 1.3.2 — 휴대폰 · 태블릿 · PC 화면 맞춤

화면 크기에 맞춰 배치가 바뀝니다. 휴대폰(320px부터), 휴대폰 가로, 태블릿 세로·가로, 노트북, PC(1920px)까지 13가지 크기에서 19개 화면을 점검해 넘침·잘림·벗어남이 없도록 했습니다.

- **매장 목록**: PC는 표, 태블릿·휴대폰은 매장별 카드로 바뀝니다 (태블릿 2열, 휴대폰 1열).
- **휴대폰 · 휴대폰 가로**: 위쪽 막대는 따라오지 않아 화면을 넓게 쓰고, **임시저장 · 미리보기 · 검토 완료** 와 저장 상태가 화면 아래에 고정됩니다.
- **서명란**: 휴대폰에서는 담당별 카드(소속 / 성명·연락처 / 서명)로 바뀝니다.
- **팝업**: 화면보다 길면 스크롤되고, 좁은 화면에서는 버튼이 위아래로 쌓입니다. 서명 패드는 화면 높이에 맞춰 줄어듭니다.
- **지침 쪽 미리보기**: 휴대폰에서는 쪽을 화면 폭에 맞춰 보여주고 +/− 로 확대합니다.
- **터치**: 손가락으로 누르는 버튼을 크게 했고, 아이폰·아이패드에서 입력 칸을 누를 때 화면이 확대되지 않도록 했습니다. 아이폰 홈 막대·노치 영역도 피합니다.
- **큰 모니터**: 1600px 이상에서는 내용 폭을 조금 넓혔습니다.

## 1.3.1 — 아이패드 대응

- **드라이브에 저장** (출력 화면): 출력물 PDF를 드라이브 `도면협의_출력/문서번호` 폴더에 저장하고 **PDF 열기** 링크를 보여줍니다. 같은 차수를 다시 저장하면 새 내용으로 바뀝니다.
  - 아이패드에서는 구글 웹앱 구조상 **A4 인쇄**나 **PDF 저장**(내려받기)이 막히거나 레이아웃이 다르게 나올 수 있습니다. 그럴 때 **드라이브에 저장 → PDF 열기 → 공유(↑) → 프린트** 로 인쇄하세요.
  - 아이패드에서는 출력 화면에 이 안내가 표시됩니다.
- 옛 iPadOS(16.3 이하) 사파리에서 앱이 열리지 않을 수 있던 코드(정규식 문법)를 고쳤습니다.
- 아이패드 사파리·크롬은 둘 다 애플 WebKit 엔진으로 동작합니다. 같은 엔진(WebKit)에서 아이패드 화면 크기로 로그인·입력·서명·문구·지침 검색·출력·PDF·드라이브 저장·끊김 보관·지침 색인 만들기를 점검했습니다.
- 지침 색인 만들기는 아이패드에서도 되지만 PC가 더 빠르고 안정적입니다. 가능하면 PC에서 하세요.

## 지침 추가·개정

코드를 고치거나 다시 배포할 필요가 없습니다.

- **새 지침 추가**: 지침 PDF를 `도면협의_지침` 폴더에 올림 → 지침 관리 **폴더 다시 확인** → **색인 만들기**
- **같은 파일을 고쳐 다시 올림**: 지침 관리에 "PDF가 바뀜 · 다시 만들기 필요"가 뜹니다 → **다시 만들기**
- **개정판을 새 파일로 받음**: 새 PDF를 올리고 **색인 만들기** → **개정판이면 바꿀 지침** 에서 이전 지침 선택. 이전 색인은 휴지통으로 가고 같은 자리에 새 지침이 들어갑니다.
- **이름·줄임말 바꾸기 / 검색에서 빼기**: 지침 관리의 각 지침 버튼. 검색에서 빼도 원본 PDF는 남습니다.
- 이미 검토서에 넣은 쪽 번호 문구는 지침을 바꿔도 그대로입니다.

## 참고 · 제한

- **PDF 저장이 안 될 때**: 기기·브라우저에 따라 웹앱 안에서 바로 내려받기가 막힐 수 있습니다. 그때는 **A4 인쇄 → PDF로 저장** 을 쓰면 같은 결과가 나옵니다.
- **서명 저장 방식**: 서명은 이미지로 바꿔 시트 칸에 저장합니다. 한 칸 최대 5만 자 이내로 자동으로 줄여 저장합니다.
- **동시 수정**: 두 분이 같은 매장의 같은 차수를 동시에 고치면, 나중에 저장한 쪽 내용이 남습니다.
