회사에서 이어서 작업하는 방법 (집 PC에서 정리, 2026-11-22)
================================================================

1. 집에서 끝낸 일
-----------------
- 업무지원(WS) 앱의 큰 파일 Index.html을 기능별 조각 21개로 나눴습니다.
  · 조각 위치: apps/ws/parts/
  · 앞으로 화면 코드는 이 조각을 고치고, 명령어 npm run build:index 로 Index.html을 다시 만듭니다.
  · src/Index.html 은 자동으로 만들어지는 파일이라 직접 고치면 안 됩니다. (직접 고치면 다음 빌드 때 사라짐)
- 나누기 전후 결과 파일 7개의 내용이 완전히 같음을 확인했고, 서버 시험 332개도 모두 통과했습니다.
- 모두 GitHub(avenuel-fm-apps 의 main)에 올렸습니다.
- 직원이 쓰는 화면(fm 저장소)과 구글 배포는 건드리지 않았습니다. 직원 사용에는 영향이 없습니다.

2. 회사 PC에서 처음 한 번만 할 일
-------------------------------
1) avenuel-fm-apps 폴더를 최신으로 받습니다. (git pull)
2) 클로드 데스크톱 앱의 Code 탭에서 Desktop/app 이 아니라 "avenuel-fm-apps" 폴더를 프로젝트로 엽니다.
   - 폴더를 믿어도 되냐고 물으면 허용합니다.
3) apps/ws 폴더에서 npm install 을 한 번 합니다. (Python 3 도 필요)
4) 확인: python apps/ws/tools/build_index.py --check  →  "같음" 이 나오면 정상

3. 그 다음부터는 (자동)
--------------------
- 새 세션을 시작할 때마다 GitHub 최신 내용을 자동으로 받습니다. (설정 위치: .claude/)
  · "이미 최신" 또는 "새로 받음 (N개 변경)" 안내가 나옵니다.
  · 저장 안 된 수정이 있으면 받기를 건너뛰고 "직접 확인 필요"라고 알려 줍니다.
- 이어 쓰는 대화(재개)에서는 자동 받기가 돌지 않습니다. 새 세션을 열 때 돕니다.
- 클로드 웹(claude.ai)에서는 이 자동 받기가 적용되지 않습니다. 데스크톱 앱 Code 탭에서 쓰세요.
- 대화 내용과 세션 이름은 PC마다 따로입니다. 새 대화에서 이렇게 말하면 이어집니다:
  "docs/인계_현재상태.md 읽고 이어서 진행해"

4. 다음 할 일 (순서대로)
---------------------
1) 뒤로가기 수정
   - 원인: 화면 이동 때 쓰는 뒤로가기 기록(google.script.history)이 구글 웹앱 안에서만 되는 기능이라,
     직원이 쓰는 fm 주소의 앱에서는 기록이 안 쌓여 폰의 뒤로가기가 앱 밖으로 나갑니다.
   - 고칠 곳: apps/ws/parts/30_core.js 의 go() 와 뒤로가기 처리
   - 자세한 계획: docs/명령서_WS_Index분리_뒤로가기.md (4절, 11~13단계)
   - 시작 전에 정할 것: 메인 화면에서 뒤로가기를 눌렀을 때 "한 번 더 누르면 종료" 안내를 넣을지 (권장: 넣지 않음)
2) 배포 (아직 아무것도 배포하지 않았습니다)
   - 직원이 안 쓰는 시간에, 사용자가 시점을 정한 뒤에 합니다.
   - 올리기 전에 안드로이드·아이폰 실기기에서 직접 확인합니다.
   - 올린 뒤 이상하면 fm 저장소에서 마지막 올린 기록을 되돌리면 이전 화면으로 돌아갑니다.
3) (보류) fm 폴더 통합
   - 두 폴더(avenuel-fm-apps/fm 과 독립 저장소 fm)가 어긋나는 문제가 생겼을 때만 진행합니다.
   - 계획: docs/명령서_fm폴더_통합.md
