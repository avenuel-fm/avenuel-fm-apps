# 블럭 연동 규칙 (v2.0)

수정: 2026-11-23 · 도면협의 연동 부분 삭제, 매장ID는 지도 기준으로 변경 (이전 v1.8은 git 기록에 있음)

시설팀 업무지원 앱, 전체 대시보드, 이후 업무 앱은 이 규칙을 따릅니다. 각 앱은 **블럭**입니다. 자기 구글시트와 자기 Apps Script 웹앱을 따로 갖고, 혼자서도 동작합니다. 전체 방향은 `docs/통합업무프로그램_기획안.md` 9번을 따릅니다.

> 도면협의 앱은 다른 블럭과 연동하지 않습니다. (이전 버전의 `summary`·`stores`·`defect` 통로와 연결 키 규칙은 삭제)

## 1. 매장ID는 지도가 만든다

| 약속 | 내용 |
|---|---|
| 고유번호 | 매장의 **매장ID(storeId)** 는 **지도(`map`)** 에서 만들어집니다. 지도에서 매장을 추가·변경·삭제한 내용이 매장ID로 반영됩니다 |
| 사용처 | 매장 목록(매장ID)을 쓰는 앱은 **열화상 점검**과 **지도** 뿐입니다 |
| 다른 앱 | 위험작업신청서·야간작업 등 나머지 앱은 매장 연동 방식을 **추후 결정**합니다. 그때까지는 매장명·업체명을 **직접 입력**받습니다 |
| 이름이 바뀔 때 | 매장명이 바뀌어도 매장ID는 그대로이므로, 매장ID로 연결된 기록(열화상 비교 등)은 끊기지 않습니다 |

## 2. 공통 약속 (모든 블럭)

| 약속 | 내용 |
|---|---|
| 날짜 | 글자로 `yyyy-MM-dd`, 일시는 `yyyy-MM-dd HH:mm`, 시간대는 Asia/Seoul |
| 변경기록 | 시트 `변경기록` 탭에 `일시 · 누가 · 무엇을 · 내용` 순서로 남깁니다. 매장ID를 쓰는 앱은 매장ID 칸을 더합니다 |
| 버전 | 각 블럭은 자기 이름과 버전을 확인할 수 있게 둡니다 |
| 메일 | 보내는 주소는 max2122@nate.com(Gmail "다른 주소에서 메일 보내기")이고, 맨 아래 시설팀 서명 4줄을 붙입니다 |
| 실패 | 한 블럭이 응답하지 않아도 다른 블럭과 대시보드는 그대로 동작합니다 |

## 3. 나중에 정할 것

- 위험작업신청서·야간작업 등이 매장 목록을 쓸지 여부.
- 직원 개인 PIN + 역할(기획안 6번)로 넘어가면 로그인은 전체 대시보드가 맡습니다.
- 전체 대시보드가 각 블럭 숫자를 가져오는 방식(이전의 `summary` 통로 대체).
