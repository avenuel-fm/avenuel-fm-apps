# 블럭 연동 규칙 (도면협의 앱 기준 · v1.8)

작성: 2026-10-31 · 기준 블럭: 도면협의 앱(잠실점 에비뉴엘 공사 도면 검토서)

시설팀 업무지원 앱, 전체 대시보드, 이후 업무 앱은 이 규칙을 따릅니다. 각 앱은 **블럭**입니다. 자기 구글시트와 자기 Apps Script 웹앱을 따로 갖고, 혼자서도 동작합니다. 블럭끼리는 아래 통로로만 주고받습니다. 전체 방향은 `docs/통합업무프로그램_기획안.md` 9번을 따릅니다.

## 1. 연결 정보

| 항목 | 값 | 어디서 |
|---|---|---|
| 웹앱 주소 | `https://script.google.com/macros/s/…/exec` | 도면협의 Apps Script → 배포 관리 |
| 연결 키 | 40자 영문·숫자 | 도면협의 구글시트 메뉴 **도면협의 → ⑥ 블럭 연결 키 보기** |

- 다른 블럭은 이 두 값을 **자기 스크립트 속성**(Script Properties)에 넣어 둡니다. 시트나 화면에는 넣지 않습니다.
- 키를 새로 만들면 예전 키는 바로 안 통합니다. 쓰는 블럭의 설정도 함께 바꿔야 합니다.
- 브라우저(화면 코드)에서 부르지 말고, **서버(Apps Script `UrlFetchApp`)끼리** 부릅니다. 키가 화면에 노출되면 안 되기 때문입니다.

## 2. 통로

모든 응답은 JSON입니다. 성공하면 `ok: true`, 실패하면 `ok: false, error: "사유"`입니다.

### 2-1. ping — 살아 있는지·버전 (키 없이)
```
GET {웹앱주소}?api=ping
→ { ok, block: "drawing-review", title: "도면협의", version: "1.8", label: "잠실점 에비뉴엘" }
```

### 2-2. summary — 전체 대시보드 카드 숫자
```
GET {웹앱주소}?api=summary&key={연결키}[&year=2026[,2027]]
→ { ok, block, title, version, url, year,
    counts: { total, ongoing, confirmed, openIn7Days, chiefWaiting, specUnsent, docMissing, defectSent },
    labels: { total:"전체 매장", ongoing:"협의중", confirmed:"컨펌완료", openIn7Days:"7일 내 오픈",
              chiefWaiting:"시설 소장 확인 대기", specUnsent:"시방서 미발송", docMissing:"서류 미제출", defectSent:"하자 발송" } }
```
- `year`는 최초 등록일(문서번호 날짜) 기준입니다. 쉼표로 여러 해를 넣으면 합쳐서 셉니다. 빼면 전체입니다.
- 카드를 누르면 `url`(도면협의 웹앱)로 보냅니다.

### 2-3. stores — 매장 목록 (업무지원 앱 「하자점검」 메뉴)
```
GET {웹앱주소}?api=stores&key={연결키}[&year=2026]
→ { ok, block, version, stores: [ {
      storeId, docNo, tenant, location, storeType,
      contractor, contractorName, contractorTel, contractorEmail, ownerCompany,
      periodStart, periodEnd, openDate, status, currentRound, firstDate,
      defectSent,          // 마지막 하자 발송 일시 (없으면 "")
      url                  // 이 매장 검토서 바로 열기 주소 (?store=매장ID)
    } ] }
```
- 하자점검 메뉴를 열 때마다 이 목록을 받아 매장 선택 목록으로 씁니다. 업무지원 앱 쪽에 따로 복사해 두지 않습니다.
- 담당자·연락처·이메일은 그 매장 **마지막 차수** 검토서 값입니다.

### 2-4. defect — 하자 발송 기록
```
POST {웹앱주소}
Content-Type: application/json
{ "api": "defect", "key": "{연결키}", "storeId": "{매장ID}",
  "count": 3, "note": "천장 마감 외 2건", "by": "업무지원 앱 · 소장", "to": "kim@daehan.co.kr" }
→ { ok, storeId, defectSent: "2026-10-31 18:20" }
```
- 업무지원 앱에서 하자 내용을 **발송한 뒤에** 부릅니다. 메일 발송 자체는 업무지원 앱이 합니다.
- 도면협의 쪽에서는 이렇게 표시됩니다.
  - 대시보드 매장 이름 아래 파란 **하자 발송 ✓ 날짜**
  - 검토서 **보낸 메일·발송 기록**에 "하자 발송" 한 줄
  - 시트 `변경기록`
- `count`, `note`, `by`, `to`는 넣지 않아도 됩니다. `note`는 300자, `by`는 40자까지만 저장됩니다.

## 3. 공통 약속 (모든 블럭)

| 약속 | 내용 |
|---|---|
| 고유번호 | 매장은 도면협의의 **매장ID(storeId)** 와 **문서번호(docNo)** 로 가리킵니다. 다른 블럭은 매장을 새로 만들지 않고 이 값을 씁니다 |
| 바로 열기 | 각 블럭은 `?store=매장ID`처럼 특정 건을 바로 여는 주소를 둡니다 |
| 변경기록 | 시트 `변경기록` 탭에 `일시 · 누가 · 무엇을 · 매장ID · 문서번호 · 내용` 순서로 남깁니다 |
| 날짜 | 글자로 `yyyy-MM-dd`, 일시는 `yyyy-MM-dd HH:mm`, 시간대는 Asia/Seoul |
| 버전 | `?api=ping`으로 블럭 이름과 버전을 돌려줍니다 |
| 메일 | 보내는 주소는 max2122@nate.com(Gmail "다른 주소에서 메일 보내기")이고, 맨 아래 시설팀 서명 4줄을 붙입니다 |
| 실패 | 한 블럭이 응답하지 않아도 다른 블럭과 대시보드는 그대로 동작합니다. 대시보드는 그 카드만 "연결 안 됨"으로 표시합니다 |

## 4. 업무지원 앱에서 부르는 예 (Apps Script)

```js
function drawingStores_() {
  var p = PropertiesService.getScriptProperties();
  var url = p.getProperty('DRAWING_URL'), key = p.getProperty('DRAWING_KEY');
  var res = UrlFetchApp.fetch(url + '?api=stores&key=' + encodeURIComponent(key), { muteHttpExceptions: true });
  var out = JSON.parse(res.getContentText());
  if (!out.ok) throw new Error('도면협의 연결 실패: ' + out.error);
  return out.stores;
}

function drawingDefectSent_(storeId, count, note, by) {
  var p = PropertiesService.getScriptProperties();
  var res = UrlFetchApp.fetch(p.getProperty('DRAWING_URL'), {
    method: 'post', contentType: 'application/json', muteHttpExceptions: true,
    payload: JSON.stringify({ api: 'defect', key: p.getProperty('DRAWING_KEY'), storeId: storeId, count: count, note: note, by: by })
  });
  return JSON.parse(res.getContentText());
}
```

## 5. 나중에 바꿀 것

- 직원 개인 PIN + 역할(기획안 6번)로 넘어가면 로그인은 전체 대시보드가 맡습니다. 블럭끼리는 지금처럼 연결 키로 통신합니다.
- 업무지원 앱 「하자점검」 화면·메일 양식은 그 앱을 만들 때 정합니다.
