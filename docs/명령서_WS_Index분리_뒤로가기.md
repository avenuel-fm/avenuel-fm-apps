# 명령서: 업무지원(WS) `Index.html` 모듈별 분리 + 뒤로가기 수정

작성: 2026-11-22 (집 PC) · **설계 문서입니다. 「진행시켜」 전에는 코드를 고치지 않습니다.**
관련: `docs/명령서_fm폴더_통합.md` (별개 일, 지금은 보류)

## 0. 한눈에

| 일 | 내용 | 결과 |
|---|---|---|
| **A. 분리** | `apps/ws/src/Index.html`(4,231줄·426KB)을 기능별 조각 파일 20여 개로 나눔 | 앱 동작은 **한 글자도 안 바뀜** (같은지 숫자로 증명) |
| **B. 뒤로가기** | 폰 뒤로가기가 앱 안 이전 화면으로 가게 수정 | 화면 이동 함수 `go()` 등 **작은 수정 2곳** |

- 순서는 **A → B**. 분리를 먼저 끝내 「똑같다」를 증명한 뒤에 B를 따로 고쳐야, B로 생긴 차이만 깨끗이 보입니다.
- 둘 다 **이 PC(또는 회사 PC)의 작업 갈래 `ws-index-split` 에서만** 합니다. `main`·`fm` 저장소·구글(clasp)에는 올리지 않습니다. 직원은 쓰는 중이므로 **배포 시점은 사용자가 따로 정함**.

## 1. 왜 나누나

- 수정이 자주 생기는데 한 파일이 4천 줄이라 찾고 고치기 어렵고, 한 군데 실수가 다른 곳에 번지기 쉽습니다.
- 나누어도 앱 속도·기능은 같습니다 (만들 때 다시 한 파일로 합치기 때문).
- 이미 SQL 24개는 기능별로 나뉘어 있어서, 화면 쪽만 뭉쳐 있는 상태입니다.

## 2. 지금 `Index.html` 구조 (확인한 것)

- 1~6줄 머리 · 7~639줄 `<style>` · 640~646 본문 · **647~4229 `<script>`(약 3,580줄)** · 끝 2줄.
- `<script>` 안에 `/* ── 구역 ── */` 주석이 **약 40개** 있어 자연스러운 칼날 자리입니다. (예: 도우미 653, 화면 이동 747, 로그인 773, 메인 926, 시방서 972, TBM 1393, 명일작업 1638, 출근현황 1793, 종합업무일지 1876, 공조기 2046, 점검 2378, 소화전 2492, QR 관리 2602, PDF 3512, 공사장 3817, 그리기 4161)
- 최상위 이름 561개, 이름 겹침 **0개** → 파일을 나눠도 이름 충돌 없음.
- 공용 상태 `const S`(전역 하나)를 모든 구역이 같이 씀. **이번에는 이 구조를 바꾸지 않습니다** (너무 큰 일, 별도 판단).

## 3. 나누는 방식 (A안: 조각은 바깥 폴더, 합친 결과를 `src/`에)

```
apps/ws/
  parts/                    ← 앞으로 여기서 고침 (조각 파일들)
  tools/build_index.py      ← 조각을 순서대로 이어 붙여 src/Index.html 을 만듦
  src/Index.html            ← 자동 생성물 (직접 고치지 않음). 구글에 올라가는 파일은 이것 하나 그대로
  tools/build_fm.py         ← 기존 그대로 (src/Index.html 을 읽어 fm/ws/app.html 등 생성)
```

- 조각을 `src/` **안에 두지 않는 이유**: clasp 가 `src` 의 모든 `.html` 을 구글에 올리기 때문.
- 이렇게 하면 `build_fm.py`·시험·구글 올리기가 **전부 지금과 똑같이** 동작합니다.

## 4. 뒤로가기(B)가 안 되는 이유와 고칠 방법

**원인 (코드로 확인)**
- `go(view)` 가 화면을 옮길 때 `google.script.history.push(...)` 로 뒤로가기 기록을 남기는데, 이 기능은 **구글 웹앱 안에서만** 있습니다.
- 지금 직원이 쓰는 `fm/ws/app.html` 은 GitHub 페이지에서 직접 열리므로 그 기능이 없고, `try/catch` 가 오류를 조용히 삼켜 **기록이 안 쌓임** → 폰 뒤로가기를 누르면 앱 밖으로 나감.
- `popstate`(브라우저 뒤로가기 신호) 처리 자체가 코드에 **없음**.

**수정 방향 (30_core.js, 2곳 + 보조)**
1. `go()`: 구글 웹앱이면 지금 방식, 아니면 `history.pushState({v: view}, '')` 로 기록.
2. 앱 시작·로그인 직후 `history.replaceState({v: 첫 화면}, '')` 로 바닥 기록 하나 깔기.
3. `popstate` 처리 추가: `state.v` 가 있고 로그인 상태면 `S.view = v; render()`.
4. **막아야 하는 경우** (뒤로가기가 데이터를 잃게 하면 안 됨):
   - 저장 안 된 입력이 있는 화면(`risk` 의 `dirty`, `csck` 의 `csLeave()` 등 기존 `back()` 의 확인창 조건) → 뒤로가기 때도 같은 확인창. 취소하면 `pushState` 로 현재 화면 기록을 다시 쌓아 제자리 유지.
   - `pdf` 화면은 기존대로 `S.pdf.from` 으로 복귀.
   - 지도(`map`)처럼 안에 또 다른 창이 있는 화면은 시험으로 따로 확인.
5. 메인 화면에서 뒤로가기: 앱을 떠남(기본). 「한 번 더 누르면 종료」 안내는 **사용자 결정 필요**(권장: 지금은 넣지 않음).

**영향 범위**: `go()` 호출 약 수십 곳은 그대로, `back()` 의 `PARENT` 표도 그대로. 화면 모양·데이터는 안 바뀜.

## 5. 작업 순서

### 준비 (1단계)
0. 이 PC에 **Python·`npm install`·Playwright** 설치 필요 (현재 없음). 설치 전에 사용자 확인.
1. `git status` 깨끗한지 확인, 갈래 `ws-index-split` 만들기.
2. **기준값 저장**: `src/Index.html` 과 `build_fm.py` 가 만드는 `app.html`·`spec.html`·`check.html`·`check-sb.html`·`eh-sb.html`·`eq.html` 의 SHA-256(내용 지문)을 임시 파일에 기록. (`build_fm.py` 는 `avenuel-fm-apps/fm/` 에 쓰므로 실행 전후로 `git status` 로 변화 확인; 아직 `fm` 저장소로는 복사하지 않음)
3. 읽는 곳 확인: `Index.html` 을 열어 읽는 도구·시험이 어디인지 검색(`grep`) — 경로를 바꾸지 않으므로 영향 없어야 함.
4. **기준 시험**: `npm test`(서버) 와 `npm run test:sb` 일부 통과 상태 기록 (분리 전 이미 실패하는 시험이 있으면 그 목록을 따로 저장).

### A. 분리 (5~9단계)
5. 일회용 스크립트로 `Index.html` 을 구역 주석 글자 기준으로 조각 20여 개로 자름. **다시 이어 붙여 원본과 바이트까지 같은지 먼저 확인** (다르면 중단).
6. `tools/build_index.py` 작성: 조각을 정해진 순서로 이어 붙여 `src/Index.html` 생성, 맨 위에 「자동 생성: parts/ 를 고치세요」 주석은 **넣지 않거나**(지문 비교를 위해) 분리 확정 후 마지막에만 추가.
7. `package.json` 에 `"build:index": "python tools/build_index.py"` 추가. `build:fm` 앞에서 자동으로 돌도록 연결할지는 결정(권장: 연결).
8. **검증**: 새로 만든 `src/Index.html` 과 `build_fm.py` 결과 6개의 지문이 2단계와 **모두 같음**. 같지 않으면 원인 찾기 전까지 다음 단계 금지.
9. 시험 전체 한 번(`npm test`, `npm run test:sb`) — 기준 시험과 같은 결과.
10. 임시 파일 정리, 분리 커밋(저장 기록) — **여기까지는 화면·동작이 100% 같음**.

### B. 뒤로가기 (11~13단계)
11. `parts/30_core.js` 의 `go()`·`setChangeHandler` 부분만 4절대로 수정. 새로 만든 지문과 비교해 **차이가 이 부분뿐**인지 확인.
12. **시험 추가·실행** (Playwright, 휴대폰 크기 화면):
    - 메인 → 점검 → 소화전 → 뒤로 → 뒤로 → 메인
    - 입력 중 뒤로(확인창 뜸 / 취소하면 그대로)
    - PDF 보기에서 뒤로
    - 지도·CAD 화면에서 뒤로
    - 로그인 전 뒤로(앱 오작동 없음)
    - 기존 전체 시험도 통과
13. **실기기 확인 요청**: 안드로이드 크롬·아이폰 사파리(홈화면 앱 포함)에서 같은 동작. 이 단계는 사용자만 가능. 이상 시 수정 반복.

### 마무리 (14~15단계, 묶음 끝에 한 번에)
14. 문서: 결정 한 건 추가(WS는 짝수, `90_결정과이력.md`에서 마지막 번호 확인), `CLAUDE.md` 에 「`Index.html` 은 자동 생성, `apps/ws/parts/` 를 고친다」 규칙, `docs/설계/WS_00…` 폴더 설명, `apps/ws/설치_및_테스트_안내.md` 에 올리는 방법·버전 올림(`Code.gs` `APP.version`).
15. **배포는 사용자 결정**: 쓰는 직원이 적은 시간에 (1) `fm/` 결과 `fm` 저장소 복사 (2) 필요 시 clasp. 올리기 전 「바뀐 것 · 되돌리는 법」을 정리해 보여 줌.

## 6. 안전장치

- 분리(A)는 **내용 지문이 같아야만** 다음으로 감 → 「똑같다」를 눈이 아니라 숫자로 확인.
- 직원 화면은 `fm` 저장소가 바뀌어야 바뀜. 이 작업은 15단계 전까지 거기 손대지 않음.
- 되돌리기: 갈래를 버리면 끝. 분리 커밋과 뒤로가기 커밋을 **따로** 남겨 B만 되돌릴 수 있게.
- 구글 웹앱(clasp)에도 올리는 경우: 새 배포 금지, 기존 배포 ID 새 버전으로만 (`DEPLOY.md`).

## 7. 사용자가 정해 줄 것

1. 시작 승인(「진행시켜」)과 Python·npm 설치 허용
2. 메인 화면에서 뒤로가기 시 「한 번 더 누르면 종료」 안내를 넣을지 (권장: 넣지 않음)
3. 배포 시점 (직원이 안 쓰는 시간)
4. 분리된 조각 이름·개수 조정이 필요한지

## 8. 아직 확인하지 못한 것 (가정)

- 줄 번호·구역 개수는 지금 `main` 기준이며, 회사에서 새로 올라온 수정이 있으면 어긋날 수 있음 → 시작 전 최신 받기.
- 뒤로가기 증상이 안드로이드 크롬만인지 아이폰도 같은지, 홈화면 앱(PWA)에서 어떤지는 실기기 확인 전.
- `ws-api.js`/`offline.js` 안에 뒤로가기와 겹치는 처리가 있는지는 B 단계 첫머리에서 한 번 더 확인.
