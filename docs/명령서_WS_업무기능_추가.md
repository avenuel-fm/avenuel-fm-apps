## 1. 공통 원칙

1. 사용자는 비개발자(시설팀 소장)입니다. 화면 글은 쉬운 한국어로, 버튼은 눌러서 바로 알 수 있게 씁니다.
2. 화면 모양은 기존 색·글꼴·버튼 규칙을 따릅니다. 구분선은 기존 **경계선 색**(`#D8DDE5` 계열)을 씁니다. 새 색을 만들지 않습니다.
3. 작업위치는 키보드 입력이 아니라 **버튼 선택**입니다: `B3, B2, B1, 1F, 2F, 3F, 4F, 5F, 6F, 10F, 외곽`. 목록은 한 곳(설정 상수)에 두어 앱 전체가 같이 씁니다.
4. 사진은 올리기 전에 자동으로 작게 줄입니다. 서류 사진(방염서류·각서·위험작업신청서)은 글자가 읽히도록 일반 현장 사진보다 **덜 줄입니다**.
5. 사진 저장이 통신 불량으로 실패하면 기기에 잠시 보관했다가 연결되면 자동으로 올리고, 화면에 「대기 중 N장」을 보여 줍니다(주간·야간·위험작업신청서 공통).
6. 사진을 누르면 확대·축소로 볼 수 있습니다(두 손가락 확대, +/− 버튼, 100~400%). DW 종합방재실 협의서 사진 보기(`openFdView`)와 같은 방식입니다. 같은 부품을 공유합니다.
7. 사진 삭제는 한 번 되묻습니다.
8. **매장ID는 지도에서 만들어집니다.** 매장 목록(매장ID)을 쓰는 곳은 **열화상 점검**뿐입니다. 위험작업신청서·야간작업 등은 업체명·매장명을 **직접 입력**받습니다(`docs/블럭_연동규칙.md` v2.0).
9. 새 열·시트·표는 맨 끝에만 추가하고, 기존 자료는 지우지 않습니다. 새 저장 항목은 Supabase 쪽 상수·함수에도 같이 반영합니다(앱 구조는 `apps/ws/CLAUDE.md`를 먼저 읽고 따름).
10. 배포는 평소 순서(소스 수정 → 빌드 `build:fm` → `fm/` 복사 → 커밋·푸시)를 따릅니다. 코드 고친 뒤 시험을 돌리고, 결과를 쉬운 말로 보고합니다.

## 2. 직원 삭제(퇴사 처리)·파트 선택

**위치**: 출근현황에서 직원 이름을 누르면 나오는 「기본 휴일」 메뉴. **소장·관리파트만** 새 항목이 보입니다.

- **파트 체크**: 전방파트 / 기건파트 중 하나만 선택됩니다. 전방 → 인원 집계에서 전기·방재, 기건 → 기계·건축. 바꾸면 출근현황 집계가 바로 바뀝니다.
- **직원 삭제(퇴사 처리)**: 버튼은 위험색(빨강 글자)으로 표시합니다. 누르면 되묻기 팝업: 「정말 삭제하시겠습니까? ○○○(파트)을 퇴사 처리합니다. PIN과 로그인 인증이 함께 삭제됩니다. 지난 출근·일지 기록의 이름은 그대로 남습니다.」 [취소] [삭제]
- 확인하면 **퇴사 처리**: 직원 행을 지우지 않고 상태를 퇴사(비활성)로 바꿉니다. **PIN과 인증(로그인 정보)은 동시에 삭제**합니다. 한쪽만 지워지는 일이 없도록 한 번에 처리합니다(중간에 실패하면 모두 되돌림).
- 퇴사자는 출근현황·집계·선택 목록에서 빠지고, 과거 기록에는 이름이 남습니다. 소장이 「퇴사자 보기」에서 되살릴 수 있습니다(되살리면 PIN은 다시 만들어야 함).
- 막는 경우: 소장 본인, 마지막 남은 관리자는 삭제 버튼이 눌리지 않습니다.
- 삭제·파트 변경은 변경기록에 남깁니다(누가·누구를·무엇을·언제).
- 권한 확인은 **서버(DB 규칙)에서도** 합니다. 화면에서 버튼만 숨기는 것으로 끝내지 않습니다.

## 3. 리포트 월별 묶음 (온습도 · 공조기 · 에어커튼 공통)

- 온습도 리포트의 「날짜별 상세기록」, 공조기·에어커튼 리포트의 「일일 기록」을 **월 단위로 접고 펼치는 묶음**으로 바꿉니다. DW 대시보드의 월별 묶음(`App.html` `renderDashBody`, `.macc`)과 같은 모양입니다.
- 가장 최근 달만 펼치고 나머지는 접습니다. 머리줄을 누르면 열고 닫습니다.
- 월 머리줄 요약: 온습도 = 평균·최고·최저·기준 초과 횟수, 공조기 = 점검 N회·이상 N건·미점검 N일, 에어커튼 = 점검 N회·이상 N건.
- 기준을 벗어난 날(행)은 색 표시, 「이상만 보기」 필터. 공조기·에어커튼은 설비(번호)·층별 거르기를 두고 선택한 값은 기억합니다.
- 월 단위 인쇄·PDF가 되게 합니다(펼친 달만이 아니라 선택한 달 전체).
- 세 리포트가 **같은 공용 부품**을 쓰게 만들고, 머리줄 요약만 리포트마다 넘깁니다.
- 기준월은 기록 날짜(일자)입니다.

## 4. 서류작업 → 주간/야간 작업내역

서류작업 옆에 **「주간/야간 작업내역」** 메뉴를 추가합니다. 열면 상단에 **주간작업 / 야간작업** 탭이 있습니다.

### 4-1. 주간작업 탭

입력 항목(위에서 아래): 일자 · 파트 체크(전기·방재 / 기계·건축) · 작업자 · 작업위치(버튼) · 작업내용 · **작업 전 사진 / 작업 후 사진** · 사용자재 · 비고.
맨 아래: **뒤로 · 인쇄 A4 · PDF 보기 · 저장**.

- 작업 전 사진(왼쪽)과 작업 후 사진(오른쪽)을 **좌우로** 나누고, 가운데에 **세로 구분선**(경계선 색)을 둡니다. 각각 **최대 4장**, 칸은 2×2입니다. 사진 찍기/갤러리 둘 다 되고, 장마다 ✕로 지웁니다.
- 인쇄·PDF: 각 칸에 **한 장만 있어도 출력**됩니다(빈 칸은 출력하지 않음). 한쪽이 4장 모두 차면 A4 한 쪽에 맞게 **축소해서** 출력합니다.
- **사용자재**: 줄마다 이름·수량·단위로 나눠 받고 「+ 자재 추가」로 줄을 늘립니다. 나중에 자재 사용내역과 연결할 예정이므로 한 줄에 글로 섞어 쓰지 않습니다.
- **종합업무일지 자동 기록**: 저장하면 작업내용이 종합업무일지의 해당 파트 **「금일작업」**에 기록됩니다. 전기·방재 체크 → 전방 파트, 기계·건축 체크 → 기건 파트, 둘 다 체크 → 양쪽. 작업 하나에 고유번호를 붙여 일지와 연결하므로 **수정하면 일지도 같이 바뀌고, 삭제하면 일지에서도 빠지며, 두 번 기록되지 않습니다.**
- **야간 일일작업 현황 항목은 없애고**, 그 자리에 사용자재 입력을 둡니다(종합업무일지 쪽 야간 일일작업 현황 칸의 제거 범위는 착수 전 확인, 7번).
- 작업 사진은 **검색되도록 색인**합니다: 일자·작업위치·작업내용·작업자 글자로 찾습니다.

### 4-2. 야간작업 탭

상단: 검색창 · 「검색하기」 · 「신규작성」.

- **검색**: 층·업체명·작업내용 글자로 찾습니다. 검색어가 비어 있으면 최근 작업을 보여 주고, 날짜 범위 필터를 하나 둡니다. 결과에는 「방염서류 없음」·「각서 없음」 표시를 합니다.
- **신규작성**을 누르면 빈 양식이 나옵니다. 순서:
  1. 현장 사진: 4열 격자 안에 **「사진찍기」** 칸과 **「여러 장 넣기」**(갤러리에서 여러 장) 칸. **개수 제한 없음**. 올릴 때 자동 축소, 올리는 중 진행 표시, 장마다 ✕.
  2. 날짜 · 업체명(**직접 입력**) · 작업위치(버튼) · 작업내용.
  3. **방염서류 / 각서**: **좌우로 나란히** 두고 가운데 **세로 구분선**(경계선 색). 둘 다 **여러 장**, 사진으로 넣습니다(사진찍기·갤러리). 예전의 「서류 제출/미제출」 체크 목록은 **없앱니다**.
  4. 기타사항.
- 서류 사진은 누르면 확대해 글자를 확인하고, 흐리거나 너무 어두우면 「다시 찍으세요」 안내를 합니다. 일반 사진보다 덜 줄여 저장합니다.
- 맨 아래: **뒤로 · 인쇄 A4 · PDF 보기 · 저장**.
- **PDF·인쇄 순서와 방식** (시안 하단 박스와 같음)
  - ① 작업 내용 + 현장 사진(여러 장이면 **축소**해서 한 쪽에 모음) + 각서 사진: **양면 인쇄용으로 붙여서** 만듭니다.
  - ② **방염서류 사진: 한 장이 A4 한 쪽 크기, 단면 인쇄용, 맨 뒤에** 붙입니다. 방염서류만 따로 단면으로 뽑을 수 있게 합니다.
  - 웹앱은 프린터에 양면/단면을 지정할 수 없습니다. 쪽 순서만 맞춰 한 PDF에 담고, 양면 구간(①)이 **짝수 쪽**이 되도록 필요하면 빈 쪽을 하나 넣어 단면 구간(②)과 섞이지 않게 합니다. 방염서류 쪽에는 「단면 인쇄」 안내를 작게 적어 둡니다(인쇄물에는 나오지 않게 처리할 수 있으면 그렇게).
  - 사진이 없는 항목은 인쇄물에 「미첨부」로 표시합니다.
- (선택, 시간이 되면) 같은 업체가 며칠 이어서 작업할 때 이전 작업을 열어 「오늘 작업 추가」로 사진·작업내용만 새로 넣는 기능.

## 5. 서류작업 → 위험작업신청서

위험작업신청서 이미지는 **한꺼번에 받지 않고 중간중간 입력**됩니다. 그래서 「신청서 추가」 버튼은 두지 않습니다.

- 위쪽: 검색창 + 「검색하기」(날짜·업체명·위치).
- **사진찍기 / 갤러리 선택**을 누르면 사진이 바로 저장됩니다. 저장할 때 **날짜 태그**(찍은 날, 기본값은 오늘)가 자동으로 붙습니다.
- 저장 시 **업체명·매장명(직접 입력, 선택)** 과 **위치(버튼, 선택)** 를 같이 받습니다. 비워 둬도 저장됩니다. 이후 저장하는 사진에 같은 값이 이어서 붙습니다.
- **보여주기**: 기존에 저장된 사진은 **일자별로 묶어 4열**로 보여 줍니다(일자 머리줄에 장수 표시). 사진 **아래에 업체명·날짜·시간**을 같이 표시합니다(시간은 저장한 시각, 업체명 없으면 「(업체 미입력)」).
- 사진을 새로 저장하면 **그날 사진의 맨 끝**에 붙습니다. 예전 사진은 순서가 바뀌지 않습니다.
- 사진을 누르면 확대(이전/다음으로 넘기기 포함). 삭제는 되묻고, 소장·관리파트만 가능하게 하는 것을 기본으로 합니다.
- 같은 사진이 두 번 저장되지 않게 합니다(연달아 같은 사진을 고르면 안내).
- 통신 불량 시 보관 후 자동 올리기(공통 5번).
- 맨 아래: **뒤로 · 인쇄 A4 · 저장**.

## 6. 점검 → 열화상점검: 기존데이터 비교

### 6-1. 화면

- 열화상점검의 **모든 탭**(점검 입력 · 리포트 · 새로 생기는 기존데이터 비교) **맨 아래에 뒤로 · 인쇄 A4 · 저장** 줄을 둡니다.
- 세부항목에 **「기존데이터 비교」** 탭을 추가합니다. **층별 → 매장별**로 나눠 보고, 이번 점검의 스팟온도를 지난 분기와 비교한 표(차단기 / 지난 / 이번 / 차이 / 상태)를 보여 줍니다.
- 지난 분기보다 기준 이상 오르면 **「점검 요망」**을 표시하고, 점검 요망은 표 맨 위에 모아 보여 줍니다. 인쇄에도 넣습니다. 지난 분기 자료가 없거나 차단기가 연결되지 않으면 「비교 불가」.
- **기준온도 설정**: 「지난 분기보다 ○℃ 이상 오르면 점검 요망」. **직원 누구나** 바꿀 수 있고, 마지막 변경자·시각을 화면에 표시하며 변경기록에 남깁니다. 처음 기본값은 5℃(사용자가 실제 기준을 알려 주면 바꿈).

### 6-2. 매장 연결 (중요)

- 기준 자료 하나에 **여러 매장이 같이** 들어 있고 분기마다 **정렬이 다를 수 있습니다.** 그래서 파일 안의 순서나 글자가 아니라 **매장ID로 연결**합니다.
- 매장은 글자로 입력하지 않고 **지도의 매장 목록(매장ID)에서 선택**합니다. (지도에서 매장을 추가·변경·삭제한 내용이 매장ID로 반영되어야 합니다.)
- 지난 분기 파일을 처음 읽을 때, 파일 안의 이름(예: 「OO매장 3F」)을 목록의 매장과 **짝지어 주는 확인 화면**을 한 번 띄웁니다. 비슷한 이름은 자동 추천하고 사람은 확인만 합니다. 짝지은 결과는 저장해서 다음 분기부터는 묻지 않습니다. 이름이 조금 달라도(띄어쓰기·층 표기) 비교되도록 이름 비교 규칙(공백·기호 제거, 층 표기 통일)을 둡니다.
- 목록에 없는 매장(철수·신규)은 「매장 미연결」로 따로 모아 두고, 소장이 나중에 목록의 매장과 짝지을 수 있게 합니다.
- 매장 이름이 바뀌어도 매장ID는 그대로이므로 지난 기록이 끊기지 않습니다.

### 6-3. 비교 기준 양식

- **권장: `.atr`(서멀스튜디오 보고서)** 를 비교 기준으로 씁니다. 스팟온도가 숫자로 들어 있어 바로 비교됩니다. PDF는 사람이 보는 인쇄·보관용으로 둡니다. (열화상 앱 `fm/thermal/app.js`가 이미 .atr을 읽고 씁니다.)
- 최종 결정은 착수 전 확인(7번)을 거쳐 확정합니다.

## 7. 착수 전 확인 항목 (코드 고치기 전에 먼저 확인하고 보고)

1. **지도의 매장ID와 열화상이 쓰는 매장 구분이 같은 번호 체계인지**. 지도에서 만든 매장ID를 열화상 비교에서 그대로 쓸 수 있는지 확인합니다. 다르면 어떻게 연결할지 사용자에게 먼저 보고합니다.
2. **지난 분기 `.atr` 파일이 보관되어 있는지**, 그 안에 차단기 이름·층·매장 정보와 스팟온도가 들어 있는지(열화상 담당 세션 또는 실제 파일로 확인). 없거나 부족하면 PDF가 필요한지 사용자에게 보고합니다.
3. **종합업무일지**에서 「금일작업」 칸의 위치(전방 파트·기건 파트)와, 「야간 일일작업 현황」을 없앨 때 기존 기록·인쇄 양식에 미치는 범위.
4. **작업위치 층 목록** B3~6F, 10F, 외곽에 7~9F가 필요한지.
5. **도면협의 코드의 `stores`·`defect`·`summary` 통로**(`apps/dw/src/Code.gs`)가 블럭 연동규칙 v2.0 삭제와 맞는지 — 이 명령서 범위 밖이므로 **고치지 말고 결과만 보고**합니다.
6. 직원 삭제의 **인증(로그인 정보) 삭제**가 Supabase 인증과 앱 PIN 표에서 각각 어떻게 지워지는지(한 번에 처리 가능한지).

## 8. 진행 순서 (권장)

1. 7번 확인 → 결과 보고.
2. **공용 부품**: 사진 확대 보기, 사진 올리기(축소·대기·재시도), 작업위치 버튼, 월별 묶음.
3. 3번(리포트 월별 묶음) — 가장 위험이 낮음.
4. 2번(직원 삭제·파트).
5. 5번(위험작업신청서).
6. 4번(주간작업 → 일지 연동 → 야간작업 → PDF 순서).
7. 6번(열화상 기존데이터 비교).
8. 한 항목이 끝날 때마다 시험·커밋. 한꺼번에 몰아서 하지 않습니다.

## 9. 시험

- 기존 시험(`apps/ws` 시험)이 모두 통과해야 합니다. 통과 개수를 보고합니다.
- 새로 확인할 것: 직원 삭제 후 PIN·인증이 같이 사라지고 기록은 남는지, 파트 바꿈이 집계에 반영되는지 / 월별 묶음(최근 달만 펼침, 요약 숫자) / 주간작업 저장 → 일지 기록·수정·삭제 연동과 중복 없음 / 작업위치가 버튼 외 값을 받지 않는지 / 사진 1장·4장·0장 인쇄 모양 / 야간작업 PDF 쪽 순서(양면 구간 → 방염서류 단면 구간) / 사진 올리기 실패 후 재시도 / 열화상 비교에서 정렬이 다른 두 파일이 같은 매장끼리 비교되는지, 점검 요망 표시·기준온도 변경 기록.
- 가능하면 실제 기기(아이패드·휴대폰)에서 사진 찍기·두 손가락 확대를 확인합니다. 못 한 것은 못 했다고 보고합니다.

## 10. 하지 않는 것

- CCTV, 배터리 히트맵(보류).
- 위험작업신청서·야간작업의 매장 연동(추후 결정).
- 도면협의 앱 코드 변경.
- 압축·주석 정리(별도 명령서).
