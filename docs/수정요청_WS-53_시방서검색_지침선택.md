# 수정 요청 WS-53: 시방서 검색 — 처음엔 지침을 모두 꺼 두고, 검색한 지침만 기억

접수: 2026-11-22 (사용자, 집 PC) · 상태: **대기 — 「진행시켜」 전에는 코드를 고치지 않음** · 문서: `WS_시방서검색.md` · 결정 번호는 WS=짝수, 90 결정표에서 마지막 번호 확인 후 이어 씀

## 지금 문제
- 메인 → 시방서 검색에 들어가면 「검색할 지침을 하나 이상 고르세요」 안내가 있는데, 실제로는 **지침이 모두 선택되어 있음**. 안내와 실제가 어긋남.
- 원인(코드): `apps/ws/parts/33_spec.js` 4째 줄 `S.sp = { …, off: {} … }` — `off`(꺼진 지침 표)가 비어 있어서 전부 켜짐. 켜고 끈 상태는 화면을 나가면 사라짐.

## 원하는 동작
1. **처음 들어가면 모든 지침이 선택 해제** 상태. 위쪽 단추·왼쪽 체크박스 모두 꺼짐, 결과 자리에는 「검색할 지침을 하나 이상 고르세요」.
2. 지침을 **하나 이상 골라 실제로 검색**을 했으면, 그때 **켜 둔 지침 목록을 이 기기(브라우저)에 저장**.
3. **다음에 시방서 검색에 들어가면 저장한 지침만 켜져** 있음.
4. 저장 목록에 없는 지침(새로 추가된 지침 포함)은 **사용자가 고를 때까지 계속 꺼진 채** 둠.

## 설계 메모 (제안, 확인 필요)
- 저장 형태: 「켜 둔 지침 id 목록」(예: 키 `ws_sp_on`) — 꺼진 목록이 아니라 **켠 목록**을 저장해야 새 지침이 자동으로 꺼짐. 앱 안 `store()` 도우미 사용(실패해도 앱은 그대로).
- 불러오기: 지침 목록을 받은 직후(`S.sp.boot`가 켜질 때), 모든 지침 id를 `off=true`로 두고 저장 목록에 든 것만 `off` 해제.
- 저장 시점: 검색어가 있고 켠 지침이 1개 이상인 상태로 **검색이 실제로 돈 순간**(`spGo`/`spDraw` 경로). 체크만 만지고 검색 없이 나간 경우는 저장하지 않음 (사용자 말 그대로).
- 건드리지 않는 것: 「이전 판 포함」(`S.sp.old`), 검색 결과·미리보기 동작.
- 외부 공개용 `fm/ws/spec.html`(`window.WS_PUB`)도 같은 코드라 같이 바뀜. 기기별 저장이라 서로 영향 없음.
- 시험: `apps/ws/test/sb_spec_test.js` 가 「처음부터 전부 켜짐」을 전제하면 고쳐야 함. 새 시험: 첫 화면 전부 꺼짐 / 고르고 검색 → 다시 들어가면 같은 것만 켜짐 / 새 지침은 꺼짐 / 저장소를 못 써도 오류 없음.
- 작업 위치: `apps/ws/parts/33_spec.js` 만 (분리 완료 상태). `src/Index.html`은 `npm run build:index`로 다시 만듦.

## 사용자에게 확인할 것 (시작 전)
1. 저장 시점이 「검색을 실제로 돌린 때」 하나로 괜찮은지 (체크만 바꿔도 저장할 수도 있음)
2. 저장 단위: 이 기기(브라우저) 하나. 같은 폰을 여러 직원이 쓰면 같은 선택을 공유함. 직원별로 나눌지(보통은 불필요)
3. 「이전 판 포함」 상태도 같이 기억할지 (기본: 기억하지 않음)

## 진행 순서 (진행시켜 이후)
