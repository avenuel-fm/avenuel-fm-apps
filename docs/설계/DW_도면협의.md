#### 15.2.1 종합방재실 협의서 · 소방 점검 예정일 제안 (v1.8.2 · 확정 2026-11-04)
**1. 화면**
- 검토서 1번 기본 정보의 **소방 점검 예정일 날짜 칸 바로 오른쪽**에 버튼을 둡니다. 휴대폰에서는 날짜 칸 아래로 내려갑니다.
  - 올리기 전: 파란 점선 **[📷 종합방재실 협의서 입력]**
  - 누르면 **[카메라로 찍기] / [사진 파일 고르기]** 창 (카메라는 `capture=environment`)
  - 올린 뒤: 녹색 **[📄 종합방재실 협의서 확인하기]**, 아래에 `올린 일시 · 올린 사람 올림 · 다시 올리기 · 지우기`
  - 확인하기 → **A4 세로 비율 팝업**(높이 화면의 94%, 폭 = 높이 × 0.68), 사진 아래 **[↺ 왼쪽으로 돌리기] [↻ 오른쪽으로 돌리기]**. 돌린 사진도 칸 안에 맞춰 줄임. Esc·바깥 누르기·✕로 닫음
- 테넌트명이 없으면 올리지 않고 안내합니다. 저장 안 된 새 검토서는 먼저 저장한 뒤 올립니다.
- 컨펌완료로 잠긴 검토서에서도 올리기·보기·돌리기·지우기를 할 수 있습니다 (협의서가 늦게 오는 경우).

**2. 규칙 (결정 26~29)**
| 항목 | 규칙 |
|---|---|
| 개수 | **매장마다 1장** (차수와 상관없이 같은 협의서). 여러 장은 올리지 않음. 다시 올리면 예전 파일은 휴지통 |
| 화질 | 문서 사진이라 **긴 변 2400px, JPEG 85%** (03 문서 9.1 예외) |
| 돌린 방향 | 0/90/180/270을 저장해 다음에 열 때·다른 기기에서도 그 방향으로 보임. 다시 올리면 0으로 |
| 저장 | 드라이브 `도면협의_사진/{문서번호}/YYYY-MM-DD_방재실협의서-{테넌트명}_001.jpg` (날짜 = 올린 날). 파일 설명에 `종합방재실 협의서 · 테넌트명 · 문서번호` |
| 시트 | `매장` 탭 맨 오른쪽 열 `방재실협의서` = `{"f":파일ID,"at":올린 일시,"by":올린 사람,"r":방향,"name":파일 이름}` |
| 기록 | 올림 / 다시 올림 / 지움은 `변경기록` |
| 지우기 | 확인창 → 파일 휴지통, 칸 비움 |

**3. 대시보드**
- 매장 이름 아래 녹색 **「방재실 협의 ✓」** (올린 매장)
- 할 일 **「방재실 협의서 미첨부 n」**(주황): 소방 점검 예정일이 **7일 안이거나 지났고**, 오픈이 아직 안 지났고, 협의서가 없는 매장. 누르면 그 매장만 걸러 봄
- `?api=summary`에 `counts.fireDocMissing` / `labels.fireDocMissing = '방재실 협의서 미첨부'`

**4. 소방 점검 예정일 제안 (결정 30)**
- 소방 점검 예정일이 비어 있고 공사 종료일이 있으면 **「💡 공사 종료일 · YYYY-MM-DD · 눌러서 넣기」**를 보여 줍니다(예전: 오픈 2일 전).
- 누르면 공사 종료일이 그대로 들어가고, 그 뒤에도 날짜 칸에서 언제든 고칠 수 있습니다. 저절로 채우지는 않습니다.

**5. 서버 함수**
| 함수 | 권한 | 하는 일 |
|---|---|---|
| `apiFireDocUpload(a, storeId, dataUrl)` | 로그인 | 저장·이름·예전 파일 휴지통·매장 칸·변경기록 → 매장 정보 |
| `apiFireDoc(a, storeId)` | 로그인 | 그 매장 협의서 `{url, r, f}` |
| `apiFireDocRotate(a, storeId, r)` | 로그인 | 방향 저장 (0/90/180/270만) |
| `apiFireDocDelete(a, storeId)` | 로그인 | 휴지통 + 칸 비움 |
- v1.9(공통 DB)로 옮길 때: 협의서도 `사진색인`(업무구분 `도면`)과 매장 이력에 넣습니다.

#### 15.2.2 계정 옮기기 · 폴더 ID로 찾기 (v1.8.3 · 확정 2026-11-04, 결정 33)
1. **왜**: DW를 업무지원(WS) 앱 계정으로 옮겨 한 계정에서 운영합니다 (결정 33). 두 계정 모두 개인 Gmail이라 **소유권 이전**(요청 → 수락)을 씁니다. 복사하면 파일 ID가 바뀌어 예전 사진·협의서·보낸 메일 링크가 끊기므로 쓰지 않습니다.
2. **넘기는 것**: 시트(Apps Script·스크립트 속성 포함) + 폴더 4개 `도면협의_사진` `도면협의_출력` `도면협의_지침` `도면협의_백업`과 그 안 모든 폴더·파일. 휴지통·다른 계정 소유는 건너뜀.
3. **시트 메뉴 ⑦ 계정 옮기기**
   | 메뉴 | 누가 | 하는 일 |
   |---|---|---|
   | 1. 소유권 넘기기 요청 | 기존 계정 | 받을 이메일 입력 → `_계정이전` 탭에 목록(폴더를 펼치며 추가) → 항목마다 편집자 공유(알림 메일 없음) + 이전 요청(`pendingOwner`). **시트는 맨 마지막** |
   | 2. 소유권 받기 | 새 계정 | `_계정이전`의 「요청함」을 하나씩 수락(`role=owner, transferOwnership`). 시트는 맨 마지막. 기존 계정 요청이 끝나기 전·다른 계정으로 누르면 안내만 |
   | 3. 이전 점검 | 아무 계정 | `매장`·`검토서`·`삭제보관`에 적힌 드라이브 ID(사진 `"f"`, 링크 `/d/`, `?id=`, `"fileId"`) + 폴더 4개 + 시트 → `_이전점검` 탭에 「이 계정 소유 / 다른 계정 소유 / 휴지통 / 찾을 수 없음」. 자동 백업 예약·시방서 보내는 주소도 함께 표시 |
   | 이어하기 예약 멈추기 | — | 1·2번의 1분 뒤 이어하기 예약을 지움 |
   - 한 번에 4분 30초까지 하고 남으면 1분 뒤 이어서(시간 트리거, 6분 제한 대비). 다시 누르면 「오류」만 다시 시도.
   - 소유권 이전은 DriveApp에 없어 **Drive API v3**를 `UrlFetchApp` + `ScriptApp.getOAuthToken()`로 부름 (고급 서비스 켜기 불필요, 새 권한: 외부 서비스 연결·이메일 주소 보기).
4. **폴더 ID로 찾기**: `appFolder_(종류)` — 스크립트 속성 `FOLDER_PHOTO` `FOLDER_PDF` `FOLDER_BACKUP` `GUIDE_FOLDER`에 ID 기억 → 없거나 휴지통이면 이름으로 한 번 찾되 **이 계정 소유 폴더 먼저**, 그래도 없으면 만듦. 그래서 폴더를 `시설팀 통합업무/10_도면협의/`로 옮겨도 동작합니다 (결정 10, WS-8).
5. **옮긴 뒤 새 계정이 할 일** (설치가이드 「6. 계정 옮기기」): 새 배포(새 `/exec`) → 자동 백업 다시 켜기 → Gmail 「다른 주소에서 메일 보내기」에 시방서 주소 등록 → 껍데기 주소 교체(TinyURL·QR 그대로) → 기존 배포 보관처리.
6. **영향**: DW·WS가 같은 계정으로 실행되어 메일 하루 한도(13.2)를 함께 씀. 블럭 연결 키·PIN·문서번호·매장 ID는 그대로.
