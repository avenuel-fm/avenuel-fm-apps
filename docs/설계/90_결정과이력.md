## 19. 검증 결과

### 19.1 문서끼리 맞추기
| 점검 | 결과 |
|---|---|
| 공통 규격 v1.0, 통합 v0.4, WS v0.3 사이에 서로 다른 값 | 13건을 찾아 부록 A로 하나씩 정함 |
| 실제 DW 코드와 맞는지 (`Code.gs` v1.8) | 매장 ID는 UUID, 문서번호는 `에비뉴엘컨펌_###_YYMMDD`, DW 상태는 협의중/컨펌완료. 이 문서에 그대로 반영. 공통 규격 예시 값이 틀렸던 것을 바로잡음 |
| 실제 DW 색상 변수와 WS 변수 | `--line` 이름이 서로 다른 색을 뜻함 → 기준 이름과 별칭으로 정리 (12장) |
| 장 사이 서로 가리키기 | 4·5·6·8·10·11·17장이 같은 이름과 값을 씀 |

### 19.2 실제로 될지 (Apps Script 동작 기준)
| 점검 | 결과 |
|---|---|
| 앱끼리 잠금 | 통하지 않음 → W1~W4 규칙과 사진 ID 앱 코드로 대응 |
| 앱끼리 기기 저장소 공유 | 앱마다 주소(출처)가 달라 공유 불가 → 앱마다 기기 표, 입장표로 연결 |
| 주소창에서 입장표 지우기 | `history.replaceState`로는 안 됨 → `google.script.history.replace` |
| 비공개 드라이브 썸네일 주소 | 구글 로그인이 없으면 안 보임 → 묶어서 받기 |
| 응답 뒤 백그라운드 작업 | 없음 → 화면 재호출 + 예약 재시도 |
| 계정 한도 | 13.2 표로 예산을 정함. 메일 100명/일, 예약 작업 90분/일이 가장 빠듯함 |
| 캐시 | 앱마다 따로, 한 키 100KB → 월별 분할 + 최근 달 2분 |
| 스크립트 속성 9KB | 폴더 ID 묶음은 시트 `설정`에 둠 |

## 20. 예상 문제점과 대책

|---|---|---|---|
| 1 | 두 앱이 동시에 색인을 써서 한 줄이 덮어써짐 | 높음 (사진 올리기가 몰리는 시간) | `Values.append`·`appendRow`만, 자기 줄만 고치기 (3.2). 공통 틀 시험에 동시 쓰기 포함 (18장 1단계) |

| 3 | 새해 첫날 두 앱이 동시에 `색인_2027` 탭을 만들려다 오류 | 낮음 (생기면 큼) | HUB가 12월에 미리 만듦, 앱은 만들지 않음 (W4) |

| 10 | 공통 DB가 열리지 않으면 모든 앱 로그인 실패 | 낮음 | 직원 목록 캐시로 10분 유지, 색인은 `색인대기`에 (8.1, R6) |
| 11 | 사진색인이 커져 검색이 느려짐 (1년 수만 줄) | 중간 | 문서 먼저 검색, 필요한 열만 캐시, 연도 탭 (10.2, 10.3) |
