## 19. 검증 결과

### 19.1 문서끼리 맞추기
| 점검 | 결과 |
|---|---|
| 공통 규격 v1.0, 통합 v0.4, WS v0.3 사이에 서로 다른 값 | 13건을 찾아 부록 A로 하나씩 정함 |
| 실제 DW 코드와 맞는지 (`Code.gs` v1.8) | 매장 ID는 UUID, 문서번호는 `에비뉴엘컨펌_###_YYMMDD`, DW 상태는 협의중/컨펌완료. 이 문서에 그대로 반영. 공통 규격 예시 값이 틀렸던 것을 바로잡음 |
| 실제 DW 색상 변수와 WS 변수 | `--line` 이름이 서로 다른 색을 뜻함 → 기준 이름과 별칭으로 정리 (12장) |
| 장 사이 서로 가리키기 | 4·5·6·8·10·11·17장이 같은 이름과 값을 씀 |

### 19.2 실제로 될지 (Apps Script 동작 기준)
| 점검 | 결과 |
|---|---|
| 앱끼리 잠금 | 통하지 않음 → W1~W4 규칙과 사진 ID 앱 코드로 대응 |
| 앱끼리 기기 저장소 공유 | 앱마다 주소(출처)가 달라 공유 불가 → 앱마다 기기 표, 입장표로 연결 |
| 주소창에서 입장표 지우기 | `history.replaceState`로는 안 됨 → `google.script.history.replace` |
| 비공개 드라이브 썸네일 주소 | 구글 로그인이 없으면 안 보임 → 묶어서 받기 |
| 응답 뒤 백그라운드 작업 | 없음 → 화면 재호출 + 예약 재시도 |
| 계정 한도 | 13.2 표로 예산을 정함. 메일 100명/일, 예약 작업 90분/일이 가장 빠듯함 |
| 캐시 | 앱마다 따로, 한 키 100KB → 월별 분할 + 최근 달 2분 |
| 스크립트 속성 9KB | 폴더 ID 묶음은 시트 `설정`에 둠 |

## 20. 예상 문제점과 대책
| # | 문제 | 가능성 | 대책 (반영 위치) |
|---|---|---|---|
| 1 | 두 앱이 동시에 색인을 써서 한 줄이 덮어써짐 | 높음 (사진 올리기가 몰리는 시간) | `Values.append`·`appendRow`만, 자기 줄만 고치기 (3.2). 공통 틀 시험에 동시 쓰기 포함 (18장 1단계) |
| 2 | 사람이 공통 DB를 정렬하거나 줄을 지워 ID와 줄이 어긋남 | 중간 | 공유 탭 시트 보호, 필터 보기만, 매일 백업 (3.2 W3) |
| 3 | 새해 첫날 두 앱이 동시에 `색인_2027` 탭을 만들려다 오류 | 낮음 (생기면 큼) | HUB가 12월에 미리 만듦, 앱은 만들지 않음 (W4) |
| 4 | 다른 앱이 방금 쓴 문서가 검색에 2분 늦게 나옴 | 확실 | 이번 달·지난달 캐시 2분. 자기 앱이 쓴 것은 바로 보임 (10.3) |
| 5 | 메일 하루 100명을 넘겨 발송 실패 (공사가 몰리는 시기) | 중간 | 남은 수 표시, 80명부터 경고, 실패는 오류기록 (13.2) |
| 6 | 예약 작업이 하루 90분을 넘겨 PDF 재시도·백업이 멈춤 | 낮음 | 10분 간격, 건이 없으면 바로 끝, 백업 하루 1번 (11.2, 13.2) |
| 7 | 아이폰 Safari가 오래 쓰지 않은 사이트의 기기 저장소를 지워 다시 PIN 입력 (7일 안팎) | 중간 | PIN 다시 입력은 정상 동작으로 안내. 작성 중 내용은 서버 임시 저장으로 남음 (9.4) |
| 8 | 전화번호 PIN을 동료가 알아 남의 이름으로 로그인·결재 | 중간 | 결재 알림(「OO님이 확인했습니다」) + 변경이력 추적 + 관리자 PIN 다시 넣기로 모든 기기 로그아웃 (7.5) |
| 9 | 공통 틀 복사본이 앱마다 달라져 검색키·디자인이 어긋남 | 높음 (앱이 늘수록) | 공통 틀 버전 표시 + HUB 노란 표시 (17.2) |
| 10 | 공통 DB가 열리지 않으면 모든 앱 로그인 실패 | 낮음 | 직원 목록 캐시로 10분 유지, 색인은 `색인대기`에 (8.1, R6) |
| 11 | 사진색인이 커져 검색이 느려짐 (1년 수만 줄) | 중간 | 문서 먼저 검색, 필요한 열만 캐시, 연도 탭 (10.2, 10.3) |
| 12 | `HUB_KEY`가 새면 누구나 입장표를 만들 수 있음 | 낮음 | 속성에만 보관, 교체 절차 (8.4). 교체하면 전원 다시 로그인 |
| 13 | 기능 문서가 늘면서 공통 문서와 어긋남 | 중간 | 기능 문서는 공통 규칙을 **장 번호로 가리키기만** 하고 값을 다시 정하지 않음. 공통 요소를 바꿀 때는 17장 절차, 00 목차에 버전 한 곳 |
| 14 | DW 문서번호에 `_`가 있어 다른 이름 규칙과 섞일 수 있음 | 낮음 | 문서번호는 파일 이름에 쓰지 않고, 폴더 이름(`도면협의_출력/{문서번호}`)에만 씀 |
| 15 | 사진 다시 올리기에서 번호가 겹치거나 빠짐 | 중간 | 같은 번호 재사용 + 예전 파일 휴지통 + 색인 삭제 표시 (5.1) |
| 16 | 서버 임시 저장(30초마다)으로 호출이 늘어 동시 실행 30개 한도에 가까워짐 | 낮음 | 바뀐 내용이 있을 때만 보냄. 사진 올리기 중에는 건너뜀. 동시 접속 10명 기준 1분에 최대 20번 (13.2) |

| 21 | 롯데쇼핑 그룹을 고르면 받는 사람이 많아져 메일 하루 100명 한도가 빨리 참 | 중간 | 발송 전 "n명에게 보냅니다" 표시, 80명부터 경고 (13.2). 그룹 인원은 관리 화면에서 정리 |
| 22 | 주소록에 같은 사람이 이메일만 달리 여러 번 저장됨 | 낮음 | 이메일 기준으로 하나만 저장. 관리 화면에서 합치기 |
