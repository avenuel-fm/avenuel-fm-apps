> **요약**
> - 서류작업 아래 새 메뉴. 직원이 **손으로 쓴 위험작업신청서를 사진으로 찍는 대로 바로 저장**하고, 날짜별로 모아 보고, 검색하고, A4로 인쇄한다. 앱 안에서 항목을 입력하는 양식은 **아님**.
> - 저장할 때 **날짜 태그**(기본 오늘) + **업체명·매장명**(직접 입력, 선택) + **위치**(버튼 B3~6F·10F·외곽, 선택). 비워 둬도 저장되고, 다음 사진에 같은 값이 이어서 붙는다.
> - 사진은 글자가 읽히게 **2400px·85%**(일반 현장 사진 1600px·70%보다 덜 줄임). 같은 사진 두 번 저장 방지, 통신 불량이면 「올리기 대기 중 N장」 → 연결되면 자동 재전송.
> - 보기·올리기 = 전 직원, **지우기 = 소장·관리자**(숨김 처리). 메뉴 켜기·끄기 키 `docs.risk`(결정 148·210).
> - 남은 것: 앱을 닫으면 대기 중 사진은 사라짐(기기 보관은 `WS_오프라인저장.md` 부품이 생기면), 두 손가락 확대(지금은 −/＋ 버튼).

#### 15.3.26 위험작업신청서

**1. 화면 흐름** (`apps/ws/parts/62_risk.js`, 보기 이름 `rw`) — 시안 `docs/시안/WS-명령서_화면수정/시안.html` 5장
1. 서류작업 › [위험작업신청서] 줄. 위쪽 검색창 + [검색하기] (날짜·업체명·위치 글자, 예: `2026-11-24`, `11-24`, `OO`, `3F`).
2. [사진찍기](카메라 바로 찍기) · [갤러리에서 선택](여러 장) → 고르면 **바로 저장**. 날짜 태그 칸(기본 오늘, 갤러리의 옛 사진은 날짜를 바꿔 저장).
3. 업체명·매장명 입력칸, 위치 버튼(다시 누르면 해제). 이후 저장하는 사진에 같은 값이 붙음.
4. 결과: **일자별 접기 목록**(머리줄에 `N장`, 가장 최근 날만 펼침), 펼치면 **4열**. 사진 칸은 가로 4:3·자르지 않고 줄여 넣기·남는 곳 연회색(03 9장). 사진 아래 `업체명 · 위치`, `MM/DD HH:MM`(업체명 없으면 「(업체 미입력)」). 새 사진은 그날 맨 끝.
5. 사진을 누르면 전체 화면 보기: 이전·다음, −/＋(100~400%, 스크롤로 이동), 닫기.
6. 소장·관리자에게만 사진 모서리 ✕ → 되묻기 → 지움.
7. 맨 아래 줄: [뒤로] [인쇄 A4]. 사진은 올리는 즉시 저장이라 [저장] 버튼은 없음(대기 중 사진은 [지금 올리기]).
8. 인쇄 A4 = 세로, 지금 보이는 목록(검색 결과)을 일자별로 한 줄 4장.

**2. 저장 규칙**
| 항목 | 규칙 |
|---|---|
| 업로드 | 화면이 `ws-files` 버킷 `risk_photo/YYYY-MM/{무작위}.jpg` 에 먼저 올리고 주소·경로만 DB 함수에 넘김 (`ws_add_file` 이 경로 모양 검사) |
| 드라이브 폴더(files.drive_folder) | `서류작업/위험작업신청서/YYYY/YYYY-MM` |
| 사진 이름(files.file_name) | `YYYY-MM-DD_위험작업신청서-{업체명 or 업체미입력}_###.jpg` (그날 몇 번째) |
| 번호 | `WS-RK-YYYYMMDD-###` (종류 코드 `RK`) |
| 중복 방지 | 기기가 사진마다 만든 24자리 고유 번호 `cid` — 서버가 같은 번호는 한 번만 저장(응답만 못 받고 다시 보내도 중복 없음). 화면에서도 같은 파일(이름·크기·수정시각)을 연달아 고르면 건너뜀 |
| 남용 막기 | 한 사람 하루 300장, 날짜는 오늘 −10년 ~ 내일 |
| 지운 사진 | `deleted=true` 숨김만 (파일·기록은 남음), 변경기록에 한 줄 |

**3. DB** (`apps/ws/supabase/25_risk.sql`, 15_menu.sql 다음에 Run — 15_menu.sql 도 `docs.risk` 때문에 다시 Run)
- 표 `rw_photos`: rk_id · photo_day · company · floor · file_id(→files) · cid(고유) · saved_at · saved_by · deleted. 정책 없음 = 함수로만 접근.
- 함수 3개(로그인 기기만): `ws_rw_list(token, q, from, to)` · `ws_rw_add(token, day, co, floor, file, cid)` · `ws_rw_delete(token, id)`. 검색어·범위가 없으면 최근 60일, 최대 600장. 메뉴를 끄면(`docs.risk`) 직원은 서버에서도 막힘(`ws_menu_guard`).
- 화면 통로 `fm/ws/ws-api.js`: `rwList` · `rwAdd`(사진을 다시 줄이지 않고 올림) · `rwDelete`.
- 구글 판(`Code.gs`)에는 이 기능이 **없음** (공조기 가동·CAD처럼 Supabase 판 전용). `Code.gs` 는 메뉴 키 `docs.risk` 만 추가.

**4. 메뉴 켜기·끄기**: `MENU_KEYS_`(Code.gs) · `15_menu.sql`(3곳) · 화면 `MENU`(`34_menu_settings.js`)에 `docs.risk` 추가. 환경설정 › 서류작업 아코디언에 「위험작업신청서」 켜짐/꺼짐.

**6. 남은 것 / 확인 필요**
- 대기 중 사진은 **앱 메모리**에만 있음(`shortcut:` 주석) — 앱을 닫거나 새로고침하면 사라짐. 오프라인 임시 저장 부품(`WS_오프라인저장.md`)에 `rw` 종류를 끼우면 해결.
- 두 손가락 확대는 브라우저 기본 동작에 맡김(−/＋ 버튼은 있음). 흐린 사진 「다시 찍으세요」 안내는 만들지 않음(명령서 4-2 야간작업 쪽 설명이라 이 메뉴 범위 밖으로 봄).
- 작업위치 층 목록에 7~9F 는 없음(명령서 7장 4번, 필요하다고 하면 `RW_FLOORS`·`ws_rw_floors` 두 곳에 추가).
