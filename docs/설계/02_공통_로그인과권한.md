# 공통 · 로그인과 권한

- 판: **v1.16** · 수정 2026-11-10 · 공통 규격 v1.17
- 담은 장: 7 로그인 · 권한
- **이럴 때 읽기**: 로그인, PIN, 기기 표, 입장표, 역할별 권한을 다룰 때
- 목차·읽는 법: `docs/설계/00_목차_읽는법.md`

> **요약**
> - PIN = 휴대폰 뒷 4자리(겹치면 앞 4자리), 직원은 바꿀 수 없음, 관리자가 미리 입력
> - 기기 표는 **다음 오전 6시(한국 시간, 근무일 시작)까지** `staff_id.만료.HMAC`, 입장표 5분 `?t=` 한 번만 (결정 48 → 결정 60)
> - 기기 표는 앱 칸 저장소 + 바로가기 페이지 저장소 두 곳에 보관 (결정 50)
> - 5번 틀리면 5분 잠금 + 기기와 상관없이 많이 틀리면 10분 전체 잠금(결정 74·39), 결재 때 PIN 다시 묻지 않음(대신 알림 + 변경이력)
> - 권한은 서버 함수(`requireRole_`)가 확인. 직원·파트장은 DW가 안 보임

## 7. 로그인 · 권한

### 7.1 PIN (확정 2026-11-03) + 매일 첫 로그인 서명 (결정 56, 11-05)
- 직원은 **본인의 개인 PIN**으로 로그인합니다.
- **근무일의 첫 로그인 때 PIN 다음에 본인 서명**(가로 칸, 이름이 연회색으로 깔림)을 받습니다. **서명하지 않으면 로그인되지 않습니다**(건너뛰기 없음). 근무일은 **오전 6시 시작**(출근은 8시까지지만 일찍 오는 직원이 있음, 로그인 유지 경계와 같음, 결정 60). 그날 이미 서명했으면 다시 묻지 않습니다. 입장표로 들어와도 같습니다. 이 서명은 TBM 서명란에 로그인 순서대로 들어갑니다(`WS_서류작업.md`). HUB도 직원 로그인을 만들 때 같은 규칙입니다. DW는 소장·부소장 PIN 방식 그대로(결정 36).
- **출근현황으로 나누기 (WS, 결정 92, 11-10)**: PIN을 넣으면 그 직원의 그날(근무일) 출근현황 상태를 봅니다(`WS_출근현황.md`, 이름으로 맞춤).
  - 주간 출근(빈칸·9-7·P반·P검진) = 지금처럼 **PIN + 서명** → TBM 서명란
  - 야·A반·A검진·연·법·병가 = **서명 없이 PIN만** (TBM 서명란에 안 들어감)
  - 휴·비 = **「휴일 접속 불가」** 안내, 로그인 안 됨. 그날 휴무로 바뀌면 이미 받은 기기 표도 막힘(다시 PIN → 안내)
  - 전날 야간 근무자는 다음 날 **오전 9시까지** PIN만(퇴근 8시 30분). **소장·부소장·총무**는 막지 않고 주간 출근일만 서명, 쉬는 날은 PIN만
  - 그 달 근무표가 없거나 이름이 없으면 예전처럼 PIN + 서명. 판단은 1분 기억, 출근현황을 고치면 바로 새로
- **PIN = 본인 휴대폰 번호 뒷 4자리**입니다. 다른 직원과 겹치면 그중 한 사람은 **앞 4자리**(010 다음 4자리)를 씁니다.
- **직원은 PIN을 직접 바꿀 수 없습니다.** 첫 로그인 때 PIN을 바꾸는 단계도 없습니다.
  - PIN은 관리자가 미리 넣고, 바꿀 때도 관리자가 합니다 (7.5).
- 저장은 `SHA-256(salt + PIN)`이고, salt는 사람마다 다릅니다.
- **로그인 방식**: PIN만 넣으면 직원 18명의 해시와 차례로 비교해 그 사람을 찾습니다.
  - 그래서 **두 사람이 같은 PIN을 가질 수 없습니다.** 저장할 때 막습니다.
- **틀린 횟수 제한**: 같은 기기에서 5번 틀리면 5분 동안 잠급니다.
  - **전체 잠금** (11-06 점검 1·2): 기기 번호는 화면이 보내는 값이라 바꿔 가며 끝없이 시도할 수 있습니다. 그래서 **기기와 상관없이** 10분 안에 많이 틀리면 10분 동안 PIN 로그인을 모두 막습니다. WS = 30번(결정 74), DW = 20번(결정 39, 기기에 기억된 로그인은 막지 않음). 잠금 뒤 6시간 안에 **3번째 잠금부터는 1시간** 막습니다(결정 80·41, 풀릴 때마다 다시 시도하는 것을 늦춤). 잠금은 `변경기록`에 「보안」으로 남습니다.
  - 남이 일부러 틀려 직원 로그인을 10분 막을 수는 있습니다(막는 동안 이미 로그인한 기기는 그대로).
- **결재와 소장 확인 때 PIN을 다시 묻지 않습니다** (결정 1-2). 대신 7.5의 대책을 씁니다.

### 7.2 기기 표 (다음 오전 6시까지, 결정 48 → 60)
- **만료 = 로그인한 뒤 처음 오는 오전 6시(한국 시간) = 다음 근무일 시작.** 오전 6시 전에 로그인하면 그날 6시, 6시 이후면 다음 날 6시까지입니다. 5~6시 사이 로그인도 예외 없이 그날 6시까지입니다. (11-04에 오전 8시로 정했다가 11-05 근무일 시작을 6시로 바꾸며 같이 옮김, 결정 60. 예전에는 30일이었습니다.)
  - 근무일과 경계가 같아서, 한 근무일 안에서는 PIN·서명을 한 번만 합니다. 8시 경계였을 때 만든 표(만료가 다음 6시보다 늦은 표)는 받지 않아 한 번 다시 로그인합니다.
  - 만료 시각은 서버가 정해 표 안에 넣습니다(`makeToken_`). 기기 시계와 상관없습니다.
- 형식: `staff_id.만료시각.서명`
  - 서명은 `HMAC-SHA256(HUB_KEY, staff_id|만료시각|pin_hash 앞 8자)`입니다.
- **서버에 따로 저장하지 않고 어느 앱에서든 확인할 수 있습니다.**
  - PIN을 바꾸면 이전 표는 자동으로 무효가 됩니다.
  - `사용여부=N`이면 직원 캐시가 바뀌는 10분 안에 모든 앱에서 막힙니다.
- 기기 저장 위치는 각 앱의 localStorage입니다.
  - GAS 웹앱은 앱마다 화면 주소(출처)가 달라서 **기기 저장소를 앱끼리 나눠 쓸 수 없습니다.**
  - 그래서 앱마다 기기 표를 따로 받습니다. 이것이 입장표가 필요한 이유입니다.
- **바로가기 페이지에도 함께 보관 (결정 50)**: 앱은 구글 칸(다른 사이트 안의 iframe) 안에서 돌아서, 아이폰 사파리·삼성 인터넷 등은 그 저장소를 막거나 지울 수 있습니다. 그래서 로그인·로그아웃 때 앱이 바로가기 페이지(`fm/{앱}/`, GitHub)에 `postMessage`로 표를 넘겨 그쪽 localStorage(`fm_{앱}_token`)에도 둡니다.
  - 앱이 켜질 때 자기 저장소에 표가 없으면 바로가기 페이지에 물어 받습니다(0.8초 안에 답이 없으면 건너뜀).
  - 바로가기 페이지는 **`*.googleusercontent.com`에서 온 요청에만** 답하고, 만료가 지난 표는 지웁니다.
  - `/exec`를 바로 연 경우에는 바로가기 페이지가 없으므로 앱 저장소만 씁니다.
- **켜질 때 순서 (결정 48·76)**: 저장된 표가 있으면 PIN 화면 대신 「불러오는 중」을 보이고 서버 확인(`bootstrap`)을 기다립니다. **WS는 이 기기에 기억한 지난번 메인 화면(`ws_main`, 같은 직원 표일 때만)을 먼저 보여 주고 서버 확인은 뒤에서** 합니다(결정 76). 기억한 화면이 있을 때 연결 오류면 「다시 시도」 대신 알림만, 로그아웃하면 지움. 표가 틀리면(`LOGIN`) PIN 화면, 연결 오류면 「다시 시도」 화면을 보입니다. 늦게 끝난 확인은 이미 다른 화면으로 넘어갔으면 화면을 바꾸지 않습니다.

### 7.3 입장표 (`?t=`, 5분)
- 형식: `staff_id.역할.만료시각.nonce.서명`
  - 서명은 `HMAC-SHA256(HUB_KEY, 앞부분)`입니다.
- **누가 만드나**
  - HUB 카드에서 이동할 때: HUB가 만듭니다.
  - 앱 위 막대 「앱 전환」으로 이동할 때: **지금 있는 앱이 만듭니다.** 모든 앱이 `HUB_KEY`를 갖고 있으므로 HUB를 거치지 않습니다.
- **받는 앱이 하는 일**
  1. `doGet(e)`에서 `e.parameter.t`를 확인합니다.
  2. 서명과 만료를 확인하고, nonce가 이미 쓰인 것인지 캐시(5분)에서 봅니다. 한 번 쓴 입장표는 다시 쓸 수 없습니다.
  3. 기기 표를 발급합니다.
  4. **`google.script.history.replace()`로 주소에서 `t`를 지웁니다.**
     - 공통 규격의 `history.replaceState`는 앱 안쪽 틀의 주소만 바꿉니다. 사용자가 보는 주소창은 그대로 남습니다.
- 이동할 때 열 화면도 함께 넘깁니다: `&view=…&id=…`. 예: 매장 이력에서 WS 하자점검의 그 매장으로 바로 이동.

- 권한은 **서버 함수가 확인합니다.** 화면에서 버튼을 숨기는 것은 편의일 뿐입니다.
- 모든 서버 함수는 먼저 `requireRole_(token, [역할…])`를 부릅니다.
- 볼 수 없는 앱은 앱 전환 메뉴, HUB 할 일, 통합 검색 결과에서 모두 빠집니다. 그 앱의 서버도 입장표의 역할로 다시 막습니다.
- **HUB 카드는 예외로 빼지 않고 회색 비활성으로 보여 줍니다** (결정 32). 앱 이름만 보이고 숫자·할 일은 비우며, 눌러도 열리지 않습니다. 지금은 DW 카드가 소장·부소장 외 모두에게 이렇게 보입니다.
- **DW는 소장·부소장만 쓰는 단독 앱**입니다 (결정 32). 직원에게 DW 주소를 알리지 않고, 다른 앱과는 데이터(공통 DB 색인, `summary`)만 주고받습니다.

### 7.5 직원 · PIN 관리 (확정 2026-11-03)
- 관리 화면은 **HUB가 소유**합니다. 데이터 주인도 HUB입니다 (R1).
- **관리자와 소장**이 할 수 있는 일
  - 기존 직원의 이름과 PIN을 **미리 입력**해 둡니다. 직원은 첫날부터 본인 PIN으로 바로 로그인합니다.
  - 직원을 **추가**하고 **삭제**합니다.
    - 삭제는 줄을 지우지 않고 `사용여부=N`으로 합니다 (W3). 화면에는 "삭제"로 보이고 목록에서 사라집니다.
    - 그 직원이 쓴 문서의 작성자 이름은 그대로 남습니다.
  - PIN을 잘못 넣었거나 번호가 바뀌면 PIN을 다시 넣습니다. 그 직원의 기기 표는 자동으로 무효가 되어 새 PIN으로 다시 로그인합니다 (7.2).
- 다른 앱에서도 바로 엽니다: WS PC 화면의 **관리자 버튼** → 입장표 `&view=staff` → HUB 직원 관리 화면. 저장은 HUB가 합니다.
- 입력할 항목(이름, 파트, 역할, 근무조, 이메일, 직인 등)은 사용자가 나중에 알려 줍니다 (WS-3).
- **남는 위험과 대책**: 휴대폰 뒷자리는 동료가 알 수 있어 남의 이름으로 로그인·결재할 위험이 있습니다. 결재 때 PIN을 다시 묻지 않으므로 아래로 대응합니다.
  - 결재되면 작성자에게 「OO님이 확인했습니다」를 표시합니다.
  - 모든 로그인·결재·수정을 변경이력에 이름·일시와 함께 남깁니다.
  - 의심 건이 있으면 관리자가 그 직원 PIN을 다시 넣습니다. 그러면 그 사람의 모든 기기에서 자동 로그아웃됩니다.
