## 1. 지금 있는 것 (안티그라비티 작업 폴더 `C:\avenuel\cad-viewer`, 읽기만 함)
- 이름 「도면 정리 도구」. **CAD 도면(DWG·DXF)을 열어** 레이어를 10개 분류로 나눠 보여 주고, 남길 레이어만 골라 나머지를 지우고, 글꼴을 **맑은 고딕**으로 바꾼 뒤 DWG·DXF로 저장. 용량 줄이기, 밝게·어둡게, 아이패드 터치 대응.
- 위치 `cad-webapp-supabase/webapp/` — 빌드 없는 정적 파일(`index.html`·`js/*.js`·`css/`). 디자인은 `design/tokens.css`(남색·흰색·모서리 2px, 업무지원과 같은 계열).
- 도면은 **브라우저 안에서만** 처리하고 서버에 올리지 않음. 예외 둘:
  1. DWG 열기용 해석기(LibreDWG, wasm)를 Supabase Storage 공개 버킷 `cad-assets`에서 받아 옴.
  2. **DWG 저장**: Edge Function `dxf-to-dwg`가 외부 변환 서비스(CloudConvert)에 맡김 — 현재 anon 키만 있으면 누구나 호출(사용량 소진 위험, 자체 인수인계 문서도 경고).
- 확인 못 한 것(자체 문서): 실제 DWG 저장, 큰 도면(도형 13만 개 이상), 실제 아이패드, 정리 옵션이 CAD에서 문제를 안 내는지.
- 자체 Supabase 주소·키(`js/config.js`)를 가짐 → 업무지원에 붙일 때는 **쓰지 않고** 업무지원 통로로 대체.

## 2. 지도(`fm/map/`, `WS_지도.md`)와의 관계
| | 지도 | CAD |
|---|---|---|
| 하는 일 | 에비뉴엘 도면을 **보고 매장·설비를 찾음** (이미 올려 둔 도면) | **도면 파일을 열어 정리·변환** (DWG·DXF → 정리된 DWG·DXF) |
| 자료 | Supabase 표·Storage | 파일 단위, 서버 저장 없음(1단계) |
| 겹치는 점 | 도면 이미지/벡터 그리기, 확대·이동 | 같음 → **그리기 부품을 공유할지는 나중 결정**. 지금은 서로 안 건드림 |
가능한 흐름: CAD에서 정리한 도면 → (사용자 확인 시) 지도용 도면으로 내보내기. 지금은 정하지 않음 (질문 3).

## 3. 연동 규격 초안 (열화상 방식 그대로)
| 항목 | 정한 것(초안) |
|---|---|
| 파일 자리 | `fm/cad/` (`index.html` + js·css + 해석기 wasm). 만들기 단계 없는 정적 파일. 지도·열화상처럼 업무지원이 **화면 안 창(iframe)**으로 엶 (`../cad/index.html`) |
| 여는 법 | 메인 「CAD」 칸 → 화면 안 창. 주소창은 업무지원 그대로, 「뒤로」는 업무지원이 왼쪽 아래 작은 버튼으로 그림 |
| 로그인·권한 | CAD에는 로그인 없음. 업무지원 PIN 로그인 사용. 처음엔 소장·부소장·관리자·옵저버만(지금 칸과 같음), 직원 열기는 사용자 결정 |
| 자료 통로 | `window.parent.WS_CAD`만 부름(Supabase 직접 연결·자체 키 **금지**). 부모가 없으면 `fm/cad/mock_bridge.js` 가짜 통로로 단독 시험 |
| 도면 파일 자리 | **Supabase Storage `ws-files/cad/…`** (열화상·지도와 같은 버킷, 업무지원 `upload`). 구글 드라이브는 2단계(`toDrive`, 열화상 방식). 1단계는 내려받기만 |
| DWG 해석기 | wasm을 `fm/cad/`에 함께 두어 저장소에서 받음(자체 `cad-assets` 버킷 불필요). 크면(수 MB) 지연 로드 |
| DWG 저장 | 변환 서비스 호출은 **업무지원 통로 `toDwg(dxfBlob)`**로만(로그인 확인·횟수 제한은 업무지원 Supabase 함수가 맡음). 안 되는 환경이면 DXF 저장만 |
| 디자인 | 공통 디자인(결정 150), 휴대폰 390px·태블릿·PC, 가로 스크롤 없음 |

**`WS_CAD` 통로 (업무지원이 만듦, 모두 Promise)** — 이름은 초안
| 이름 | 하는 일 | 돌려주는 것 |
|---|---|---|
| `me()` | 지금 로그인한 사람 | `{ name, role }` |
| `boot()` | 처음 열 때 | `{ recent }` 최근에 연 도면 기록 |
| `upload(blob, name)` | 원본·정리본 저장(줄이지 않음) | `{ path, url }` |
| `saveRecord(r)` | 작업 기록 `{ name, src_path, out_path, kept, fmt, date }` | `{ ok, id }` |
| `toDwg(dxfBlob)` | DXF → DWG 변환 | `{ ok, blob }` 또는 `{ ok:false, error }` |
| `toDrive(path, name)` | 2단계 | `{ ok, url }` |
| `full(on)` | 화면 가득 | — |

업무지원 쪽(나중, 「진행시켜」 뒤): `Index.html`의 `go('cad')`·`window.WS_CAD`, `supabase/NN_cad.sql`(표 `cad_record`, 함수 `ws_cad_*`, 로그인 확인 변환 호출), `fm/ws/ws-api.js`, `WS_MENU_KEYS`/`MENU_KEYS_`에 `cad` 추가(켜기·끄기), 구글 웹앱에서는 안내만.

## 7. 방식 변경 (사용자 11-20): 오프라인 변환 + 온라인 뷰어
외부 변환 서비스(CloudConvert) 크레딧을 쓰지 않기 위해 둘로 나눈다.

**① PC 단독 프로그램 「CAD 변환기」 (안티그라비티가 만듦, 인터넷 없이도 변환)**
- 기존 도면 정리 도구(레이어 분류·삭제·맑은 고딕·용량 줄이기)를 PC용 단독 실행 파일(.exe)로. 웹 서버·로그인 필요 없음.
- DWG ↔ DXF 변환은 **외부 서비스 대신 PC에 설치한 변환 부품**으로: 1순위 ODA File Converter(무료, 명령줄 지원), 대안 LibreDWG(DWG→DXF). 부품은 프로그램에 끼워 넣지 않고 사용자가 설치(재배포 약관 때문). 설치 위치는 설정에서 고름.
- 결과는 **뷰어용 DXF**(필요하면 DWG도) + 작은 미리보기 정보. 「업로드」 단추로 업무지원에 올림.
**② 업무지원 「CAD」 (온라인 뷰어만)**
- 변환된 DXF만 열어 봄. DWG 해석기(wasm)·변환 호출은 온라인에서 뺌 → 가볍고 크레딧 0.
- CAD 칸 안 「변환된파일」 목록: 도면 이름·층·올린 사람·날짜·크기 → 누르면 보기. **전 직원 열람**(직원 칸도 열림).
- 한 번 연 파일은 그 기기(브라우저 저장)에 보관해 다시 빠르게 열고, 원본은 구글 드라이브 「CAD 변환파일」 폴더에 있음.
**③ 업로드 길**
- PC 프로그램 → 업무지원 업로드 주소 → 구글 드라이브 폴더 저장 + 목록 표(`cad_file`) 기록. 올리는 사람은 업무지원 PIN로 로그인(**전 직원이 올림**(PIN 로그인한 직원 누구나)). 서버 쪽 규격·함수는 「진행시켜」 뒤 업무지원이 만들고, PC 프로그램은 `uploader` 한 부품만 부르게 해 두어 서버가 없어도 가짜 서버로 시험 가능.
- 통로 `WS_CAD`는 `me() · list() · open(id) · cacheGet/Put(기기 보관)`로 축소 (`upload`·`toDwg` 온라인에서 제거).

**정함(11-20)**: 올리는 사람 = 전 직원, 변환 부품(ODA File Converter)은 변환 PC에 설치하는 방식, 메인 칸은 뷰어 완성 때 전 직원에게 열기(그 전까지 직원은 「준비중」 유지).
**남은 정할 것**: 드라이브 폴더 이름, 파일당 크기 상한, 보관 기간(전 직원 업로드라 남용 막기: 크기 상한·하루 횟수·소장 삭제), ODA 약관 확인.

## 8. 연동 구현 (11-20, 사용자 「진행시켜」, 갈래 `claude/cad-menu`, 아직 배포 안 함)
안티그라비티가 만든 것: PC 변환기 `C:venuel\cad-viewer\cad-converter\dist\CAD변환기\CAD변환기.exe`(ODA 우선·LibreDWG 대안, 일괄 변환), 온라인 뷰어 `fm/cad/`(DXF만, 목록·열기·레이어·분류색).
**바꾼 점 — 올리는 길**: PC 변환기의 「업로드」(PIN 로그인)는 업무지원 로그인(기기 등록·근무일 서명) 규칙을 PC에서 지킬 수 없어 연결하지 않았다. 대신 **업무지원 CAD 화면의 「도면 올리기」**로 올린다(이미 로그인된 직원, 전 직원). 흐름: PC 변환기에서 DXF 저장 → 폰·PC 업무지원 CAD › 「도면 올리기」에서 파일 고름. (PC 변환기의 업로드 단추는 가짜 서버라 쓰지 않음 — 뒤에 정리)
- `fm/cad/`: 뷰어 + 「도면 올리기」 창(.dxf만, 이름·층·메모, 50MB 이하), `tokens.css` 같은 폴더에 복사(바로가기 페이지에 `apps/`가 없어 상대 경로가 안 맞았음), `mock_bridge.js`에 `upload` 더함.
- `apps/ws/supabase/18_cad.sql`(SQL Editor에서 Run): 표 `cad_file`(함수로만), `ws_cad_list`·`ws_cad_save`·`ws_cad_delete`. 전 직원 보기·올리기, 지우기 소장만. 파일 경로 `cad/YYYY-MM/<32자>.dxf`만, 50MB 이하, 한 사람 하루 30개, 같은 이름은 새 파일로 바꿈(한 줄).
- `fm/ws/ws-api.js`: `cadList`·`cadSave`·`cadDelete`.
- `Index.html`: 메인 「CAD」 칸(**전 직원**에게 열림, 아이콘은 삼각자+치수선), `go('cad')` → `../cad/index.html` 화면 안 창, `window.WS_CAD`(`me`·`list`·`open`(기기 캐시 `ws-cad`)·`upload`·`full`). 구글 웹앱에서는 안내만.
- `Code.gs`: `?api=caddrive` → `cadDrive_` : 서버 파일을 `시설팀 통합업무/20_업무지원/CAD변환파일/YYYY-MM`에 복사(열화상 `thermalDrive_` 방식, 링크 보기 공유).
- 시험: `sql_test.js`에 CAD 12개, `cad_test.js`(뷰어 6개), `test:all` 통과.
- **붙이는 날**: ① Supabase에서 `18_cad.sql` Run ② Apps Script에 `Code.gs` 올려 기존 배포 갱신(`caddrive` 길) ③ 바로가기 저장소에 `fm/cad/`·`fm/ws/app.html`·`fm/ws/ws-api.js` ④ 업무지원 CAD › 도면 올리기로 시험.
- **아직 안 한 것**: 환경설정 켜기·끄기 목록에 CAD(서버가 키를 거름 → `15_menu.sql`·`MENU_KEYS_`·화면 한 번에), 소장 「삭제」 단추(함수는 있음), PC 변환기 업로드 단추 정리, 도면 보관 기간.
