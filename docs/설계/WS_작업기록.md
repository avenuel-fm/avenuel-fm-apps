#### 15.3.6 작업 기록 (작업일지 · TBM · 점검 공통)

**입력 항목**

| 필드 | 필수 | 입력 | 제한 |
|---|---|---|---|
| 작업명 | ✔ | 직접 입력 + 자동완성(최근 작업명, 검색사전 `분류=작업`) + 칩 | 30자 |
| 위치 | ✔ | 직접 입력 + 자동완성(DW 매장 목록, 검색사전 `분류=장소`) | 30자. 매장을 고르면 `store_id` 저장 |
| 작업자 | 자동 | 로그인 정보 | 수정 불가 |
| 작업일 | 자동 | 오늘 (PC에서는 바꿀 수 있음) | |
| 구분 | 자동 | 선택한 항목 | |
| 사진 | ✔ | 작업 전 / 작업 중 / 작업 후 각 1장 | |
| 추가 사진 | | `작업사진 업로드` 버튼, 여러 장 | 작업당 전체 33장 |
| 작업 내용 | ✔ | 여러 줄 | 300자 |
| 특이사항 | | 여러 줄 | 400자 |

**사진**
- 처리 방법은 9장을 따릅니다 (5장 묶음 `uploadPhotosBatch`, 지문으로 중복 건너뛰기, 고용량 자동 축소).
- 번호: `001` 작업 전, `002` 작업 중, `003` 작업 후, `004`부터 추가 사진 (5.1).

**작성 중 내용 보관** (9.4 공통 규칙의 WS 적용)
- 첫 사진을 넣거나 [임시 저장]을 누르면 `작업기록`에 상태 `작성중` 줄과 작업 폴더를 만듭니다.
- 그 뒤 사진은 **찍는 즉시** 올리고, 입력값은 화면을 옮길 때와 30초마다 서버에 저장합니다 (`saveDraft`).
- 그래서 휴대폰을 바꿔도 **내 문서**에서 이어 쓸 수 있고, PC에서도 이어 쓸 수 있습니다.
- 임시 저장 중 사진은 드라이브에만 저장하고, 사진색인 등록과 이름 맞추기는 제출 뒤에 합니다 (9.4).
- 임시 저장을 만들 때 받은 `WS-WL-…` 번호는 버려도 다시 쓰지 않습니다 (빈 번호 그대로).

**ID**
- 사진 `PH-WS-…`, 작업일지 `WS-WL-…`, 사진 폴더 `WS-PF-…`, TBM `WS-TB-…`, 점검 `WS-IN-…`
- 파일 설명에는 파트, 위치, 작업자, 내용, 문서 ID를 적습니다.

**제출 흐름** (11.2)
```
입력(임시 저장 중 사진은 이미 올라감) → 미리보기 → [제출]
 ① saveWorkOrDefect: (작성중 기록이 없으면) WS 잠금 안에서 ID 채번·작업 폴더 생성 / 상태 제출, 연결 일정 갱신
 ② 남은 사진 uploadPhotosBatch × N (드라이브에 저장)
 ③ 화면에 "제출 완료 · PDF 만드는 중" → 직원은 다음 일로
 ④ 화면이 결과를 기다리지 않고 buildPdf(token, docId) 한 번 더 호출. 이 안에서 차례로:
    ④-1 이름 맞추기: 제출 때 작업명·작업일로 폴더·사진 이름을 다시 정함 ((2) 판단 포함, 바뀐 것만 고침)
    ④-2 사진색인 한꺼번에 등록: cdb.addPhotos (Values.append 1번)
    ④-3 Slides → PDF
 ⑤ PDF 완료 → 작업 폴더에 저장, 「작업일지 PDF 모아보기/YYYY/YYYY-MM/」에 바로가기
 ⑥ cdb.addDocs: 작업일지(WS-WL) 1줄 + 사진 폴더(WS-PF) 1줄
 - ④가 중간에 실패하면 PDF대기 재시도(10분)가 ④-1부터 다시 함. 이미 끝난 단계는 건너뜀
```
- `작업기록.PDF상태`는 `대기 / 생성중 / 완료 / 실패` 중 하나입니다. 문서색인 `세부상태`에도 반영합니다.
- 예약 작업 `retryPendingPdfs`가 **10분마다** 돕니다.
  - `생성중`으로 30분 넘게 남은 건은 `실패`로 봅니다.
  - **3번 실패**(`PDF시도횟수=3`)하면 멈추고 `오류기록`에 남깁니다. HUB 할 일과 WS PC 화면에 표시하고, 관리자·소장이 [다시 만들기]를 누릅니다.

**수정** (11.3)
- 작성자는 결재 전까지 고칠 수 있습니다.
- 결재한 뒤에는 소장·관리자만 고칠 수 있고, 고치면 결재가 처음으로 돌아갑니다.
- 모든 수정은 WS `변경기록`과 공통 `변경이력`에 남습니다.

#### 15.3.7 작업일지 PDF 양식
| 항목 | 정의 |
|---|---|
| 용지 | A4 세로 1쪽 |
| 상단 | `작 업 일 지`, `에비뉴엘 잠실점 시설팀` |
| 서명란 | 오른쪽 위 **파트장 · 소장** 2칸. `{{파트장서명}}`, `{{소장서명}}`에 결재자 직인이 들어감 |
| 정보표 | 일자, 구분, 작업명, 위치, 작업자(이름·파트) |
| 작업 내용 | 고정 높이 칸 |
| 사진 | **가로 4:3 칸 3개**, 아래에 `작업 전 / 작업 중 / 작업 후`. 칸 안은 **자르지 않고 칸에 맞게 줄이고, 남는 곳은 연회색** (9.3). 화면에서 누르면 원본 비율로 확대 (9.2) |
| 특이사항 | 사진 아래 남은 공간. 남으면 빈칸 그대로 |
| 하단 | `추가 사진 N장 · 폴더 2026-11-01_분전반-교체`, 문서 ID |

#### 15.3.8 결재
- 11.3을 따릅니다. 결재할 때 PIN은 다시 묻지 않습니다.
- 결재되면 작성자의 내 문서에 「OO님이 확인했습니다」를 표시합니다.
- 상태는 `제출 → 파트장확인 → 소장확인` 순서로 바뀌고, `cdb.updateDoc`로 자기 줄만 고칩니다.

#### 15.3.12 검색
- 공통 틀 `cdb.search`를 쓰고, 기본 범위만 WS 문서로 좁힙니다. 앱 고르기로 전체도 볼 수 있습니다 (10장).
- 결과는 **작업일지**(표)와 **이미지 폴더**(썸네일 카드)로 나눠 보여 줍니다.
- 매장 이름을 누르면 매장 이력(HUB)이 열립니다.
