# 공통 · 사진과 파일

- 판: **v1.6** · 수정 2026-11-04 · 공통 규격 v1.8
- 담은 장: 5 이름 · 폴더 · 9 사진
- **이럴 때 읽기**: 사진을 찍거나 올리고, 드라이브에 파일·폴더를 만들 때
- 목차·읽는 법: `claude/설계/00_목차_읽는법.md`

> **요약**
> - 파일 이름 `YYYY-MM-DD_작업명_###.jpg`, 폴더 `YYYY-MM-DD_작업명`, 같은 날 같은 이름은 `(2)`
> - 드라이브 `시설팀 통합업무/{앱번호}_{앱이름}/…`, 외부 공유는 보내는 PDF·ZIP만
> - 사진은 기기에서 줄여(1600px·70%, 문서 사진은 2400px·85%) 5장씩 보냄, 썸네일 320px, 지문으로 중복 건너뜀
> - **모든 사진 칸은 가로 4:3, 자르지 않고 줄여 넣기, 남는 곳 연회색**, 누르면 원본 확대
> - 작성 중 내용은 기기 + 서버 임시 저장, 사진색인·이름 맞추기는 제출 때

## 5. 이름 · 폴더 규칙

### 5.1 파일 이름 (필수)
| 대상 | 형식 | 예 |
|---|---|---|
| 작업 폴더 | `YYYY-MM-DD_작업명` | `2026-11-01_분전반-교체` |
| 사진 | `YYYY-MM-DD_작업명_###.jpg` | `2026-11-01_분전반-교체_001.jpg` |
| 작업 PDF | `YYYY-MM-DD_작업명.pdf` | `2026-11-01_분전반-교체.pdf` |
| 하자점검 | 폴더 `YYYY-MM-DD_하자점검-테넌트명` / 통보서 `YYYY-MM-DD_하자통보서-테넌트명.pdf` | |
| 도면협의 사진 | `YYYY-MM-DD_도면협의-테넌트명_###.jpg` | |
| 썸네일 | `{photo_id}_w320.jpg` | `PH-WS-20261101-0042_w320.jpg` |

- **날짜**: 찍은 날(사진 정보)입니다. 없으면 올린 날입니다.
- **작업명** (저장할 때만 바꿉니다. 화면과 PDF에는 입력한 그대로 보여 줍니다)
  - 띄어쓰기와 특수문자는 `-`로 바꿉니다. `-`가 이어지면 하나로 줄입니다.
  - 밑줄 `_`은 구분용이라 작업명 안에 쓰지 않습니다.
  - 길이는 30자까지입니다.
- **같은 날, 같은 작업명**: 작업명 뒤에 `(2)`를 붙입니다. 폴더, 사진, PDF가 모두 같습니다. 예: `2026-11-01_분전반-교체(2)_001.jpg`
- **번호**: 그 폴더 안에서 3자리로 셉니다.
  - 작업일지는 고정 칸입니다. `001` 작업 전, `002` 작업 중, `003` 작업 후, `004`부터 추가 사진입니다.
  - 그 밖의 업무는 올린 순서대로 셉니다.
  - 사진을 바꿔 올리면 **같은 번호**를 다시 씁니다. 예전 파일은 휴지통으로 보내고 색인은 `삭제여부=Y`로 표시합니다.
- 파일 설명(Description)에는 파트, 위치, 작업자, 내용, 문서 ID를 적습니다. 드라이브 검색창으로도 찾을 수 있습니다.
- 이름 바꾸기와 삭제는 **앱에서만** 합니다. 드라이브에서 직접 바꾸면 색인과 어긋납니다.

### 5.2 드라이브 구조
```
시설팀 통합업무/                                   (시설팀 공용 계정, 비공개)
├─ 00_시스템/
│   ├─ 00_공통DB_통합대시보드 · 10_도면협의_DB · 20_업무지원_DB · (새 앱 DB)
│   ├─ 양식템플릿/            Slides 템플릿 · 직인/ (비공개)
│   └─ 백업/{YYYY-MM-DD}/     매일 새벽 사본, 30일 보관
├─ 10_도면협의/
│   ├─ 도면협의_출력/{문서번호}/          검토서 PDF (외부 링크 보기)
│   ├─ 도면협의_지침/                    지침 PDF · 시방서 ZIP (외부 링크 보기)
│   └─ 도면협의_사진/{YYYY}/{YYYY-MM}/{YYYY-MM-DD}_도면협의-{테넌트명}/
├─ 20_업무지원/
│   ├─ 작업기록/{파트}/{YYYY}/{YYYY-MM}/{YYYY-MM-DD}_{작업명}/   사진 + 작업 PDF
│   ├─ 작업일지 PDF 모아보기/{YYYY}/{YYYY-MM}/                   바로가기만
│   └─ 하자점검/{YYYY}/{YYYY-MM}/{YYYY-MM-DD}_하자점검-{테넌트명}/  사진 + 통보서 PDF
├─ {새 앱 번호}_{앱이름}/                                       새 앱도 같은 모양
└─ 90_썸네일캐시/{YYYY}/{YYYY-MM}/{photo_id}_w320.jpg
```
- **앱 폴더 번호**: `10` DW, `20` WS, `30` 이후 새 앱에 차례로 붙입니다. `00`과 `90`은 시스템용입니다.
- **폴더 ID 기억**: 앱 `설정` 탭의 `FOLDER_CACHE_JSON`에 둡니다.
  - 스크립트 속성은 값 하나에 9KB까지라 담기 부족합니다.
  - 폴더를 찾지 못하면 이름으로 다시 찾고, 그래도 없으면 새로 만듭니다.
  - **예외 (결정 34)**: 기억할 폴더가 몇 개뿐인 앱은 스크립트 속성에 폴더마다 ID 하나씩 둬도 됩니다 (9KB 한도에 걸리지 않음). 예: DW `FOLDER_PHOTO` `FOLDER_PDF` `FOLDER_BACKUP` `GUIDE_FOLDER` (DW 15.2.2).
- **공유**: 외부로 보내는 PDF와 ZIP만 "링크가 있는 사용자 · 보기"로 엽니다. 나머지는 모두 비공개입니다.
- **기존 DW 폴더**는 `시설팀 통합업무/10_도면협의`로 **옮깁니다** (결정 10).
  - DW는 v1.8.3부터 폴더를 ID로 찾으므로 옮겨도 동작합니다 (DW 15.2.2). v1.8.2까지는 이름으로 찾았습니다.
  - 옮기는 작업은 "진행시켜" 후 배포 단계의 운영 작업으로 합니다 (WS-8).
- **이전 DW 사진**(`도면협의_사진/문서번호/`)은 **그대로 두고 색인만** 등록합니다 (결정 7).
  - 이미 보낸 메일, 출력물, 검토서 링크가 예전 파일을 가리키고 있기 때문입니다.
  - 새 사진부터 5.1 규칙으로 저장합니다.

## 9. 사진

### 9.1 올리기 (모든 앱 같은 방식)
1. **기기에서 처리합니다.**
   - 촬영일과 방향을 **줄이기 전에** 먼저 읽습니다.
   - 방향을 바로잡은 뒤 본사진(긴 변 1600px, JPEG 70%, 약 250KB)과 썸네일(320px, 약 15KB)을 만듭니다.
   - **예외 — 문서 사진**(협의서·서류처럼 글자를 읽어야 하는 사진): 긴 변 **2400px, JPEG 85%** (결정 27, 예: DW 종합방재실 협의서 15.2.1)
   - 지문(해시)을 계산합니다.
2. **5장씩 묶어서** `uploadPhotosBatch(token, docId, photos[{kind, seq, origB64, thumbB64, exifDate, hash}])`로 보냅니다.
   - 실패한 묶음만 다시 보냅니다.
3. **서버**가 앱 잠금 안에서 처리합니다.
   - 같은 지문이면 건너뜀
   - 이름 정하기
   - 작업 폴더와 썸네일 폴더에 저장
   - 파일 설명 적기
   - `cdb.addPhotos` (W1)
4. **끊김 대비**: 보내지 못한 사진과 입력값은 기기(IndexedDB)에 보관합니다. 다시 열면 이어서 보냅니다.
- 작업 하나에 사진은 최대 33장입니다. 20장 기준 목표는 8~10초입니다.

### 9.2 보기
- 목록과 폴더는 `getPhotoThumbnails(token, docId 또는 photoIds)`로 **한 번에 묶어** 받습니다. 30장이면 약 450KB입니다.
- 원본은 사진을 눌렀을 때만 `getFile`로 받습니다.
- **확대 보기 (모든 앱 공통)**: 썸네일, 칸에 들어간 사진, PDF 미리보기 화면의 사진을 누르면 화면 가득 확대해서 보여 줍니다.
  - 확대한 사진은 **원본 비율 그대로**(1600px 본사진) 보입니다. 잘리거나 늘어나지 않습니다.
  - 두 손가락·휠로 더 키우고, 좌우로 넘겨 같은 문서의 다른 사진을 봅니다. 닫기(✕), 원본 내려받기 버튼이 있습니다.
  - 종이로 출력한 PDF는 누를 수 없으므로, 작업일지 아래쪽에 원본이 있는 폴더 이름을 적어 둡니다 (15.3.7).
- `drive.google.com/thumbnail?id=` 주소는 **쓰지 않습니다.** 비공개 파일이라 구글 계정에 로그인하지 않은 직원 휴대폰에서는 보이지 않습니다.

### 9.3 사진 칸 — 모든 앱 공통 가로 4:3 (결정 20, 11-03)
- **모든 사진 칸의 기본 모양은 가로 4:3**입니다. PDF 사진 칸, 입력 화면의 사진 칸, 하자 통보서, 썸네일 카드 등 모든 앱이 같습니다.
- 칸 안 사진은 **자르지 않고, 칸에 맞게 줄여서** 넣습니다 (결정 5). 명판이나 계기 숫자가 잘리지 않습니다.
- 4:3이 아닌 사진은 칸에 남는 부분이 생깁니다. 이 부분은 **연회색(`--line3` #EDF0F3)**으로 채웁니다.
- 사진을 누르면 원본 비율로 확대해서 봅니다 (9.2).
- 예외: 카메라 화면에서 바로 4:3으로 잘라 찍는 기능(예: 소화기 압력계)은 저장 사진 자체가 4:3입니다.

### 9.5 카메라 여는 방법 (모든 앱 공통, 결정 44)
- **구글 웹앱 화면 안에서는 실시간 카메라를 쓰지 않습니다.** 구글 웹앱은 카메라 권한이 막힌 격리 칸(iframe) 안에서 돌기 때문입니다(2026-02 무렵부터).
- 앱 안의 모든 사진 칸(작업일지·하자·TBM 등)은 **휴대폰 기본 카메라 앱**(`<input type="file" accept="image/*" capture="environment">`)이나 사진 고르기로 받습니다. 찍은 뒤 9.1처럼 기기에서 줄입니다.
- **실시간 화면에 안내선을 겹쳐야 하는 화면만**(예: 소화기 압력계) 바로가기 페이지(GitHub, 14.1)에 그 화면을 두고, 구글 웹앱과는 JSON 통로(`?api=`, `doPost`)로만 주고받습니다 (WS 15.3.17).
  - 그런 화면도 카메라가 안 열리면 기본 카메라 앱으로 넘어가게 만듭니다.
  - 손전등을 지원하는 카메라면 손전등 버튼을 둡니다.

### 9.4 작성 중 내용 보관 — 기기 + 서버 임시 저장 (모든 앱 공통, 결정 8)
- 문서를 쓰다가 [임시 저장]을 누르거나 첫 사진을 넣으면, 앱 DB에 **상태 `작성중`** 줄과 작업 폴더를 만듭니다.
- 그 뒤 사진은 찍는 즉시 5장 묶음으로 올리고, 입력값은 화면을 옮길 때와 30초마다 서버에 저장합니다.
- 기기(IndexedDB)에도 같이 보관합니다. 신호가 끊기면 기기 것을 먼저 쓰고, 연결되면 서버로 보냅니다.
- 그래서 휴대폰을 바꾸거나 아이폰이 기기 저장소를 지워도 이어 쓸 수 있고, PC에서도 이어 쓸 수 있습니다.
- `작성중` 문서는 **문서색인에 넣지 않습니다.** 제출할 때 등록합니다.
- 7일 넘게 제출하지 않은 기록은 「오래된 임시 저장」으로 표시합니다. 자동으로 지우지는 않습니다.
- **사진색인은 제출할 때 한꺼번에 등록합니다** (결정 13). 임시 저장 중 올린 사진은 드라이브에만 있고 검색에는 나오지 않습니다.
- **이름은 제출할 때 다시 맞춥니다** (결정 14). 제출 때의 작업명·작업일을 기준으로 폴더·사진·PDF 이름을 정하고, 같은 날 같은 작업명인지(`(2)`)도 이때 판단합니다. 임시 저장 중에는 처음 만든 이름을 그대로 둡니다.
- **번호는 임시 저장을 만들 때 매깁니다** (결정 15). 제출하지 않고 버린 기록의 번호는 빈 번호로 그대로 둡니다. 번호는 찾기용이라 이어지지 않아도 됩니다.
- DW는 지금도 기기 보관 + 저장 방식이 있습니다(v1.3). DW에 서버 임시 저장을 따로 더할지는 DW 개선 때 정합니다.
