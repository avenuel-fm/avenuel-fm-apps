CAD 변환기(PC 단독 프로그램) 수정 지시 3 — 업로드를 업무지원 직원 PIN과 대조 + 레이어 이름 바꾸기 (Claude Code 세션이 정리, 사용자가 전달)

[배경 — 지금 문제]
업로드 창에서 소장 PIN을 넣어도 「인증된 직원: 홍길동 (직원)」으로 나옵니다. 지금 uploader.js 는 가짜 서버(useMock)라서 PIN과 상관없이 홍길동으로 처리합니다.
고칠 것: 입력한 PIN을 업무지원 앱의 실제 직원 PIN과 대조해서, 맞는 직원의 이름·역할로 표시하고, 그 직원이 올린 것으로 기록되게 한다.
서버 쪽(업무지원 구글 웹앱 + Supabase)은 Claude Code 세션이 이미 만들어 두었다(아래 규격). 안티그라비티는 PC 프로그램만 고친다.

[규격 — 구글 웹앱 주소로 POST]
- 주소: https://script.google.com/macros/s/AKfycbxzD0-R4Cg5_eeECMfgLok3lCSOZuac5cwVSVLvVuQTp_d3rfm_HWH1ju-EmyVC5qut6Q/exec  (설정 한 곳에만 둘 것: uploader.js 의 UPLOAD_CONFIG.serverUrl)
- 요청은 모두 POST, 본문은 JSON 글자(Content-Type: text/plain 으로 보낸다 — 구글 웹앱은 이렇게 보내야 받는다). 답은 JSON.
- 구글 웹앱은 POST 를 302 로 넘겨 답을 준다. 브라우저 fetch 는 CORS 때문에 막힐 수 있으니 **요청은 PC 프로그램의 파이썬 백엔드(backend/app.py)가 urllib 로 보내고**, 화면(JS)은 백엔드의 내부 주소(예: /api/upload/*)만 부른다. 리다이렉트를 따라가야 한다.
- 1) {"action":"cadLogin","pin":"1234"}  → {"ok":true,"name":"홍길동","role":"소장"} 또는 {"ok":false,"error":"PIN이 맞지 않습니다. (2/5)"}
     · PIN 5번 틀리면 서버가 5분 잠근다(error 문구에 그대로 나옴). 문구를 화면에 그대로 보여 준다.
- 2) {"action":"cadCats","pin":"…"} → {"ok":true,"cats":[{"id":1,"name":"공조"},…]}  (올릴 때 고를 분류 목록)
- 3) {"action":"cadPrepare","pin":"…"} → {"ok":true,"path":"cad/2026-11/<32자>.dxf","uploadUrl":"https://….supabase.co/storage/v1/object/upload/sign/ws-files/…?token=…"}
- 4) 파이썬이 DXF 파일을 uploadUrl 로 **PUT** (본문 = 파일 그대로, Content-Type: application/octet-stream). 파일이 크면(수십 MB) 진행 표시. 2xx 가 아니면 실패로 알린다.
- 5) {"action":"cadFinish","pin":"…","path":<3에서 받은 path>,"name":"도면 이름","floor":"1F","memo":"…","cat_id":"1"(선택, 없으면 ""),"size":파일바이트수}
     → {"ok":true,"id":"…","name":"홍길동","drive":true}  (name = PIN 으로 확인된 직원 이름, 구글 드라이브 사본까지 만들어졌으면 drive:true)
     · 같은 이름의 도면이 서버에 이미 있으면 새 파일로 바뀐다(한 줄 유지). 그래서 올리기 전에 「같은 이름이 있으면 덮어쓰기」 안내만 보여 주면 된다(서버에서 먼저 조회하는 규격은 아직 없음 → 안내 문구만).
     · 한 사람 하루 30개까지, 파일 50MB 이하. 서버가 거절하면 error 문구를 그대로 보여 준다.

[PC 프로그램에서 할 일]
1. 업로드 창: PIN 입력 → 「확인」 누르면 cadLogin 호출 → 성공하면 「인증된 직원: 〈서버가 준 이름〉 (〈역할〉)」. 실패하면 서버의 error 를 그대로 보여 준다. **홍길동 가짜 값·useMock 은 없앤다**(시험용 가짜 서버는 환경 변수나 별도 파일로만 켜지게 두어도 되지만 기본은 실서버).
2. 분류 선택 칸(cadCats 로 받은 목록, 맨 위 「미분류」)을 층·메모 옆에 둔다. 고른 값이 cat_id.
3. 「업로드 실행」 = cadPrepare → PUT → cadFinish. PIN 은 메모리에만 두고 저장하지 않으며, 화면을 닫으면 지운다(이 PC에서 2~3번 연속 올릴 때는 같은 PIN 을 메모리에서 다시 쓰는 것은 괜찮다).
4. 완료 문구: 「〈이름〉님 이름으로 올렸습니다. 업무지원 CAD › 분류 〈분류〉에서 보입니다」(drive:false 면 「구글 드라이브 저장은 실패했습니다. 도면 목록에는 올라갔습니다」를 덧붙인다).
5. 인터넷이 없으면 「인터넷에 연결되지 않아 올릴 수 없습니다. 변환은 인터넷 없이 됩니다」 안내.

[레이어 이름 바꾸기 — 새 기능]
- 변환기 화면의 레이어 목록에서 레이어 이름을 바꿀 수 있게 한다(이름 옆 연필 단추 또는 더블클릭 → 입력 → Enter). 바꾼 이름은 목록·미리보기에 바로 보이고, 저장하는 DXF(와 DWG)에 반영된다.
- DXF 안에서 바꿀 곳(빠짐없이): LAYER 표의 레이어 항목 이름(그룹 코드 2), 모든 도형·블록 안의 레이어 지정(그룹 코드 8), 블록 정의 안 도형, 레이아웃·뷰포트의 레이어 참조가 있으면 그것까지. 확장 데이터(XDATA)에 레이어 이름이 문자열로 있는 경우는 건드리지 않는다.
- 규칙: 빈 이름 불가, DXF 금지 문자(< > / \ " : ; ? * | = `) 불가, 255자 이하. 레이어 「0」과 「Defpoints」는 바꿀 수 없다(바꾸기 단추를 숨기거나 막고 이유를 안내).
- 새 이름이 이미 있는 레이어와 같으면 「합치기」가 되므로 확인 문구를 띄운다(「A 레이어의 도형 N개가 B 레이어로 합쳐집니다」). 대소문자만 다른 이름은 같은 이름으로 본다(CAD 규칙).
- 되돌리기(바꾸기 전 이름으로) 한 단계, 「이름 바꾼 목록」을 한눈에 보는 요약(예: 옛 이름 → 새 이름)을 저장 전 확인 화면에 보여 준다.
- 바꾼 목록은 변환 결과 정보 파일(.json)에도 남긴다(renames: [{from,to}]).
- 일괄 바꾸기(선택): 이름 앞부분 바꾸기(예: 「A-」 → 「공조-」)를 한 번에. 시간이 부족하면 개별 바꾸기만 먼저.
- 분류(공조·소방 등 자동 분류)는 이름 바꾼 뒤의 이름 기준으로 다시 계산한다.

[확인할 것]
- 실제 도면으로: 레이어 하나를 바꾼 DXF 를 CAD 프로그램(또는 ezdxf)으로 열어 도형이 새 레이어에 그대로 있는지, 옛 이름이 남아 있지 않은지.
- 올린 도면이 업무지원 CAD 목록에 올린 직원 이름으로 보이는지(서버가 이미 배포돼 있어야 함 — 아직이면 서버 호출 부분은 가짜 서버로 시험하고 알려 줄 것).
- 다른 폴더는 고치지 않는다. 결과·바뀐 파일 목록·확인한 것과 못 한 것을 알려 줄 것.
