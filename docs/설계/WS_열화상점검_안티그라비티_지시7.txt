[지금 상태 — Claude 가 11-24 에 만든 .atr 의 문서 안 그림을 꺼내 합성해 본 결과]
지시 6 으로 열화상 본체 JPEG 는 순수 320×240 baseline(약 18KB)이 되어 양식(38KB)과 모양이 같아졌다. 그런데 **본체 그림이 카메라 JPEG 를 그대로 줄인 것**이라 카메라가 그림 속에 **이미 구워 넣은 그래픽**(좌측 위 「스팟 1 32.3 / 스팟 2 29.9 / 스팟 3 26.0」 박스, 오른쪽 눈금 35.9~24.7, 십자선 1·2·3, FLIR 로고)이 남아 있다. 그 위에 우리가 만든 스팟 표시 PNG(글자 박스·십자선)가 또 얹혀서 **글자와 십자선이 겹쳐 보인다**(2중 표시).
양식의 쪽 그림은 이렇게 되어 있다(문서 1쪽, 위치 426571 JPEG 320×240 + 61771 PNG 690×517 RGBA):
 · 본체 JPEG = **카메라 그래픽이 없는 순수 열화상**(팔레트 색만).
 · 스팟 PNG(투명 바탕, 불투명 점 약 53,000개) = **왼쪽 눈금 막대(위 최고 온도 박스 「31.1 °C」, 아래 최저 온도 박스 「26.7 °C」, 가운데 색 막대)** + **스팟 십자선 3개와 「Sp1」「Sp2」「Sp3」 글자** + FLIR 로고. 즉 눈금·스팟 그래픽은 PNG 가 담당하고 본체는 그림만이다.
FLIR 에서 스팟을 조정해 저장하면 사진이 정상이 되는 것도, FLIR 가 이 두 장을 **원시 온도 자료에서 다시 만들기** 때문이다.

[할 일]
1. **열화상 본체를 카메라 JPEG 가 아니라 원시 온도 자료(FlirParser 의 rawPixels, FlirCalculator)로 직접 그린다.** 최저·최고 온도(눈금 범위)를 정하고, 온도를 0~255 로 펴서 FLIR 의 「Iron(아이언)」 팔레트(검정·남색·보라·빨강·주황·노랑·흰색 순서) 색으로 입힌 320×240 이미지(해상도가 640×480 인 사진은 그 해상도로 그렸다가 320×240 으로 줄인다)를 baseline JPEG(품질 0.85~0.9)로 만든다. 양식 본체 JPEG(문서 위치 426571, 38,514바이트)를 같은 방식으로 분석해 팔레트·밝기를 맞춘다(samples\ 사진과 양식 안 그림으로 비교).
2. **스팟 표시 PNG 를 양식 PNG 와 같은 구성으로 만든다**: 투명 바탕 690×517, 왼쪽 눈금 막대(위·아래 온도 박스에 최고·최저 온도 「31.1 °C」 형식, 가운데 팔레트 색 막대), 스팟 십자선 3개와 「Sp1」「Sp2」「Sp3」 글자(스팟 위치는 320×240 좌표 → 690×517 로 변환), 오른쪽 아래 FLIR 로고는 우리가 그리지 않아도 된다(저작권·모양 때문에 빼도 됨). 양식 PNG 를 꺼내(samples 에 저장해 두고) 글자 크기·위치·박스 모양을 그대로 따른다. 카메라 박스 「스팟 1 32.3 °C …」 같은 글자 박스는 넣지 않는다(양식에 없음).
3. 쪽의 **표 글자의 Point 온도·눈금 최고·최저는 같은 계산 결과**를 쓴다(이미 맞음, 유지).
4. 실화상(2048×1536)과 잘라낸 실화상(320×240)은 지금 방식 그대로 둔다. 실화상이 없는 사진은 열화상 본체를 잘라 쓰지 말고(기존 동작 확인).
5. 쪽 수 1·3·8, 사진이 640×480 인 경우, 스팟이 사진 가장자리에 있는 경우를 시험한다.
6. 시험용 .atr 을 samples/atr_test4/ 에 만들고 README 에 FLIR 에서 확인할 것(스팟을 안 건드려도 열화상이 나오고, 글자·십자선이 겹치지 않고, 눈금 최고·최저가 맞는가)을 적는다. 사용자가 열어 확인한다. Claude 는 FLIR 를 직접 열 수 없다.
7. (선택) 사용자가 FLIR 에서 스팟을 조정해 저장한 .atr(after)을 samples/atr_flir_saved/ 에 두면, 문서 안 그림 사본을 비교해 팔레트·PNG 구성을 더 정확히 맞춘다. 없으면 양식 PNG·본체 JPEG 기준으로 진행한다.
