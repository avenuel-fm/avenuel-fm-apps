## 1. 무엇
- 업무지원 메인의 「작업중」 칸(PC 3칸 배치에서 **서류작업 바로 아래**, 4번째 칸 `plan`)을 **「시방서 검색」**으로 바꿉니다.
- 도면협의(DW)의 **지침 검색**(검토서 특이사항 옆 사이드 메뉴)과 같은 자료를 업무지원에서 **읽기만** 합니다.

## 2. DW 지침 검색 분석 (지금 모습)
| 항목 | 내용 |
|---|---|
| 자료 위치 | Supabase (업무지원과 **같은 프로젝트** `kjhsduhufwaihhlfdipf`) |
| 지침 목록·검색 항목 | 표 `dw_guides` — 지침마다 `entries`(검색 항목 묶음), `page_map`(쪽 번호 → 쪽 그림), `file_id`(원본 PDF), `archived`(이전 판) |
| 검색 항목 한 줄 | `{ d: 지침ID, p: PDF 쪽, s: 구분, lp: 지침 안 쪽 번호, h: 소제목, t: 본문(200자), l: 표 구분, b: 글자 위치 상자 }` |
| 쪽 그림 | 버킷 `dw-files` 의 `guide/{지침ID}/` (공개 버킷), 표 `dw_files` kind `guide_page` |
| 비슷한 말 | 표 `dw_synonyms` (한 줄에 같은 뜻의 말) |
| 읽는 함수 | `dw_guide_index`, `dw_guide_page`, 부트스트랩의 `guides`·`synonyms` — **모두 DW 로그인(소장·부소장 PIN, `dw_role_`)이 있어야 함** |
| 검색 방식 | 화면(브라우저)에서 함 — 항목 전체를 한 번 받아 두고 글자 찾기(띄어쓰기 무시) + 비슷한 말 + 소제목·표 구분까지, 최대 80건 |
| 화면 | 오른쪽 420px 사이드 패널(검색창 · 지침별 걸러 보기 · 자주 찾는 키워드 · 결과 카드) + 왼쪽에 뜨는 쪽 미리보기(노란 상자로 검색어 줄 표시, 확대·고정) |
| 지침 올리기·색인 | DW 「지침 관리」에서만 (PDF 올리기 → 브라우저에서 읽어 색인·쪽 그림 만듦) |

## 3. 연결 방법
- **DW 코드는 건드리지 않습니다.** 업무지원 쪽에 읽기 전용 DB 함수 3개를 새 파일 `apps/ws/supabase/14_spec.sql`로 더합니다.
  - `ws_spec_boot(p_token)` → 지침 목록(제목·줄임말·쪽수·이전 판 여부) + 비슷한 말
  - `ws_spec_index(p_token)` → 모든 검색 항목 (DW `dw_guide_index`와 같은 순서)
  - `ws_spec_page(p_token, p_guide, p_page)` → 쪽 그림 주소 + `PDF 원본` 주소 (원본이 드라이브로 옮겨졌으면 빈 값 → 단추 숨김)
  - 모두 업무지원 로그인(`ws_auth`)으로 확인 → 로그인한 업무지원 직원은 누구나 볼 수 있음. 쓰기 없음.
- 화면: `apps/ws/src/Index.html`에 `renderSpec()` (S.view `spec`), 검색 방식은 DW 함수(`synTerms`·`findIn`·`compactFind`·`searchGuide`·`hlBoxes`)를 그대로 옮김.
- 통로: `fm/ws/ws-api.js`에 `specBoot`·`specIndex`·`specPage` 3줄. 구글 웹앱 통로(옛 화면)에서는 안 열림(안내 글).
- `14_spec.sql`은 옵저버 역할 검사도 운영 DB에서 바꿈 (부록).
- 지침 추가·개정은 지금처럼 DW 「지침 관리」에서만 → 업무지원에는 바로 나옴(같은 표).

## 4. 화면 (넓은 화면에 맞게 다시 배치)
- **PC(760px 넘음)**: 위에 큰 검색창 + 지침별 걸러 보기 → 아래 3칸
  - 왼쪽(240px): 자주 찾는 말 · 검색하는 지침 목록 · 비슷한 말 안내
  - 가운데: 결과 카드 (쪽 번호 · 지침 표 · 위치 · 글 조각(노란 표시) · 「쪽 크게 보기」 · 「참조 복사」)
  - 오른쪽: 고른 결과의 **쪽 미리보기가 늘 떠 있음** (DW처럼 마우스를 올려야 뜨는 방식이 아님), 확대·축소 · PDF 원본, 노란 상자로 검색어 줄
- **1000px 아래**(작은 PC·아이패드 세로): 왼쪽 + 결과 2칸, 쪽은 「쪽 크게 보기」 창
- **휴대폰**: 검색창 · 걸러 보기(옆으로 밀기) · 결과 카드만, 「쪽 크게 보기」를 누르면 아래에서 올라오는 쪽 보기 창
- DW의 「삽입」(검토서 특이사항에 넣기)은 업무지원에 쓸 곳이 없어 **「참조 복사」**(예: `(시설공사, p.12)`를 복사)로 바꿈.

## 5. 정한 것 · 시험

# 부록: 옵저버 역할 (결정 138)
- 직원 추가·편집의 역할에 「옵저버」 추가, 고르면 파트 칸이 **「관리」**로 자동 채워짐.
- 고칠 곳: `01_schema_rls.sql` 역할 검사(운영 DB는 제약 바꾸는 SQL 한 번 실행), `08_settings.sql` 역할 목록, `Code.gs` `ROLES`(구글 통로), `Index.html` `ROLES`·`staffDlg`.
- 권한 (사용자 11-17): **일반 직원과 같음 + 지도 고치기**. 로그인 서명·출근현황·TBM 서명 명단도 직원과 똑같이 다룸. 고친 곳: `13_map.sql` `ws_map_can_edit`에 옵저버, 안내 글 「소장·부소장·파트장·옵저버만」(`fm/map` 포함). 파트 「관리」 고정은 화면(`sfRole`)·Supabase(`ws_admin_staff_save`)·구글 통로(`Code.gs`) 셋 다.
- 직원처럼 막히는 곳: 환경설정(소장만), 공사장점검 기본 항목(관리자·소장), 출근현황 고치기(소장·부소장·총무, 근무표 직책 기준), 지도 되돌리기(소장만).
- 도면협의(DW)·HUB: DW는 역할을 따로 씀(소장·부소장 PIN 2개, 결정 36) → 영향 없음. HUB는 코드 없음.
