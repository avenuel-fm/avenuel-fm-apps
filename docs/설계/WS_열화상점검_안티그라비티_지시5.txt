(가설, 확인 필요) 예전 PC 판(engine/atr_builder.py)은 MT.bin 의 Name·OriginalPath 를 **양식 그대로 두었고**(주석 「CRITICAL: Keep original Name & OriginalPath to preserve Document binding」), FileSize 만 새 값으로 바꿨다. 새 웹 판(atr_generator.js)은 MT 의 Name·Title·OriginalPath 를 회로 이름으로 **바꾼다**. 문서와 사진 파일의 연결이 끊기면 FLIR 가 문서 안 사본만 쓰는 것일 수 있다. 또 JSON.parse 로 읽은 64비트 정수(CreationTimeUtcLong·LastWriteTimeUtcLong)가 부동소수로 반올림되어 값이 바뀐다(5250958105167387904 → …88000). 정확한 값 그대로 써야 한다(BigInt 또는 문자열 치환).

[할 일 — 이 순서로, 단계마다 사용자가 FLIR 로 열어 확인할 .atr 을 만들어 준다]
0. 먼저 사용자가 이미 받은 확인 파일을 연다: apps/thermal-reporter/samples/atr_test2/A_옛PC방식_사진3장(s1_s3_s4).atr (예전 PC 방식 그대로 만든 것, README 참고). 이 결과로 3번 가설이 맞는지 판단한다(사용자가 알려 줄 것).
1. 연결 방식 되돌리기(가설 3 시험): MT.bin 의 Name·Title·OriginalPath 는 양식 그대로 두고 FileSize·LastWriteTimeUtcLong 만 새 값(정수 그대로, 반올림 없이)으로 바꾼 .atr 을 만든다(samples/atr_test2/B_연결유지.atr, 실제 사진 samples\real 8장). 회로 이름은 나중에 문서 글자로만 바꾼다. 이것으로 FLIR 가 새 사진을 보이는지 사용자가 확인한다.
2. 안 보이면(문서 안 사본이 그려지는 것이면): **문서 안 쪽마다 사진 사본 4장을 새 사진으로 바꾼다.**
   - 쪽 시작 위치 AtrGenerator.PAGE_OFFSETS(양식 기준, 쪽 줄이기 전)를 쓰고, 쪽 블록 안에서 PNG 서명(89 50 4E 47)과 JPEG 서명(FF D8 FF)을 찾아 위 4장을 구분한다(앞 u32 가 그림 길이와 맞는 것).
   - 새 그림 만들기: ① 실화상 JPEG = 새 사진의 실화상(flir_parser.js 가 FLIR 조각 이어 붙인 자료에서 추출한 것, 없으면 열화상으로 대신) ② 열화상 320×240 JPEG = 새 사진 파일에서 열화상 부분을 같은 해상도·같은 압축 방식으로 ③ 실화상 잘라낸 320×240 = 실화상 가운데를 4:3 으로 잘라 줄인 것 ④ 오른쪽 PNG = 새 눈금 최고·최저 온도(사진 안 온도 자료에서 계산)와 스팟 3점 십자·「Sp1」「Sp2」「Sp3」 글자를 투명/검정 바탕에 그린 690×517 PNG(양식의 것과 같은 모양).
   - 바꾼 그림 앞의 u32 길이 칸을 새 길이로 고친다. 쪽 블록 길이가 바뀌므로 그 뒤 쪽들의 위치가 밀린다 → 쪽을 한 쪽씩 순서대로 조립(앞 쪽 블록 + 새 쪽 블록 + …)하고, 쪽 블록 바깥에 길이/위치를 적어 둔 칸이 있는지 확인한다(없으면 문서 전체 길이 칸도 없는 것으로 보임 — 양식에서 u32 값 중 쪽 블록 크기·위치와 같은 값이 있는지 전수 검색해서 확인할 것).
3. 표 글자 바꾸기(쪽마다): 「측정대상」 칸(회로 이름), Point 1·Point 2·Point 3 온도(「28.9 °C」 형식, 소수 첫째 자리와 °C), 온도차, 판정(정상/요주의) 글자를 새 값으로. 글자 앞 길이 칸 갱신. 양식 1쪽 글자 위치는 문서에서 「측정부위」「Point 1」「온도측정」 글자 근처의 같은 모양 글자 묶음으로 찾는다. 판정 기준: 온도차 5℃ 이하 정상, 5℃ 초과~10℃ 미만 요주의, 10℃ 이상 이상(양식의 판정 표와 같음).
4. 쪽 이름: 쪽 제목·목록에 보이는 이름도 회로 이름으로 (현재 MT 이름 필드 방식 유지 또는 1단계 결과에 맞게).
5. 길이 칸 전수 검증(지시 4 의 함수)을 새 항목(그림 길이, 표 글자)에도 적용한다. 쪽 수 1·3·8, 그리고 10장 넣었을 때(앞 8쪽만 담김)를 모두.
6. 각 단계의 .atr 은 samples/atr_test2/ 에 이름과 설명(README)으로 남겨 사용자가 FLIR 로 열어 볼 수 있게 한다. Claude 는 FLIR 를 직접 열 수 없고, FLIR 공식 부품으로 문서를 읽는 시도(Cactus.Common HashStore ReadClass)는 「Hash collision for type: Serialize」 오류로 막혀 있다. 열 수 있게 되면(DLL 선택을 줄이는 등) 자동 시험에 쓴다.
