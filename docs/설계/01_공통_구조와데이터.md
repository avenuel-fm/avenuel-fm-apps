# 공통 · 구조와 데이터

- 판: **v1.12** · 수정 2026-11-05 · 공통 규격 v1.12
- 담은 장: 1 용어 · 2 구조 · 3 데이터 주인 · 4 ID · 6 공통 DB · 8 앱 간 통로
- **이럴 때 읽기**: 앱 사이에 데이터를 주고받거나, 공통 DB·ID·종류 코드를 다룰 때
- 목차·읽는 법: `claude/설계/00_목차_읽는법.md`

> **요약**
> - 데이터마다 주인 앱은 하나. 다른 앱 DB는 **읽기만**, 알릴 일은 공통 DB **색인**에 적는다 (R1~R6)
> - 공유 탭은 **덧붙이기만 · 자기 줄만 · 지우지 않기 · 열 이름으로 읽기** (W1~W6)
> - ID: `{앱}-{종류}-{YYYYMMDD}-{###}`, 사진 `PH-{앱}-…`. 새 종류 코드는 4장 등록부에 먼저 적는다
> - 매장 ID(UUID)·문서번호(`에비뉴엘컨펌_###_YYMMDD`)는 DW만 만들고 다른 앱은 그대로 참조
> - 공통 DB는 `cdb` 함수로만, 서버끼리 API는 `ping`·`summary`만

---

## 1. 목적 · 범위 · 용어

### 1.1 목적
- 시설팀 업무를 **앱(블럭)** 단위로 전산화합니다. 모든 문서와 사진은 **한 곳에서 검색**할 수 있어야 합니다.
- 앱은 각자 따로 고치고 배포할 수 있어야 합니다. 그러면서도 **같은 직원, 같은 매장, 같은 이름 규칙, 같은 디자인**을 씁니다.
- 앱이 늘어나도 구조가 흔들리지 않도록 **데이터 주인, 통로, 이름, 버전** 규칙을 먼저 고정합니다.

### 1.2 용어
| 용어 | 뜻 |
|---|---|
| 앱(블럭) | Apps Script 웹앱 하나와 그 앱의 전용 DB 시트 하나 |
| 공통 DB | `00_공통DB_통합대시보드`. HUB가 주인이고, 모든 앱이 정해진 규칙으로 읽고 씁니다 |
| 앱 DB | 각 앱의 전용 시트. 그 앱만 씁니다 |
| 색인 | 공통 DB의 `문서색인_연도`, `사진색인_연도`. 통합 검색과 앱 간 알림에 씁니다 |
| 입장표 | 앱 사이를 PIN 없이 옮길 때 주소에 붙이는 5분짜리 표 (`?t=`) |
| 기기 표 | 로그인 후 기기에 30일 동안 저장하는 표 |
| 공통 틀 | 모든 앱이 복사해서 쓰는 공통 코드: 디자인, 로그인, 공통 DB 함수, 사진, 검색키, PDF 대기 |

### 2.3 통로 원칙 (가장 중요)
| # | 원칙 |
|---|---|
| R1 | **데이터마다 주인 앱은 하나**입니다. 주인만 만들고 고칩니다 (3장 표) |
| R2 | 앱 사이 데이터의 **기본 통로는 공통 DB 직접 읽기·쓰기**입니다 (`SpreadsheetApp.openById`). 모든 앱이 같은 시설팀 계정으로 실행되므로 가능합니다 |
| R3 | **다른 앱의 전용 DB는 읽기만** 합니다. 다른 앱에 알릴 일은 공통 DB **색인**에 기록하고, 받는 앱이 읽습니다 |
| R4 | 서버끼리 부르는 API는 **HUB 요약 카드(`summary`)와 상태 확인(`ping`)만** 둡니다. 기존 DW API는 호환용으로만 남깁니다 |
| R5 | 공통 DB는 **공통 틀의 `cdb` 함수로만** 다룹니다. 앱 코드에 열 번호를 직접 쓰지 않습니다 |
| R6 | 다른 앱을 읽지 못해도 **자기 기능은 계속 동작**해야 합니다. 대기 후 다시 시도합니다 |

## 3. 데이터 주인과 접근 규칙

### 3.1 주인 · 접근 표
| 데이터 | 주인 | HUB | DW | WS | 새 앱 |
|---|---|---|---|---|---|
| 정보·직원·파트·앱목록·검색사전·공지 | HUB | 쓰기 | 읽기 | 읽기 | 읽기 |
| 문서색인_YYYY | **줄마다 그 줄을 만든 앱** (`app_id`) | 읽기 | 자기 줄 쓰기 | 자기 줄 쓰기 | 자기 줄 쓰기 |
| 사진색인_YYYY | 줄마다 만든 앱 | 읽기 | 자기 줄 쓰기 | 자기 줄 쓰기 | 자기 줄 쓰기 |
| 변경이력 · 오류기록 | 모두 (덧붙이기만) | 덧붙이기 | 덧붙이기 | 덧붙이기 | 덧붙이기 |
| **주소록** | HUB (고치기·삭제는 HUB 관리 화면) | 쓰기 | 읽기 + 새 시공업체 덧붙이기 | 읽기 + 새 시공업체 덧붙이기 | 읽기 + 덧붙이기 |
| **매장 · 문서번호** (DW `매장` 탭) | **DW** | 읽기 | 쓰기 | 읽기 | 읽기 |
| DW 검토서·서명 등 | DW | — | 쓰기 | — | — |
| WS 일정·작업기록·하자 등 | WS | — | — | 쓰기 | — |

### 3.2 공유 탭 쓰기 규칙 (앱끼리 잠금이 통하지 않기 때문)
- Apps Script의 잠금(`LockService`)은 **앱(스크립트)마다 따로** 걸립니다. 그래서 DW와 WS가 공통 DB에 동시에 쓰면 서로를 막지 못합니다.
- 그래서 공통 DB의 공유 탭에는 아래 방식으로만 씁니다.

| 규칙 | 방법 |
|---|---|
| W1 새 줄은 **덧붙이기만** 합니다 | 여러 줄은 Sheets 고급 서비스 `Values.append`로 씁니다. 시트 서버가 끝 줄을 찾아 붙이므로 겹치지 않습니다. 한 줄은 `appendRow`로 씁니다. **`getLastRow()+1` 위치에 직접 쓰지 않습니다** (동시에 쓰면 덮어씀) |
| W2 **자기 줄만** 고칩니다 | `app_id`가 자기인 줄만 고칩니다. ID로 줄을 찾고(`TextFinder`), 그 줄만 바꿉니다 |
| W3 줄을 **지우거나 정렬하지 않습니다** | 지울 때는 `삭제여부=Y`로 표시합니다. 사람도 시트를 정렬하지 않습니다. 보기용으로는 "필터 보기"만 씁니다. 공유 탭에는 시트 보호를 겁니다 |
| W4 **탭은 HUB만 만듭니다** | 다음 해 탭(`문서색인_2027` 등)은 HUB가 12월 1일 예약 작업으로 미리 만듭니다. 탭이 없으면 앱은 자기 `색인대기` 탭에 두고 `오류기록`을 남깁니다 |
| W5 **열 이름으로 읽습니다** | 머리줄 이름으로 열 위치를 찾습니다. 새 열은 **맨 오른쪽에만** 추가합니다. 열 이름과 순서는 바꾸지 않습니다 |
| W6 **버전을 확인합니다** | 공통 DB `정보` 탭의 `스키마버전`이 앱이 아는 버전보다 높으면, 앱은 계속 동작하되 HUB에 "공통 틀 갱신 필요"를 표시합니다 |

### 3.3 앱 DB 규칙
- **시트 값은 모두 글자로 쓰고 읽습니다 (결정 54, 모든 앱 필수).** 구글 시트는 `2026-11`, `2026-11-04 23:05`, `0012` 같은 글자를 날짜·숫자로 바꿔 저장합니다. 칸을 글자 형식(`@`)으로 지정해도 `appendRow`·`setValues`로 쓰면 바뀝니다.
  - 쓸 때: 모든 값 앞에 `'`를 붙입니다(`asText_`). 시트 화면에는 `'`가 보이지 않고 글자 그대로 남습니다. `=`로 시작하는 글자가 수식이 되는 것도 막습니다. 줄 하나를 한 번에 쓰는 방식은 그대로입니다.
  - 읽을 때: 날짜·숫자로 바뀐 칸은 열 이름에 맞춰 글자로 되돌립니다(`cellOut_`: `연월` → `yyyy-MM`, 그 밖의 날짜 → `yyyy-MM-dd HH:mm`). 예전에 바뀌어 저장된 줄도 그대로 맞게 셉니다.
  - 시트 메뉴 「데이터 점검」으로 바뀐 칸·빈 필수 칸을 찾고 고칩니다.
  - 시험용 가짜 시트도 진짜처럼 날짜·숫자로 바꾸게 만들어 시험합니다(WS `test/mock_env.js`).
- 앱 DB는 그 앱의 잠금으로 보호합니다. 번호 매기기와 여러 줄 쓰기는 `LockService.getScriptLock()` 안에서 합니다.
- 필수 탭: `설정`, `변경기록`, `색인대기`. 그 밖의 탭은 앱이 정합니다.
- 시트 열을 추가할 때는 버전이 바뀔 때 한 번 자동으로 합니다 (`SCHEMA_VER`). 이 규칙은 DW v1.8에서 이미 쓰고 있습니다.

## 4. 식별자(ID)
| 대상 | 형식 | 예 | 만드는 곳 |
|---|---|---|---|
| 직원 | `S###` | `S001` | HUB |
| 파트 | `P##` | `P01` | HUB |
| **매장 ID** | DW가 만든 값 그대로 (UUID 36자) | `3f2a…-…` | DW만 만듭니다 |
| **문서번호** | DW 형식 그대로 `에비뉴엘컨펌_###_YYMMDD` | `에비뉴엘컨펌_002_261010` | DW만 만듭니다 |
| 문서·작업 | `{앱}-{종류}-{YYYYMMDD}-{###}` | `WS-WL-20261101-003` | 각 앱이 자기 잠금으로 만듭니다 |
| DW 검토서 (색인용) | `DW-RV-{최초등록일 YYYYMMDD}-{일련번호}-R{차수}` | `DW-RV-20261010-002-R2` | DW. 원래 문서번호는 `원본_ref`에 둡니다 |
| 사진 | `PH-{앱}-{YYYYMMDD}-{####}` | `PH-WS-20261101-0042` | 각 앱이 자기 잠금으로 만듭니다 |

- 이 표에서 공통 규격 v1.0을 고친 곳이 두 군데 있습니다.
  - **매장·문서번호**: 공통 규격 예시 `ST2026-014 / DW-26-014`는 실제 DW와 다릅니다. 이미 출력물, QR, 시트에 쓰인 값이라 바꾸지 않습니다. 다른 앱은 **글자 그대로 참조**만 합니다.
  - **사진 ID**: 공통 규격 `PH-YYYYMMDD-####`는 모든 앱이 번호 하나를 같이 쓰는 방식입니다. 앱끼리 잠금이 통하지 않아(3.2) 번호가 겹칠 수 있으므로 앱 코드를 넣었습니다.
- **종류 코드 등록부** (새 종류는 여기에 먼저 등록합니다)

| 앱 | 코드 | 종류 |
|---|---|---|
| WS | `WL` | 작업일지 |
| WS | `PF` | 작업 사진 폴더 |
| WS | `DF` | 하자점검 |
| WS | `TB` | TBM |
| WS | `IN` | 점검표 |
| WS | `SC` | 일정 |
| WS | `FE` | 소화기 (QR 1장 = 1대) |
| WS | `FC` | 소화기 월 점검 1건 |
| WS | `SG` | 로그인 서명 (근무일 · 직원 1건) |
| DW | `RV` | 도면 검토서 |
- 날짜는 ID 안에서만 8자리(`20261101`)로 씁니다. 화면, 이름, 시트에서는 10자리(`2026-11-01`)로 씁니다.

| `직원` | staff_id, 이름, part_id, 파트명, 역할, 근무조, pin_hash, pin_salt, 이메일, 직인이미지ID, 사용여부, 수정일시, **PIN변경필요, PIN변경일시** |

- `주소록` 탭은 v1.2에서 새로 만든 탭입니다 (6.3).
- `직원`의 `PIN변경필요`, `PIN변경일시` 열은 **지우지 않습니다** (W5: 열 이름·순서 고정).
  - 직원이 PIN을 바꾸지 않으므로(7.1) `PIN변경필요`는 항상 `N`입니다.
  - `PIN변경일시`는 관리자가 PIN을 넣거나 바꾼 일시를 적습니다.
- WS v0.3이 제안한 `검색동의어` 탭은 `검색사전`이라는 이름으로 넣었습니다.
- **칩(자주 쓰는 낱말 버튼)은 각 앱의 `항목설정`에 둡니다.** 공통 DB에는 넣지 않습니다. 칩은 앱마다 다르고, 칩을 고치려고 공통 규격을 바꿀 일이 없게 하기 위해서입니다.

### 6.1 역할 (고정값)
`소장 / 부소장 / 파트장 / 직원 / 관리자`
- 관리자는 시스템 설정만 합니다. 결재 권한은 없습니다.

### 6.2 문서색인 `상태` (고정값)과 앱별 세부상태
- **공통 상태**: `작성중 · 제출 · 파트장확인 · 소장확인 · 발송 · 조치대기 · 완료 · 취소`
  - HUB 할 일과 통합 검색은 이 값만 봅니다.
- 앱 고유 상태는 `세부상태` 열에 적습니다.

| 앱 | 앱 상태 | 공통 상태 |
|---|---|---|
| DW | 협의중 | 제출 |
| DW | 컨펌완료 | 완료 (시설 소장 확인 여부는 `세부상태`에 "컨펌완료·소장확인"처럼 적음) |
| WS 작업일지 | 제출 → 파트장확인 → 소장확인 | 같음 |
| WS 하자점검 | 작성중 / 발송 / 조치중 / 완료 | 작성중 / 발송 / 조치대기 / 완료 |
| WS 일정 | 대기 / 진행중 / 완료 | 색인에 넣지 않음 (앱 안에서만) |

### 6.3 주소록 (v1.2 · 확정 2026-11-03)
메일을 보낼 때 받는 사람을 고르는 공용 주소록입니다. 하자 발송(WS), 원격 서명 요청·서류 요청(DW)이 함께 씁니다.

| 구분 | 저장 방식 | 화면에서 |
|---|---|---|
| **롯데쇼핑** | **그룹으로 묶어** 저장합니다. 그룹 예: 영업팀, 안전관리팀 (그룹은 관리 화면에서 추가) | 그룹 이름을 누르면 그 그룹 전원을 한 번에 고르고, 사람마다 빼거나 넣을 수 있음 |
| **시공업체** | **묶지 않고** 한 사람씩 저장만 합니다 (`그룹` 칸은 비움) | 회사명·이름·이메일로 검색해서 고름 |

- **처음 채우기**: HUB 관리 화면의 「주소록 불러오기」로 한 번 가져옵니다.
  - 지금까지 저장된 시공업체: DW `검토서`의 시공업체 이름·담당자·연락처·이메일 (같은 이메일은 하나로)
  - 롯데쇼핑 인원: DW 원격 서명에서 쓴 안전관리팀·영업팀 이메일
- **자동 추가**: 앱에서 새 시공업체 이메일로 메일을 보내면 `구분=시공업체`로 한 줄 덧붙입니다 (W1). 이미 있는 이메일이면 `최근사용일시`만 고칩니다. 이 칸은 앱이 고쳐도 됩니다(덮어써도 문제없는 값).
- **고치기·삭제**: HUB 관리 화면에서만 합니다. 삭제는 `사용여부=N`입니다 (W3).
- 롯데쇼핑 인원 추가와 그룹 정리는 소장·부소장·관리자가 합니다 (7.4).
- 주소록은 개인 연락처라 공통 DB와 함께 **비공개**입니다. 화면에는 로그인한 직원에게만 보입니다.
- `출처`: `DW검토서` / `DW서명` / `직접입력` / `앱발송`

## 8. 앱 간 통로

### 8.1 공통 DB 함수 `cdb` (공통 틀, 모든 앱에 같은 코드)
| 함수 | 하는 일 |
|---|---|
| `cdb.info()` | 스키마버전 확인 |
| `cdb.staff()` / `cdb.parts()` | 10분 캐시 |
| `cdb.apps()` | 앱 전환 메뉴용, 10분 캐시 |
| `cdb.dict()` | 검색사전, 10분 캐시 |
| `cdb.contacts()` | 주소록 (롯데쇼핑 그룹별 + 시공업체), 10분 캐시 (6.3) |
| `cdb.touchContact(email, info)` | 보낸 이메일이 없으면 시공업체로 덧붙이고, 있으면 최근사용일시만 고침 |
| `cdb.addDocs(rows)` | 색인 덧붙이기 (W1) |
| `cdb.updateDoc(docId, patch)` | 자기 줄만 고치기 (W2) |
| `cdb.addPhotos(rows)` | 사진색인 덧붙이기 |
| `cdb.markPhotosDeleted(ids)` | 사진 삭제 표시 |
| `cdb.findDocs({storeId, app, kind, from, to})` | 매장 이력, 다른 앱 문서 읽기 |
| `cdb.search(query, filter)` | 통합 검색 (10장) |
| `cdb.log(action, targetId, summary)` | 변경이력 |
| `cdb.error(kind, targetId, msg)` | 오류기록 |
| `cdb.flushPending()` | `색인대기`에 남은 것을 다시 쓰기. 앱 시작 때와 예약 작업 때 부름 |

- 한 번의 서버 호출에서는 공통 DB를 **한 번만 엽니다** (`openById`는 한 번에 0.3~1초 걸림).

### 8.2 다른 앱 데이터 읽기
| 읽는 앱 | 읽는 것 | 방법 |
|---|---|---|
| WS | DW 매장 목록 (위치 자동완성, 하자점검 만들기) | `openById(DW_DB_ID)`의 `매장` 탭, **머리줄 이름으로 읽음**, 5분 캐시 |
| DW | 이 매장의 하자 내역, 하자 발송 여부 | `cdb.findDocs({storeId, app:'WS', kind:'하자점검'})` |
| HUB | 매장 이력 | `cdb.findDocs({storeId})` |

- WS v0.3의 "DW 매장 행에 하자 발송 상태 직접 기록"은 **쓰지 않습니다** (R3).
  - WS가 발송하면 문서색인 상태를 `발송`으로 바꾸고, DW는 그것을 읽어 "하자 발송 ✓"로 표시합니다.
  - DW v1.8의 `POST defect` API는 호환용으로 남겨 둡니다.

### 8.3 서버끼리 API (모든 앱 필수)
| 통로 | 키 | 응답 |
|---|---|---|
| `GET ?api=ping` | 없음 | `{ok, app, title, version, specVersion, commonVersion}` |
| `GET ?api=summary&key=…[&year=&month=&part=]` | HUB_KEY | `{ok, app, counts:{…}, labels:{…}, todos:[{key, label, count, level:'pu'|'or'|'rd', role:[…], url}]}` |

- 오류 응답은 `{ok:false, error:'사유'}`입니다.
- HUB는 `UrlFetchApp.fetchAll`로 동시에 부릅니다. 제한 시간은 8초이고, 결과는 5분 캐시합니다.
- 실패하면 그 카드만 "연결 안 됨"으로 표시하고, 마지막 숫자를 회색으로 보여 줍니다.
- `todos.role`은 그 할 일을 볼 역할입니다. 예: 소장 확인 대기 → `['소장']`.

### 8.4 스크립트 속성 (모든 앱)
| 키 | 설명 |
|---|---|
| `COMMON_DB_ID` | 공통 DB |
| `APP_DB_ID` | 자기 앱 DB. 시트에 붙은 스크립트(DW)는 비워 두면 그 시트를 씀 |
| `HUB_KEY` | 32바이트 비밀키 (입장표, 기기 표, summary). **시트·화면·메일에 넣지 않습니다** |
| `DRIVE_ROOT_ID` · `THUMB_CACHE_FOLDER_ID` | 드라이브 |
| `DW_DB_ID` | DW를 읽는 앱만 |

- `HUB_KEY`를 바꾸면 모든 앱의 기기 표가 무효가 되어 전원이 다시 로그인합니다. 키 변경은 HUB 관리 화면 안내를 따라 모든 앱에서 같은 날 합니다.
