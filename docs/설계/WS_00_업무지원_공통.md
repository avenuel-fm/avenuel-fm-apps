### 15.3 WS 업무지원 v1.0 — 앱별 설계 (WS 설계정의서 v1.1 통합)

> WS 앱 전체에 걸친 것(구성·로그인·메인·화면·DB·통로·함수)만 여기에 둡니다. 기능별 상세는 `WS_작업기록.md`, `WS_하자점검.md`, `WS_소화기점검.md`에 있습니다.
> 공통 요소(로그인, ID, 이름, 폴더, 색인, 검색, 사진, PDF, 디자인)는 공통 문서(01~07)를 따릅니다.
> `WS-1`~`WS-8`은 `docs/수정요청_대기목록.md`의 **WS 구역** 항목 번호입니다.

#### 15.3.1 목적 · 범위
- **목적**: 하루 업무 흐름을 정해진 순서대로 처리하고, 결과를 **사진이 들어간 양식 PDF**로 남깁니다.
  - 흐름: 오늘 일정 → TBM → 작업 → 점검 → 하자점검
  - PDF는 웹에서 보고 PC에서 인쇄합니다.
  - 모든 문서와 사진은 HUB 통합 검색에서도 찾을 수 있습니다.
- **앱 정보**: 앱 코드 `WS`, 폴더 번호 `20`, 앱 DB `20_업무지원_DB`
  - 화면은 두 가지입니다: `/exec`(휴대폰), `/exec?view=pc`(PC 관리 화면)
- **다른 앱과의 관계**
  - HUB: 공통 DB의 주인이고 **직원·PIN 관리 화면을 소유**합니다. WS 요약 카드를 보여 줍니다.
  - DW: 매장 마스터의 주인입니다. WS는 DW `매장` 탭을 읽기만 합니다.

#### 15.3.3 로그인
| 경로 | 동작 |
|---|---|
| HUB 카드나 앱 전환으로 들어옴 | 입장표를 확인하고 기기 표를 발급한 뒤 주소에서 `t`를 지웁니다 (7.3) |
| 짧은 주소로 직접 들어옴 | 기기 표가 있으면 바로 메인, 없으면 PIN 팝업 |
| PIN | 본인의 개인 PIN입니다 (7.1). 같은 기기에서 5번 틀리면 5분 잠깁니다 |
| 위 막대 | 점명 · `업무지원` · 버전 / 앱 전환 ▾ / `이름 · 파트` 접속 중 / 로그아웃. **직원에게는 앱 전환 메뉴에 도면협의가 보이지 않습니다** (7.4) |
| 직원 정보 | `cdb.staff()`로 읽고 10분 캐시합니다 |

- 직원은 PIN을 바꿀 수 없습니다 (7.1).
- **HUB를 만들기 전 직원 관리 (결정 86, v0.6.8)**: WS 시트 `직원` 탭이 직원 목록입니다. 시트 메뉴로 관리합니다.
  - **② 직원 등록**: 이름 · PIN 4자리 · 파트명 · 역할. 예전 이름 「테스트 직원 등록」에서 「테스트」를 뺐습니다. 여기 넣는 직원은 **실제 직원**으로, 본 버전에서도 그대로 씁니다.
  - **⑦ 직원 삭제**: 이름이나 staff_id를 넣고 「예」를 누르면 `사용여부=N`이 됩니다. 줄은 지우지 않습니다(W 규칙, 결정 10). 그래서 서명·TBM·점검 기록의 이름은 그대로 남습니다. 삭제하는 즉시 그 직원은 로그인할 수 없고, 쓰던 기기도 다음 화면에서 로그아웃됩니다. 그 PIN은 다른 직원이 다시 쓸 수 있습니다. 이름이 같은 직원이 둘 이상이면 staff_id로 고릅니다.
  - **⑧ 직원 PIN 바꾸기 (결정 94, v0.7.3)**: 이름이나 staff_id → 새 PIN 4자리. 다른 직원이 쓰는 PIN은 거부합니다. 새 암호(salt)로 다시 저장하므로 그 직원이 쓰던 기기는 로그아웃되고 새 PIN으로 다시 로그인합니다(서명은 근무일 규칙 그대로). 직원 본인은 PIN을 바꿀 수 없고(7.1), 관리자가 시트에서만 바꿉니다.
  - **본 버전으로 옮길 때**: HUB를 만들면 이 줄들을 공통 DB `직원` 탭(01 6장)으로 **그대로** 옮깁니다. 옮기는 열은 `staff_id`(`S###`) · 이름 · 파트명 · 역할 · `pin_hash` · `pin_salt` · 사용여부입니다. 그러면 직원은 PIN·서명을 다시 넣지 않고, 기록의 `staff_id`도 이어집니다. 그래서 **PIN 암호화 방식(`hashPin_`)과 `staff_id` 번호는 바꾸지 않습니다.** 공통 DB에만 있는 열(part_id · 근무조 · 이메일 · 직인 등)은 HUB에서 채웁니다.

#### 15.3.4 메인 (휴대폰 첫 화면)
- **테스트판 문구 (결정 102, v0.9.2)**: 메인 맨 위 회색 띠는 「이 버전은 테스트판 입니다. v0.9.2」처럼 **버전만** 보여 줍니다(버전은 서버 `APP.version`).
- **환경설정 (결정 102, v0.9.2 → v0.9.3)**: 역할 **`소장`에게만** 메인 메뉴 **맨 아래 오른쪽**에 [환경설정] (왼쪽은 「어둡게/밝게」). 다른 사람에게는 안 보이고, 서버 함수도 소장만 받음(`bossOnly_`).
  - 알림 표시 시간: 1 · 1.5 · 2 · 2.6(기본) · 3 · 4 · 5초. `설정` 탭 `알림표시초`에 저장 → 모든 직원에게 다음 접속부터.
  - 직원 추가(이름·파트·역할·PIN) · 편집(이름·파트·역할) · PIN 변경 · 삭제(`사용여부=N`). 시트 메뉴 ②·⑦·⑧과 같은 규칙(남의 PIN 거부, PIN 바꾸면 그 직원 기기 로그아웃).
  - 내 계정은 삭제할 수 없고 내 역할은 바꿀 수 없음(환경설정을 잃지 않게). `변경기록`의 「누가」에 그 소장 이름.
- **오늘 일정**
  - WS `일정` 탭에서 오늘 내 일과 우리 파트 일을 시간순으로 보여 줍니다.
  - 누르면 작업 기록 화면이 열리고 분류·작업명·위치·`store_id`·`연결_task_id`가 미리 채워집니다.
  - 제출하면 그 일정은 `완료`로 바뀝니다.
- **메뉴 2×3**
  ```
  [ 서류작업 ] [ 작업 ]     ← 서류작업 안에 TBM·명일 작업 예정 (`WS_서류작업.md`)
  [ 점검 ]     [ 일정 ]
  [ 하자점검 ] [ 결재 대기 / 내 문서 ]
  ```
  - 6번째 칸은 역할마다 다릅니다.
    - 파트장·소장·부소장: **결재 대기** (내 차례 건수 배지)
    - 직원: **내 문서** (내 문서 상태와 임시 저장 기록)
  - **시험 기간 표시 (결정 84, v0.6.7)**: 아직 기능이 없는 4칸(작업 · 일정 · 하자점검 · 결재 대기/내 문서)은 이름을 **「작업중」**으로 보여 줍니다(아래 작은 글씨 「준비 중」, 누르면 「준비 중」 안내). 동작하는 칸은 **서류작업 · 점검** 둘. 기능이 생기는 칸부터 위 원래 이름으로 되돌립니다.
- 그 밖에 진행률, 공지(`공지.대상앱`이 WS 또는 전체), 하단 탭(홈 / 문서함 / 검색)이 있습니다.
- 주요 버튼은 한 손으로 쓰기 쉽게 화면 아래쪽에 둡니다.

#### 15.3.13 WS 앱 DB `20_업무지원_DB`
| 탭 | 열 | 비고 |
|---|---|---|
| 설정 | 키, 값, 설명 (`SLIDES_TEMPLATE_WL`, `SLIDES_TEMPLATE_DF`, `FOLDER_CACHE_JSON` …) | 필수. 비밀키는 넣지 않음 |
| 변경기록 | 일시, 누가, 무엇을, 대상ID, 문서번호, 내용 | 필수 (DW 형식) |
| 색인대기 | 공통 DB에 못 쓴 색인 줄 | 필수. `cdb.flushPending()` |
| 항목설정 | 분류, item_id, 항목명, form_id, 사진칸구성, 자주쓰는칩목록, 표시순서, 사용여부 | |
| 일정 | task_id, 날짜, 시각, 분류, 업무명, 위치, store_id, 대상파트, 담당_staff_id, 상태(대기/진행중/완료), 연결_log_id | 색인에 넣지 않음 |
| 작업기록 | log_id, 작업일, 분류, 항목명, 작업명, 위치, store_id, staff_id, 작성자명, 파트명, 작업내용, 특이사항, 사진수, folder_id, pdf_id, 상태, 파트장확인자, 파트장확인일시, 소장확인자, 소장확인일시, 연결_task_id, 작성시각, 수정시각, PDF상태, PDF시도횟수 | |
| 하자점검 · 하자항목 | `WS_하자점검.md` | 열 정의는 기능 문서에 |
| 소화기 · 소화기점검 | `WS_소화기점검.md` | 열 정의는 기능 문서에 |

- 번호 매기기와 여러 줄 쓰기는 `LockService.getScriptLock()` 안에서 합니다.
- 열 추가는 `SCHEMA_VER`로 버전이 바뀔 때 한 번 자동으로 합니다.
- 공통 DB 접근은 3장·8.1을 따릅니다. WS는 `app_id=WS`인 줄만 덧붙이고 고칩니다.
- 드라이브 경로는 5.2를 따릅니다. 외부 공유는 하자 통보서 PDF만입니다.
