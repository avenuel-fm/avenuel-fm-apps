#### 15.3.18 서류작업

**1. 메뉴**
```
메인 2×3 첫 칸 [서류작업] (예전 [TBM])
  ├─ TBM               ← 이 문서 2~6장
  ├─ 명일 작업 예정     ← 9장 (양식 받음, 코딩 전)
  ├─ 출근현황           ← `WS_출근현황.md` (15.3.19, 설계 중)
  └─ (그 밖의 서류)     ← 추가될 때마다 이 문서에 장 추가
```
- 메인 배치: `[서류작업] [작업] / [점검] [일정] / [하자점검] [결재 대기·내 문서]` (15.3.4)

**2. 로그인 서명 — 매일 첫 로그인 (결정 56)**
1. PIN 4자리 → 맞고 오늘 서명이 없으면 **서명 칸**(가로로 넓은 칸, 휴대폰 가로 폭 가득). 칸 가운데에 **본인 이름을 연회색 굵은 글자**로 깔고 그 위에 따라 씀 (소화기 손글씨 칸과 같은 모양, 결정 46).
2. [지우기]로 다시 쓰기. **너무 짧게 그은 서명은 받지 않음**(소화기 칸과 같은 기준) (개선 A).
3. [서명하고 로그인] → 서명 그림을 **가로 600px 흑백 PNG**(흰 바탕·검은 글씨만, 보통 10KB 안팎)로 줄여 드라이브에 저장하고 WS `서명` 탭에는 **파일 번호만** 한 줄. 그 뒤 기기 표 발급(02 7.2). 로그인이 느려지지 않게 하려는 것 (결정 60).
   - **서명하지 않으면 로그인되지 않습니다.** 건너뛰기 버튼 없음. [PIN 다시]로 처음 화면만 돌아감 (결정 60).
4. **그날 이미 서명했으면 다시 묻지 않음**: 같은 근무일에 다른 기기·새로고침·입장표(`?t=`)로 들어와도 PIN만(또는 입장표만)으로 들어감 (개선 B).
5. **근무일**: **오전 6시 시작**. 오전 6시~다음 날 오전 5시 59분 = 같은 근무일(출근은 8시까지지만 일찍 오는 직원 고려). 기기 표 만료도 다음 오전 6시라 경계가 같음 (결정 60). 예: 11월 5일 06:10 로그인 → 11월 5일 근무일, 11월 5일 05:30 로그인 → 11월 4일 근무일.
6. 혹시 기기 표는 살아 있는데 오늘 서명 줄이 없으면(시트에서 지운 경우 등) 메인 대신 서명 칸이 뜸 (`signToday`).
- 서명은 **TBM 서명용**입니다. 결재 직인(`직원.직인이미지ID`, 11.3)과는 따로입니다.

**3. 서명 저장**
| 항목 | 규칙 |
|---|---|
| 드라이브 | `시설팀 통합업무/20_업무지원/서류작업/서명/{YYYY-MM}/{YYYY-MM-DD}_서명-{이름}.png` (날짜 = 근무일) |
| WS `서명` 탭 | sign_id(`WS-SG-YYYYMMDD-###`), 근무일, staff_id, 이름, 파트명, 서명_id(파일), 서명시각, 들어온길(PIN/입장표), TBM사용(Y/N), 삭제여부 |
| 하루 한 번 | 같은 근무일·같은 직원 줄이 있으면 새로 받지 않음 |
| 보관 (개선 C) | **TBM PDF에 쓰인 서명은 계속 보관**. 쓰이지 않은 서명은 **90일 뒤 휴지통**(매일 새벽 예약 작업, `삭제여부=Y`) |
| 종류 코드 | `SG` 서명 (01 4장 등록부) |

**4. TBM 서명란 — 로그인한 순서대로 (결정 56)**
- 서명란은 **미리 채우지 않습니다.** 그날 `서명` 탭에 쌓인 줄을 **서명시각 순서대로** 읽어 1번 칸부터 채웁니다.
- **그날 로그인한 직원만** 들어갑니다. **파트 구분 없이 전 직원 섞어서** 순서대로입니다.
- TBM 화면을 연 뒤에 로그인한 사람도, TBM을 다시 열거나 [새로고침]하면 다음 칸에 들어갑니다. 늦게 받아도 저장만 되어 있으면 됩니다.
- 서명란은 **20칸(4줄×5칸)**. 주간 근무자는 16명 안팎이라 다음 쪽은 만들지 않음 (결정 66 → 72로 고침, 전: 28칸). 21번째부터는 PDF에 넣지 않음.
- **로그인(서명) 시각**(예: `07:42`)은 **앱 화면에만** 작게 표시. PDF에는 넣지 않음 (결정 60 → 66으로 고침).
- v0.4.0 화면: [서류작업 → TBM]에 오늘 근무일 서명 목록(순번·이름·파트·시각·서명 그림)과 [새로고침]. 사진·PDF는 양식 받은 뒤.

**4-1. TBM 양식 — PDF에 채우는 규칙 (11-06 양식 받음, 결정 66)**
- 원본: `docs/양식/WS_TBM_양식_1평가표.png`·`_2사진.png`(빈 양식), `WS_TBM_작성예_*.webp`(손으로 쓴 예). 시안: `docs/양식/WS_TBM_시안_1.png`·`_2.png`.
- PDF = **A4 가로 2쪽**. 출력하면 양식과 같은 모양.

| 1쪽 「[TBM 실시 및 위험성 평가표]」 | 채우는 값 |
|---|---|
| 사업소명 | `잠실점 에비뉴엘` (고정) |
| 작업 일시 | 근무일, `YY.MM.DD` (예: `26.11.06`) |
| 작업인원 | 서명란에 들어간 사람 수 (`11 명`) |
| 관리감독자/책임자 | 그날 서명한 사람 중 **역할=소장**의 이름 + 서명. 서명 그림은 양식의 「(서명)」 자리(칸 오른쪽)에 넣고 「(서명)」 글자는 지움(11-07, v0.6.6). 소장이 없으면 **역할=부소장**. 둘 다 없으면 비움(PDF는 만듦). 이름이 아니라 직원 시트 `역할` 칸으로 찾음 |
| 위쪽 체크 칸 (사다리·비계·우마·테이블리프트(렌탈)·크레인·스카이·달비계·용접기) | 작업 표 작업내용에 그 낱말이 있으면 `○`, 앱에서 고침 |
| 작업 표 (기본 8줄, 결정 72) | 작업위치·작업내용 = **그 근무일 날짜의 명일 작업 예정**(9장 `명일작업` 탭)에서 가져옴. 인원 = 그 줄 부서(=파트)의 출근(그날 서명) 인원. 위험요인·재해형태·위험성·안전보건 개선조치 = 4-2 방식. 모두 **앱에서 고칠 수 있음** |
| 서명란 (4줄×5칸, 결정 72) | 로그인 순서대로 **세로 먼저**(1줄 위→아래 5칸, 다음 줄). 이름 칸 = 글자, (인) 칸 = 로그인 서명 그림(「(인)」 글자는 지움). 빈 칸은 「(인)」 그대로. **관리감독자도 서명란에 들어감**, 함께 서명한 부소장은 서명란에만 |

| 2쪽 「■ 「TBM 실시 사진」」 | 채우는 값 |
|---|---|
| 날짜 | `YYYY년 M 월 D 일` (근무일) |
| 사진 2칸 (나란히) | 왼쪽 회의 사진, 오른쪽 구호 사진. 공통 규칙: 가로 4:3, 자르지 않고 줄여 넣기, 남는 곳 연회색(9.3). 사진에 날짜 글자 안 넣음 |

- **정한 것 (11-06 확인)**
  1. 부서 = 파트(명일 작업 예정 부서가 전방파트·기건파트, 결정 68). 소장·부소장은 부서 인원에 넣지 않음
  2. 같은 부서 줄이 여러 개면 줄마다 그 부서 출근 인원 전체
  3. 작업 표는 기본 **8줄**(결정 72, 전: 6줄). **8줄을 넘으면 줄을 더하고, 표 전체 높이는 그대로 두고 줄 높이·글자 크기를 줄임**(글자 최소 6.5pt). 시안 `WS_TBM_시안_1_8줄.png`
  4. 위쪽 체크 칸: 작업내용에 그 낱말이 있으면 자동 `○`, 앱에서 눌러 바꿈
  5. **쪽마다 아래 가운데 쪽 번호** `- 1 / 2 -`
- 시안: `WS_TBM_시안_1.png`(6줄), `_1_8줄.png`, `_2.png`(사진), `_입력화면.png`(휴대폰)

**4-2. 위험성 입력 방식 (11-06 정함, 결정 70)** — 시안 `WS_TBM_시안_입력화면.png`
- 직원은 **고르기만** 하고, 나머지는 자동으로 채움. 모두 고칠 수 있음.
  1. **위험요인** = 목록에서 고르기. 작업내용에 「사다리」 같은 낱말이 있으면 맞는 위험요인을 **자동으로 미리 골라 둠**
  2. **재해형태** = 위험요인에 묶인 값이 자동으로 들어감 (고용노동부 분류 말: 떨어짐·넘어짐·맞음·끼임·부딪힘·감전·화재·절단·베임 등)
  3. **위험성** = 가능성(1~3) × 중대성(1~3), 위험요인에 묶인 기본값이 자동. 직원이 숫자를 눌러 바꿀 수 있음. **1~2 하 · 3~4 중 · 6~9 상**. PDF에는 `6 (상)`
  4. **안전보건 개선조치** = 위험요인에 묶인 자주 쓰는 문구를 **여러 개 골라 넣기**(기본 문구는 미리 체크) + [직접 쓰기]. PDF에는 ` / `로 이어 씀
- **목록 관리**: WS 시트 새 탭 `위험성목록` (낱말 · 위험요인 · 재해형태 · 가능성 · 중대성 · 개선조치1~4 · 사용여부). 소장이 시트에서 줄을 더하고 고치면 앱에 바로 반영(코드 수정 없음). 첫 목록은 4-3 (시트 메뉴로 한 번에 넣음)
- 낱말 맞추기: 작업내용에서 목록을 위에서부터 보고 **처음 맞는 줄**을 고름. 맞는 줄이 없으면 맨 아래 「(기본)」 줄
- `위험성목록` 탭 열: 순서, 낱말(쉼표로 여러 개), 위험요인, 재해형태, 가능성, 중대성, 개선조치1~4(앞에 `✓`면 미리 체크), 사용여부

**4-3. 첫 위험성 목록 (11-06 확정, 결정 70)**
- 사용자가 받은 예시(사다리·비계·우마·고소작업대·크레인·용접·그라인더) + 시설팀 작업. 11-06 사용자 확정. 시트에서 언제든 고침(현장 안전 담당 확인 권장).

**5. TBM 작성 · PDF (결정 58·66)**
1. [서류작업 → TBM] → 오늘(근무일) TBM. 사진 버튼은 [📷 카메라] [📂 파일] (결정 72). 위에 서명란 미리보기(로그인 순서), 작업 표(명일 작업 예정에서 가져옴, 고치기·목록 고르기), 아래 사진 칸 2개: **회의 사진 · 구호 사진** (가로 4:3, 9.3). 사진은 **카메라 또는 파일 고르기** 둘 다 (결정 66).
2. [저장] → 사진 2장과 작업 표를 저장(TBM 탭 한 줄). **이때 PDF는 만들지 않습니다** (결정 58, 11-05 수정).
3. 서명이 늦게 들어와도 됩니다. 화면의 서명 목록에서 다 들어왔는지 확인합니다.
4. **[PDF로 저장]** (따로 있는 버튼) → 고친 내용이 있으면 먼저 저장 → 4-1의 규칙대로 2쪽을 채워 PDF로 저장(그 시각까지의 서명). **PDF는 휴대폰 화면에서 만듦**(도면협의 검토서와 같은 html2pdf, A4 가로 1123×794px) → 서버는 드라이브에 저장만. Slides 템플릿(11.1)은 쓰지 않음. 사진이 비어 있으면 묻고 진행. 이때 쓰인 서명은 `TBM사용=Y`. 출력은 이 PDF로.
5. 저장: `시설팀 통합업무/20_업무지원/서류작업/TBM/{YYYY}/{YYYY-MM}/{YYYY-MM-DD}_TBM.pdf`. 문서색인 1줄(`WS-TB-…`, 4장).
6. **PDF를 저장하면 버튼이 [PDF 열기]로 바뀜** — 눌러서 새 창에서 드라이브 PDF를 봄. 그 뒤 고치거나 서명이 더 들어오면 다시 [PDF로 저장] (결정 72)
7. **PDF로 저장한 뒤 서명이 더 들어오면** 「PDF 뒤 서명 n명 추가」 표시 → [PDF로 저장]을 다시 누르면 같은 이름으로 새로 만들고 예전 PDF는 휴지통.

**9. 명일 작업 예정 (11-06 새 양식 v2 · 업무지원 v0.5.0 배포)**
- 양식: **`docs/양식/WS_명일작업예정_양식_v2.png`** (11-06, 기준). 예전 양식 `WS_명일작업예정_양식.png`는 참고용
- **양식 모양 (v2)**
  - 제목 「■ 에비뉴엘 시설팀 명일 작업 일정 현황」, 일자 `YYYY 년 MM 월 DD 일` (년·월·일 칸)
  - 표 열: 구분(「㈜맥서브 에비뉴엘 잠실점」 세로 합친 칸) | **순번(따로 한 칸)** | 부서 | 작업장소 | 작업 내용 | 비고
  - 작업장소는 「2층,3층,4층」처럼 **여러 곳**을 한 칸에 씀
  - 위험 작업 줄은 **순번까지** 그 줄 글자 모두 빨간색
  - 아래 안내: 「※ 사다리, 위험물작업(용접·페인트) 작업은 빨간색으로 표시」
- **사용자 요구 (11-05)**: 부서·작업장소·작업 내용·비고 입력·수정 / 「고소작업·사다리·용접」 들어가면 빨간 글자 / 작성한 양식 이미지 저장
- **사용자 요구 (11-06, 결정 68)**: 새 양식 v2 / 엑셀 모양 대신 **도면협의 앱 디자인**(파스텔 색, 둥근 모서리) / **휴대폰·PC 둘 다 입력** / 부서 = 전방파트·기건파트 / 일자 = 작성일 다음 날
- **정한 것 (결정 62, 11-06 결정 68로 고친 곳 표시)** — 코딩은 「진행시켜」 뒤
  1. **빨간색 범위 = 그 줄 전체** (순번·부서·작업장소·작업 내용·비고, 양식 v2와 같음)
  2. **단어를 찾는 칸 = 작업 내용 + 비고** (둘 중 한 곳에만 있어도 그 줄 전체 빨간색)
  3. **빨간 단어 = 고소작업 · 사다리 · 용접 · 페인트** (4개, 입력하는 동안 바로 바뀜)
  4. **이미지 저장 = 휴대폰에 그림 파일(PNG) 내려받기** (드라이브에는 저장하지 않음)
  5. **줄 수 = 입력한 줄까지만** (빈 줄은 이미지에 넣지 않음, 순번은 1부터 이어서)
  6. **작업장소 = 직접 입력** (고르기 목록 없음, 「2층,3층,4층」처럼 여러 곳 가능)
  7. **일자 = 작성일 다음 날** (내일 예정 작업을 적는 것)
  8. **전 직원이 쓰고 고칠 수 있음** (로그인한 직원 모두)
  9. **부서 = 전방파트 · 기건파트 둘 중 고르기** (직접 입력 없음) — *결정 68로 바뀜 (전: 전기방재·기계건축)*
  10. **위험 작업 손 표시 버튼 없음** — 빨간색은 단어로만 자동
  11. **저장 = 날짜마다 한 장**. 같은 일자를 다시 열면 그 장을 이어서 고침(시트 저장, 여러 직원이 함께 고침)
  12. **작성일 = 근무일 기준**(오전 6시 시작, 결정 60). 예: 11월 5일 15:00 작성 → 일자 11월 6일, 11월 6일 01:00 작성 → 근무일 11월 5일이라 일자 11월 6일
  13. **디자인 = 도면협의 앱 디자인** (06 문서 12장: `--ground` 바탕, 흰 카드 12px 모서리, 입력·버튼 8px·44px, 입력 글자 16px, 휴대폰 주 버튼 52px) — 결정 68
  14. **휴대폰·PC 둘 다 입력** — 결정 68
     - **PC (가로 768px 이상)**: 양식처럼 **표** 한 장. 줄마다 순번 · 부서(전방/기건 고르기) · 작업장소 · 작업 내용 · 비고 · 지우기
     - **휴대폰 (768px 미만)**: 표 대신 **줄마다 카드**. 카드 위에 순번·부서 고르기·지우기, 그 아래 작업 내용(한 줄 전체), 그 아래 작업장소 | 비고 나란히
     - 위험 줄: 글자 빨간색 + 카드(표 줄) 왼쪽 빨간 띠 + 연분홍 바탕, 「위험 작업」 칩
     - 아래 [+ 줄 더하기], 화면 맨 아래 고정 막대 [저장] · [그림으로 저장]
  15. **그림 파일 모양** = 양식 v2의 칸 순서·글자 그대로, 색·모서리만 도면협의 디자인 (머리줄 연파랑, 위험 줄 빨간 글자·연분홍 바탕, 바깥 둥근 모서리) — 결정 68
