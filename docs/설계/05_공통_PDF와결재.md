## 11. PDF · 결재

### 11.1 만드는 방법
| 앱 | 방식 |
|---|---|
| DW | 화면에서 만드는 지금 방식 유지 (HTML 인쇄·PDF) |
| WS 작업일지·하자통보서 | Google Slides 템플릿을 채운 뒤 PDF로 저장 (WS 설계) |
| 새 앱 | 둘 중 하나를 고르고 그 앱 문서에 적음 |

### 11.2 "먼저 제출 완료, PDF는 이어서" (모든 앱 같은 규칙)
- Apps Script에는 응답을 보낸 뒤 서버가 계속 일하는 기능이 **없습니다.** 그래서 아래처럼 만듭니다.
  1. 제출 호출이 끝나면 화면에 바로 "제출 완료 · PDF 만드는 중"을 띄웁니다.
  2. 화면은 결과를 기다리지 않고 `buildPdf(token, docId)`를 **따로 한 번 더** 부릅니다.
  3. 각 문서에는 `PDF상태` 칸(대기 / 생성중 / 완료 / 실패)을 둡니다.
     - 이 칸은 앱 DB의 맨 오른쪽 열입니다.
     - 문서색인의 `세부상태`에도 반영합니다.
  4. **예약 작업이 10분마다** `대기`와 `실패` 건을 다시 만듭니다.
     - 처리할 건이 없으면 바로 끝냅니다. 예약 작업은 하루 90분 한도를 쓰기 때문입니다 (13.2).
     - 3번 실패하면 `오류기록`에 남기고 HUB 할 일에 표시합니다.

### 11.3 결재 (원터치 직인)
- 결재선은 작성자 파트의 파트장(`파트.파트장_staff_id`) → 소장입니다.
- 결재자가 [확인]을 누르면 다음이 일어납니다. **PIN은 다시 묻지 않습니다** (7.1). `approveDocument(token, docId, role)`에는 PIN 인자가 없습니다.
  1. **결재자 본인 직인**(`직원.직인이미지ID`)이 서명란(`{{파트장서명}}`, `{{소장서명}}`)에 들어갑니다.
  2. PDF를 다시 만들어 바꿉니다.
  3. 상태와 결재자, 일시가 기록됩니다.
  4. 작성자 화면(내 문서)에 「OO님이 확인했습니다」가 표시됩니다 (7.5).
- 공통 규격의 "작성자 직인"은 **결재자 직인**으로 고쳤습니다.
- **수정 규칙**
  - 작성자는 결재 전까지 고칠 수 있습니다.
  - 결재한 뒤에는 관리자·소장만 고칠 수 있고, 고치면 결재가 처음으로 돌아갑니다.
  - 모든 수정은 변경이력에 남습니다.
