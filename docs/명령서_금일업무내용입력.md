# 작업 명령서: 업무지원(WS) 「금일 업무 내용 입력」 기능 구현

- **작성일**: 2026-11-22
- **대상 앱**: 에비뉴엘 업무지원 앱 (`apps/ws`)
- **담당 도구**: Claude Code
- **규칙 준수**: 에비뉴엘 CLAUDE.md 지침 (비개발자 친화적 용어, 「진행시켜」 전 코드 미수정, 조각 파일(`parts/`) 기반 빌드)

---

## 1. 개요 및 목적

에비뉴엘 업무지원(WS) 앱의 **[서류작업]** 메뉴 내에 **「금일 업무 내용 입력」** 화면을 신설합니다.  
직원들이 현장에서 당일 수행한 작업 내용, 작업 전/후 사진(2장), 사용 자재 내역을 편리하게 입력하고, 이 데이터가 **종합업무일지(금일작업 내용)** 및 추후 오픈될 **자재현황(재고 관리)**과 유기적으로 이어질 수 있도록 데이터 파이프라인을 구축합니다.

---

## 2. 화면 위치 및 UI 상세 요구사항

### 2.1 진입 경로
- 메인 화면 → **[서류작업]** 클릭 → 서류작업 하위 메뉴 목록에 **[금일 업무 내용 입력]** 추가
  - (기존: TBM, 명일 작업 예정, 출근현황, 종합업무일지 … → 신규 메뉴 추가)

### 2.2 화면 구성 요소 (모바일 친화 UI, 도면협의 디자인 시스템 적용)
1. **상단 헤더**
   - 뒤로가기 버튼 (`←`, 이전 화면인 서류작업 메뉴로 이동)
   - 화면 제목: **금일 업무 내용 입력**
   - 작업 일자 표시 (기본값: 오늘 근무일, 기준: 오전 6시 시작)
2. **입력 폼 영역**
   - **업무 내용**: 텍스트 입력창 (작업명, 상세 위치 및 수행 내용)
   - **작업 사진 등록 (2장)**:
     - **작업 전** 사진 첨부 칸 (미리보기 + 촬영/앨범 선택)
     - **작업 후** 사진 첨부 칸 (미리보기 + 촬영/앨범 선택)
   - **사용 자재 입력란**:
     - 사용한 자재명, 규격, 수량(단위) 입력
     - 행 추가/삭제 기능 (여러 개의 자재 등록 가능)
     - 향후 자재현황(마스터 품목)과의 자동완성/매칭을 고려한 구조
3. **하단 액션 바**
   - **[저장하기]** 버튼 (너비 100% 또는 하단 고정, 도면협의 테마 주 색상 적용)

---

## 3. 데이터 파이프라인 및 연동 설계

```
[금일 업무 내용 입력] 화면
       │
       ▼ (1. 저장)
[작업내용 저장소 (Supabase / Sheet)]
       ├─────────────────────────────────────────┐
       ▼ (2. 자동 연동 파이프라인)                 ▼ (3. 매칭/차감 파이프라인)
[종합업무일지] (금일작업 사항 연동)         메인 [자재현황] (자재표 출고 연동)
```

### 3.1 종합업무일지 연동
- **연동 대상**: 서류작업 > 종합업무일지의 **금일작업 사항** (전기방재 / 기계건축 파트별 작업 줄)
- **동작 방식**:
  - 당일 등록된 업무 내용 항목들이 종합업무일지의 「금일작업」 리스트에 자동으로 집계되거나 직접 동기화되어 표기될 수 있도록 식별 키(`work_date`, `part`, `work_title`, `work_desc`)를 공통 표준화합니다.

### 3.2 자재현황(자재표) 연동
- **연동 대상**: 향후 메인 화면에 오픈될 **[자재현황]** (자재 마스터 및 재고 수불표)
- **동작 방식**:
  - 사용 자재 필드를 단순 텍스트뿐만 아니라 구조화된 데이터(`{ item_name, spec, qty, unit }`)로 저장합니다.
  - 추후 자재현황 기능 활성화 시, 사용 자재 데이터를 바탕으로 출고(재고 차감) 기록을 자동 발생시키는 파이프라인 핸들러를 구성합니다.

## 4. 파일 변경 및 구현 계획 (Claude Code 실행 가이드)

### 4.1 신규 조각 파일 분리 생성 (`apps/ws/parts/`)
> **중요**: 현재 진행 중인 모듈 분리 체계에 맞추어 `Index.html`에 통합 작성하지 않고, **독립된 전용 조각 파일(`parts/45_dailywork.js`)**로 분리하여 관리합니다. 작업 후 빌드 스크립트로 병합합니다.

1. **`parts/20_body.html`**:
   - 서류작업 목록에 「금일 업무 내용 입력」 버튼/카드 추가
   - `#v-dailywork-input` 신규 화면 컨테이너 추가 (뒤로가기 헤더, 업무내용 입력란, 전/후 사진 업로더, 자재 입력 테이블, 하단 저장 버튼)
2. **`parts/45_dailywork.js` (신규 독립 모듈 파일)**:
   - 기존 다른 기능 파일들과 섞이지 않도록 **단독 파일로 분리 생성**
   - 화면 전환 및 초기화 (`openDailyWorkInput()`, 뒤로가기)
   - 전/후 사진 압축(리사이즈) 및 업로드 핸들러
   - 사용 자재 행 동적 추가/삭제/유효성 검사 로직
   - 데이터 저장 호출 (`saveDailyWork_`)
3. **빌드 및 동기화**:
   ```bash
   cd apps/ws
   python tools/build_index.py
   python tools/build_fm.py
   ```
   - `build_index.py` 실행 시 파일 번호 순서에 따라 `45_dailywork.js`가 자동으로 `src/Index.html`로 깔끔하게 빌드됩니다.

### 4.2 백엔드 / 데이터 저장소 (`Code.gs` 또는 Supabase)
- 신규 저장 함수 정의: `saveDailyWork(record)`
  - 일자, 작성자, 파트, 업무내용, 사진 URL/ID(전/후), 사용 자재 목록(JSON)
- 종합업무일지 조회 시 당일 저장된 `daily_works` 데이터를 함께 불러올 수 있는 연동 API 구비

## 5. Claude 작업 규칙 및 주의사항
1. 사용자가 **「진행시켜」**라고 명시하기 전까지는 실제 코드를 임의로 변경하지 않습니다.
2. 화면 디자인은 기존 `docs/설계/06_공통_디자인.md` 및 도면협의(DW) 스타일을 일관되게 적용합니다.
3. 작업 완료 후 `npm test` 또는 `npm run test:all`을 수행하여 기존 기능의 회귀 오류가 없는지 검증합니다.
